# 0.8.10 Plan — Precalculated Gravity Field (Classic Grid Checkbox)

> **Roadmap position (`0.8.*` · Gameplay-completion group, before calibration):** Placed
> after Periodic FFT (`0.8.0`) — it generalizes `0.8.0` §3's immutable
> field-snapshot, sharing and invalidation contract from the torus to the classic
> open map — and alongside `0.8.9-plan-trade-trajectories.md`, whose arc shooter
> samples the same accessor this checkbox switches. Like every numerics change it
> lands before `0.8.3`'s single calibration pass. The `0.8.11` GPU engine may build
> the same grid later; nothing here depends on it.

Standalone spec: a fork can rebuild this from this file alone. Source note:
`drafts/new/gravity-precalculate-trade-trajectories.md` §precalculate gravity:

	checkbox pre-calculate gravity field or mass field or force field then move all incl ships and background trade by this field. 
	use interpolation between cells.
	think or measure is it better performance during game.
	background trade anyway use cached trajectories.

## 0. decisions

1. **Force field, not mass field, not potential.** What every mover samples is
   acceleration, so the grid stores **(ax, ay) evaluated by the direct sum at
   each cell centre** and samples bilinearly between cells. A mass-field grid
   would still need the Poisson solve that FFT already performs
   (`0.8.0`'s periodic path — and that stays the periodic law with its own
   oracle); the potential is a *view* quantity with its own raster and stays
   out of physics. One grid, one interpolation, one law.
2. **Static fields only, shared with `0.8.0`'s rule.** `periodic && fieldStatic`
   already samples the FFT grid; `precalc && fieldStatic && !periodic` samples
   this one. Moving ports keep the direct minimum-image/direct sum and never
   allocate a grid — the same branch `0.8.0` shipped. On the torus the checkbox
   is dark (that world is already grid-sampled).
3. **The grid covers the flight area, not the field box.** Flights leave the
   1600×1000 field box and end at the 2400×1500 area edge (`END_EXIT`);
   prediction must not switch laws mid-flight, so cells span the whole flight
   area (`0.8.1`'s wider world gets the wider grid by the same parameterization).
   A one-cell guard band clamps the boundary samples the exit check allows.
4. **Measure before defaulting.** The note says «think or measure is it better
   performance during game»: the checkbox ships default-off on classic maps and
   the worklog records the measured opening/flight/prediction workloads for 26
   planets (and, for context, the already-gridded 104–192 torus). It becomes
   default-on only if the measurements justify it; the checkbox exists either
   way, and off must be byte-identical classic.
5. **Background trade needs no grid sampling — it needs the same law.** Trade
   ships never integrate live (`0.8.9`: scripted arcs or straight lines). The
   `0.8.9` shooter samples the same accessor, so curves caches are built under
   whatever law the run selected, and their cache keys already carry the field
   revision that this plan extends. That is the note's «background trade anyway
   use cached trajectories» made precise.

## 1. the option

One checkbox in the experimental panel, beside `periodic FFT`:

	precalc field

- Off is the shipped game: every static-field sample is the direct sum.
- On is a different numerical law for the same physics: samples read the
  precomputed grid, so seeds, benches and replays pin it (§5). The `g field`
  slider still multiplies at sample time and never rebuilds the grid.
- Toggling rebuilds the field snapshot (and restarts the seed if fired
  mid-run, like any law switch). Locked at the recorded value while a replay
  runs.

## 2. the grid

New file `gravity_grid.js`, classic script, `module.exports` guarded, sibling
of `gravity_fft.js` and shaped like it:

	GRID over the flight area (2400 × 1500 here; 0.8.1's long strip re-parameterizes)
	cells: power of two per axis, keeping dx, dy <= 10 px   // 256 × 256 here
	storage: two Float32Array (ax, ay) + Float64 world metadata

- Float32 storage: at `dx, dy ≤ 10 px` against `SOFT = 60` (6–9 cells per
  softening radius) the interpolation error dominates bit depth; Float32 halves
  memory and matches `0.8.11`'s GPU readback exactly, so CPU and GPU fills are
  the same shape. The direct sum is evaluated at cell centres in Float64 and
  rounded once on store.
- Bilinear interpolation between the four surrounding cell centres, cell index
  math identical in style to `GravityFFT`'s gather (`y * gridX + x`, origin at
  index zero). Outside the guard band the direct sum answers (a sample can only
  be there during the final exit step, but the law must be total).
- Parameterized `(gridX, gridY, worldW, worldH)` from day one so `0.8.1`'s
  long strip reuses the file unchanged, cell count re-derived from its flight
  area.
- Building is a budgeted job: ~65536 cells × 192 bodies worst case ≈ 12.6 M
  body evaluations; slice it like `0.8.0`'s solve budget, block dependent
  launch/prediction until the snapshot is ready, never let physics sample a
  half-built grid.

## 3. snapshot, invalidation, sharing

`0.8.0` §3's contract applies verbatim, with the grid as the snapshot payload:

- The solved grid is an **immutable snapshot** identified by geometry,
  dimensions, active extent, source positions, effective signed strengths,
  topology, the precalc flag and a field revision. Sims with the *same* field
  (live, rival, helper, fleet, burn/exit probes, the `0.8.9` shooter) adopt the
  same snapshot; nobody writes to it.
- **Invalidation is explicit** — `setField` identity, `setCount`, world/
  topology changes, strength edits (`setStrength`, `resetField`), masked
  strength rewrites, seed rerolls, designed-field adoption, save restore.
  `refreshField` refills positions for time sync and must not rebuild an
  unchanged static field. A dirty static field is built once before its next
  sample, prediction or paint; repeated `spawn` / `fillStep` / `refreshField` /
  prediction slices / `setScales` never rebuild.
- Only `precalc && fieldStatic && !periodic` samples the grid; moving sources
  take the direct path and never allocate. Probe topology/flag setup happens
  **before** field setup, as in `0.8.0`.
- Memory: 256² × 2 × Float32 = 512 KiB **per distinct field**, plus the build
  workspace; measure peak retained memory with the opening planner the way
  `0.8.0` does. No eager allocation in sim constructors, no allocation inside
  `advance` / `fieldAt`.

## 4. accuracy

The oracle is the direct sum, the same independent oracle `0.8.0` uses for its
grid — here the grid *is* a direct-sum resampling, so error is interpolation
only:

- vector error `|a_grid − a_direct| ≤ 0.02 · |a_direct| + 0.01 · a_ref` outside
  `2ε` of every source, `a_ref = MU / SOFT²`, on deterministic scattered,
  cell-centre, cell-corner and seam-of-cells samples including cancellation
  points between opposite-signed wells;
- inside `2ε` the bound relaxes to `0.05 · |a_direct| + 0.01 · a_ref` — bilinear
  between centres of a 6–9-cell softening radius is well inside this;
- signed wells (lab `−2…5` strengths) and zero-sum fields included; the `g
  field` slider multiplies after interpolation and is not part of the grid;
- prediction, live flight, helper, bot and the `0.8.9` shooter sample the same
  grid — one test pins live/full/sliced prediction agreement under the option.

## 5. integration

- Cache keys that already carry topology, dimensions and field revision
  (`0.8.0` §5: opening/seat masks, departure, leg, exit, pair-track) gain the
  precalc flag and grid geometry — a grid field is a different field and never
  reuses a direct-sum trace, and vice versa.
- `GravityScene` exposes `precalcGrid()` (the immutable snapshot with
  dimensions and revision, or null) as a test accessor, not a gameplay API —
  the `0.8.0` `periodicGrid()` pattern.
- URL: `&pg=1`, carried the way `&fft=1` is — link codec, replay hash, saved
  start maps, full run captures and compact career playback record it; restore
  before rebuilding geometry; saved-opening/lite/seat caches select matching
  law only (`0.8.9`'s law filter gains the flag).
- The field/potential **views** keep their own rasters: the classic body-loop
  shader and CPU raster are view machinery, not physics, and are unchanged
  here (`0.8.0` §6 owns the torus blit; `0.8.11` may move both to GPU).

## order

1. `gravity_grid.js` + `precalc_field_test.js`: geometry, fill, gather, oracle
   bounds, revision identity. No game hook.
2. Hook `GravitySim`: flag, snapshot build/share/invalidate, prediction
   agreement, classic fingerprints pinned with the flag off.
3. Cache keys, probes, bots, fleet; measure opening/flight workloads and
   retained memory on 26-planet worlds (and read the torus numbers for
   context) — record the default decision in the worklog.
4. URL/replay/saved-map/lite carry; README; one `dom_smoke` pass.

## Validation

- `precalc_field_test.js`, headless: §4's oracle bounds on scattered and
  adversarial samples, signed and zero-sum fields; grid build once per field
  identity (unchanged `refreshField`/`spawn`/`predict`/`setScales` never
  rebuild; every §3 invalidation rebuilds exactly once before next use);
  probes share the live snapshot and never mutate it; moving sources never
  call the grid; live/full/sliced prediction agree under the flag.
- Classic unchanged with the flag off: `classic_physics_test` fingerprints,
  `gravity_seed_test` link checks, `gravity_bench` / `career_gravity_bench` /
  `bot_bench` known-failure names (`timings` are measurements, not fixtures).
- Key regressions: identical seeds with different precalc flags do not share
  opening, departure or leg traces; `&pg=1` round-trips through link, replay
  hash, saved map and compact playback; sparse high-index mask cases retained.
- `dom_smoke`: checkbox present; off → classic path; on → tag carries `pg`;
  route/lab behaviour unchanged; a shot's prediction matches the live flight
  sampling the grid.
- Perf report in the worklog: build ms (cold), sample ms vs direct sum per
  workload (opening planner, prediction slices, long flight), retained KiB per
  field; the default-off-or-on decision recorded against those numbers.
- `node --check` on every touched script, `git diff --check`, fast tier green.

## Scope boundary

No change to the periodic law, its FFT solver or its oracle; the checkbox is
dark there. No potential/zones view change, no mass-field grid, no CIC deposit
on the classic map. No moving-source grids. No GPU build here (`0.8.11`). No
third slider — geometry and storage are constants. No auto-default-on without
the §0.4 measurement. `0.8.1`'s wider world reuses the parameterized file and
is otherwise out of scope.
