# 0.7.38 Plan — Lite Profile (Fast Boot, Quiet Background, Lean Frame)

> **Roadmap position (Pre-FFT `0.7.*` · First):** Zero physics or balance drift; speeds up page boot, automated Playwright runs, and laptop battery play for every plan that follows.

Source notes: `drafts/new/lite-version.md`.

---

## Goal

Give players, laptops on battery, and test sessions a first-class **lite profile**
(`?lite=1` or a persistent **lite** checkbox in the settings/cargo strip) that:

1. Starts unseeded career runs immediately from `saved_maps.js` (`< 50 ms`) and
   avoids redundant `OrbitSim` world resets during page boot.
2. Stops 60 Hz cosmetic canvas painting and moon/hover animation on `#o` when
   the trade backdrop is not the active gameplay or view layer, while keeping
   career economy `tradeSim` stepping and moving-port physics 100 % byte-identical.
3. Silences Web Audio (`AudioContext` never created while muted by lite) and
   `PhotoDeck` popups/image probes without overwriting the user's saved sound
   preferences in `localStorage`.

---

## Design

### 1. Single-reset boot & saved-map career start (`orbit_view.js`, `gravity_gui.js`, `gui_maps.js`, `gui_game.js`)

- **Avoid triple `scene.reset` on cold boot:** Today `orbit_view.js` runs
  `sim.step(START_MINUTES)` (`360` minutes = 7 200 trade steps) for seed `42` on
  script load, `gravity_gui.js` immediately runs `scene.reset(bootSeed)` for a
  random `startupSeed()`, and `setPlayMode('career')` resets a third time if a
  saved map is armed. Resolve the initial target seed/map *before* the boot
  `scene.reset` (or defer `orbit_view.js`'s initial 360-minute pre-history until
  `gravity_gui.js` supplies the boot seed) so cold boot runs `START_MINUTES`
  **once**.
- **Default saved-map career start in lite mode:** When starting `career` in lite
  mode without an explicit `?seed=`, `?map=`, or `#game=1` hash:
  - Look up matching `SAVED_MAPS` records (`kind === 'start'`,
    `universe === planetCount`, `seats.length === seatsWanted`,
    `gs === gravityScale`, `fs === forceScale`, no custom `gravity` override)
    and arm one via `GravityMaps.arm(record)`.
  - If the chosen difficulty/roster (`easy` = 2 seats, `hard` = 4 seats, `off` =
    1 seat, or custom `universe` / scales) has no matching `SAVED_MAPS` start
    record, fall back cleanly to `prepareCareerStarts` (and optionally include
    1-seat / 2-seat / 4-seat `start` entries in `saved_maps.js` so every default
    difficulty radio boots fast).
- Clicking `new seed` in career while lite mode is on cycles through matching
  `SAVED_MAPS` start records first; `Shift+click` (or an explicit `?seed=<n>`)
  always rolls a fresh arbitrary seed through the live planner.

### 2. Separate deterministic `tradeSim` state from 60 Hz `#o` backdrop work (`orbit_view.js`, `gui_game.js`)

**Critical invariant:** During `career` (`tradeState.gameClock === true`),
`advanceCareerWorld()` in `gui_game.js` steps
`tradeSim.advanceTo(tradeSim.t + DT * scene.trade.speed)` on every career clock
step, and `GravityGame.refreshBoard`, `advanceEvacuation`, and colony/fuel laws
read `tradeSim`. Lite mode **must never skip `advanceCareerWorld()`'s
`tradeSim.advanceTo(...)`**, or task offers and `captureState` would diverge
from non-lite runs.

What lite mode suppresses is **visual-only work inside `orbit_view.js`'s own
`requestAnimationFrame` loop**:

- Expose `OrbitScene.setLite(on)` and `OrbitScene.markDirty()` on `orbit_view.js`.
- When `lite` is on and `!showBackdrop` is false? More precisely, when `lite` is
  on, `mode === MODE_PLANETS`, and `viewMode !== 'trade'`:
  - In lab (`!tradeState.gameClock`), do not advance `sim.step(dt * speed)` in
    the background on every animation frame (`scene.reset(seed)` still ran its
    one-time `360`-minute pre-history).
  - Do not run per-frame `stepMoons`, `updatePortPositions`,
    `updateShipPositions`, `updateHover`, `updateHud`, or 60 Hz `draw(now)` on
    canvas `#o`.
  - Paint a clean static `#o` frame (starfield/grid + static planet discs, no
    moving ships/builders/moons/pulsing rings) **only when `backdropDirty` is
    set** (`resetWorld`, `resize`, `setPlanetMask`, `setBackdrop`, `setLite`, or
    switching `viewMode` / `mode`), and skip `#o` painting altogether while
    `cleanCareerView` already hides `#o`.
- Whenever `mode === MODE_PORTS` (moving orbital stations *are* the gravity
  bodies) or `viewMode === 'trade'` (the player explicitly selected the trade
  view), `orbit_view.js` steps and paints normally, omitting only decorative
  moons/merchant trails if `lite && mode === MODE_PORTS && viewMode !== 'trade'`.

### 3. Audio & postcard suppression without clobbering `localStorage` (`gui_sound.js`, `gravity_sound.js`, `photo_deck.js`)

- **`PhotoDeck.setEnabled(on)` (`photo_deck.js`):** When disabled by lite mode,
  `show`, `showCareer`, and `toast` return early (closing any open card) before
  probing candidate `photos/<kind>/*.jpg|png` URLs via `new Image()` — avoiding
  both DOM timers and spurious 404 image requests on static hosts. Note:
  `PhotoDeck` is purely visual (`toast` only displays already-settled money text;
  actual purse credits happen in `gravity_game.js`), so suppressing it has zero
  gameplay effect.
- **Audio gate (`gui_sound.js` / `gravity_sound.js`):** While lite mode is active,
  hold `sound.setEnabled(false)` in runtime state and skip `sound.unlock()` on
  pointer/key gestures so `AudioContext` and the 24 continuous Voronoi Web Audio
  oscillator voices are never instantiated. **Do not** write `enabled = false`
  into `gravity.sound.*` in `localStorage` when `?lite=1` comes from the URL;
  turning lite mode off restores the user's prior sound enabled state.

### 4. URL & UI controls (`index.html`, `gravity_gui.js`, `gui_share.js`)

- Query param `?lite=1` activates lite mode for the session (`?lite=0` overrides
  stored `localStorage` `gravity.lite = '1'` off for that tab); only clicking the
  UI `#liteMode` checkbox writes `gravity.lite` to `localStorage`.
- `syncSeedUrl` preserves `lite=1` when active so copied/reloaded URLs stay in
  lite mode; game/replay hashes (`#game=1...`) remain unchanged because lite is
  a viewer profile, not a rule parameter.

---

## Scope & non-goals

- Lite mode **never** alters `PlanetGravity`, `GravitySim`, `GravityGame`,
  `OrbitEcon`, `tradeSim` career clock stepping, `GravityBot` search budgets, or
  `CareerActions` / `CareerReplay` state.

## Verification

- `experiments/lite_mode_test.js` (added to `experiments/run_fast.js`):
  1. `?lite=1&mode=career` boots from `SAVED_MAPS` in `< 150 ms` with a single
     `OrbitSim` world reset and zero `AudioContext` / `Image` allocations.
  2. `?map=0&you=bot&lite=1` and `?map=0&you=bot` produce byte-identical
     `GravityMaps.captureState` (including `tradeSim` and `tasks`) after 1 000
     career steps.
  3. Over 60 frames at rest in `MODE_PLANETS` (`viewMode !== 'trade'`), `#o`
     redraw count is `0` after the initial static paint, and switching to
     `viewMode === 'trade'` or `MODE_PORTS` immediately resumes live `#o` frames.
  4. Opening `?lite=1` does not overwrite pre-existing `gravity.sound.*` keys in
     `localStorage`, and unchecking `#liteMode` restores them.
  5. `node experiments/run_fast.js` stays green.
