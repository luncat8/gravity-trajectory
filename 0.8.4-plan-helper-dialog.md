# 0.8.4 Plan — Helper Dialog (`H` Radio Assistant)

> **Roadmap position (End of `0.8.*` · After all gameplay & balance):** M0–M2 (`launchReasons`, `comms_copy.js`, `gui_comms.js`, `return-tow`) are already live for core career blockers. Placing the remaining M3 (full topic browser, canon/art, `didn't help` escalation, delta since last call) and M4 (non-career mode answers including `maxdistEmc`/`maxdistImp`, rival character & intent summary, README) **after** all gameplay modes, colonies, fleets, Periodic FFT, Rival Characters, and Bot Balancing (`0.7.38`–`0.8.3`) ensures H's topic index and live snapshots cover every final rule in a single pass.

H is the comms officer at the captain's base: an emissary of the cluster
Capital, delivered to a planet by somebody else's catapult, signal flag in one
hand, aluminium spyglass in the other. The player calls in and picks a question
from chips; H answers with text assembled from the live game state — irrelevant
branches hidden, matching ones with conditional inserts ("...but you don't have
any"), and action buttons attached to the answer. H explains rules and game
state; trajectory search stays with the auto-scanner (`gui_helper.js`, a
different entity). H never speaks first: it raises one icon when it finds a
closed launch gate the player is standing behind, and the player decides whether
to answer.

## layers

Four layers, because three of them are separately testable:

```
rules layer       gravity_game.js / orbit_tech.js / orbit_econ.js / gravity_sim.js
  │  launchReason · launchReasons · formatLaunchReason · repairCost ·
  │  spaceWear · landingWear · exitCostAt · launchFee · padLift ·
  │  fuelPrice · bribeAmount · bribeRefusal · bribeWindowOpen ·
  │  bribeCorruption · arrestChance · planetProfit · planetBuildable ·
  │  gearKnown · prototypesOf · canAccept
facts & slots     comms_copy.js — node-safe, no DOM
  │               buildSnapshot: one frozen snapshot of live state + rule knobs
  │               HH_FACTS: id → { test(snapshot), why(snapshot) }
  │               H_SLOTS:  slot → fn(snapshot) → formatted string
topics layer      comms_copy.js — pure data + validator
  │               H_TOPICS: id → { ask, rank, when, steps, lines, ref, refWhen, chips, actions }
  │               H_ACTIONS: id → { label, when, enabled, costly }
dialog layer      gui_comms.js: card, transcript, back, chips, CTAs, stamp
  │               COMMS_HANDLERS: 1-to-1 map from H_ACTIONS ids to page handlers
```

`comms_copy.js` needs no page: `HH_FACTS`, `H_SLOTS` and `H_TOPICS` run directly
under Node against real careers or snapshot fixtures, and only the card in
`gui_comms.js` needs a DOM. The player-facing name is **H**; the panel is
`comms`. The prefix is `comms`, never `helper` — that name belongs to the scan
engine (`helperState`, `gui_helper.js`), and a dialog sharing a name with a scan
is a support ticket.

## the rules layer: one ladder, one writer

The draft's first question — *«не могу улететь»* — is 90 % of the feature, and
the game already answers it in one ordered ladder. The ladder becomes
structured reasons; the strings the launch list prints do not change by one
character:

```
launchReasons(career, sim, planet, speed, repaired) → [{ id, need, have, repair? }, ...]
launchReason(career, sim, planet, speed, repaired)  → first reason | null
formatLaunchReason(reason)                          → the printed string ('' for null)
launchBlock(...)                                    → formatLaunchReason(launchReason(...))
```

The ladder, in order (the first closed gate is the headline; the rest are the
blockers underneath it):

| # | id | closed when | need / have |
|---|---|---|---|
| 1 | `arrest` | `career.arrested` | — |
| 2 | `space` | `career.at < 0` | — |
| 3 | `wrong-planet` | `career.at !== planet` | planet / `career.at` |
| 4 | `worn` | `!repaired && !careerShipUsable(career)` | — / condition |
| 5 | `no-rail` | `!sim.canLaunchFrom(planet)` | — |
| 6 | `cap` | `speed > sim.speedLimit(planet)` | cap / speed |
| 7 | `fee` | purse < cost (cost = fee, + repair when `repaired`) | cost / purse, `repair` flag |

Two rules keep the list honest:

- **ship-state gates always report.** `arrest` and `worn` are facts about the
  ship, so they appear even when a position gate is closed: in space with a
  worn ship the list is `[space, worn]`.
- **planet gates need the planet.** `space` and `wrong-planet` are position
  gates: when one is closed, `no-rail`/`cap`/`fee` are skipped — they describe
  a planet the ship is not on. And `no-rail` closes the rest: with no rail
  there is no cap and no fee to report.

`launchBlock`'s strings before and after the split are identical for every
existing caller (launch list, bot log, scan gate); the split is a pure
refactor of the rules layer. H switches on `id` instead of parsing English,
and a new gate added later shows up in H for free.

## the snapshot and slots: live variables, zero hardcoded values

`buildSnapshot()` reads the live objects **once** — on open, on asking a topic,
on landing, on any `careerNotice`, `careerChanged` or `cancelHelperForChange`
event (including experiment sliders and cheats), and once per elapsed game
second while the card sits open. It reads **both** run state (`purse`,
`condition`, `fuelKg`, `padCharge`, `padCount`, `bribeAmount`, `corruption`,
`tasks`, `arrestUntilStep`, `reasons`, …) **and** every rule constant, tech
identifier, price, rate and multiplier (`fuelPrice`, `FUEL_KG_PER_KWH`,
`FUEL_BUY_STEP`, `WEAR_REPAIR_COST`, `spaceWear`, `landingWear`,
`CAREER.evacFee`, `CAREER.taxPerKwh`, `COMMERCIAL_BASE`, `COMMERCIAL_KWH`,
`COMMERCIAL_PAD.catapult.id`, `OBS`, `CATAPULTS`, `BRIBE_VALUE_COEF`,
`bribeCorruption`, `arrestChance`, `ARREST_SECONDS`, `REBEL_START`, `SPEED_MIN`,
`WAIT_SEC`, `sim.forceScale`, `spaceWearScaleOf()`, `CHEAT_COMMUNISM`) directly
from the rules modules at snapshot time — never re-declared or cached as
literals. Every fact, slot and line reads that frozen snapshot, so an answer is
consistent with one instant, cannot mix two planets, and updates automatically
whenever a rule knob or live value changes. Allocation is fine here: it happens
on interaction or throttled refresh while open, never in the frame loop.

Every factual value enters prose through `H_SLOTS` (`{slotName}`), including
item ids (`{obsId}`, `{nextPadId}`, `{commercialPadId}`). Authored strings carry
no digits and no copied constants.

## the topic record

```
const H_TOPICS = {
	'money': {
		ask: 'no money',
		rank: 10,
		when: 'career-open',
		steps: ['non-career', 'career-ended', 'at-arrest', 'in-flight', 'at-space'],
		lines: [
			{ text: 'Money can be earned (purse {purse}):' },
			{ text: 'by flying past planets with a working {obsId}.',
			  note: { fact: 'reports-active', invert: true } },
			{ text: 'by taking the rulers’ offer on {planetTag} (+{bribeAmount}, once per visit until you leave {planetTag}; adds +{bribeRot} rot).',
			  when: 'bribe-open' },
			{ text: 'by winning the sport slot on {sportPlanetTag} (land ≥ {sportMinLength} for +{sportReward}, {sportLeft} left).',
			  when: 'sport-open',
			  note: { text: 'nothing on the board now', when: { not: 'sport-open' } } },
			{ text: 'by a guest launch on your rail ({taxPerKwh}/kWh × rail tier).',
			  note: { fact: 'own-pad-any', invert: true } },
			{ text: 'by completing a contract leg ({contractSummary}).' }
		],
		ref: [],
		chips: ['bribe', 'pad', 'repair'],
		actions: []
	},
	'leave': { … }
};
```

`when` is a key of `HH_FACTS`, or `{ all: [...] }` / `{ any: [...] }` /
`{ not: expr }`. No strings are evaluated. `steps` checks `H_STEPS` in order and
the first matching step replaces the topic body. `note` either holds `{ text,
when }` or delegates straight to `{ fact, invert: true }`, printing
`HH_FACTS[fact].why(snapshot)` when the predicate fails so a predicate's reason
is never written twice. The validator proves every fact, step, slot, `ref`,
`chips` and `actions` key resolves and that `ref` is acyclic.

## the money topic is one subtree, cited under every shortfall

`leave`, `repair`, `pad` and `fuel` carry `ref: ['money']` guarded by a topic
`refWhen` shortfall predicate, so one copy of `money` attaches whenever the
purse cannot cover that topic's cost and stays out of the way when solvent.
Each referenced topic renders at most once per answer. Where a shortfall is a
single step away on the current planet (the rulers' offer covering repair, pad,
fee or evacuation; a slower aim fitting the purse; own battery charge converting
to fuel; the commercial rail lifting off a dry pad), H prints one line of live
arithmetic (including rot cost when naming the offer) — only one step, only
actions available on this planet right now, never as a chip and never as a
ranked recommendation. If the step does not exist, the line is not printed.

## chips: integer ranks, no formula

- every topic carries an integer `rank` (`0` = blocking, `50` = flavour);
- the chip list is the topics whose `when` holds, sorted by `rank`, then by
  *not asked since this planet* (one boolean, `asked[id]`), deduplicated and
  capped at 6;
- `what should I do?` is always chip #1 and is not a topic — it expands the top
  live finding (never `bribe`) with its active `ref` subtree;
- follow-up and `ref` expansion deduplicate targets, so `no money` never appears
  twice from two different blockers.

One integer and one boolean. A test can assert the exact chip list for a
fixture.

## surface, freshness, transcript

- **entry**: a `comms` button beside the rule-help button (`?` / `KeyH` open
  the rule drawer today), and a **notice icon that H raises itself** when it
  finds a problem at the moment of the problem (see *the entry point*). **No
  new hotkey in the MVP**: `KeyH` and `?` already open the rule drawer, and
  `KeyC` is free but would sit next to `KeyF`/`KeyZ`/`KeyP` and the arrow
  trims — a key is only worth taking when the button proves too far.
- **card**, non-modal, ~300 px, bottom-right above the flight panel, scrolls,
  collapses to one line. It never pauses the clock and never moves the flight
  panel. On a phone it becomes the same overlay the photo deck already uses
  when space runs out.
- **stamp**: every answer line reads `checked 412 s · P6`. **The transcript
  clears on a planet change** — old numbers are exactly the rot this design
  exists to prevent, and a stamp alone does not stop a player reading them.
- **history** up to the last 3 exchanges, with `back`, because the draft is a
  conversation.
- **`didn't help`** as the last chip of every answer: it clears the topic and
  offers the three nearest, and writes a `careerMsg`-style log line. No
  telemetry — the log is the player's, and a test can read it.
- text first: focusable chips, `Esc` closes, `aria-live` on the answer block,
  no canvas text (this is the one help surface that must work at any zoom).

## the character: a voice with a canon and no face

H is faceless in the MVP. No portrait; when art exists it lands in
`photos/helper/` with the CSS fallback card `photo_deck.js` already uses, which
is the repo's one pattern for optional art.

Voice, as constraints rather than taste:

- one cause, then the exits; numbers live, never rounded for comfort;
- at most one dry joke per answer, and none while the ladder is blocking;
- never a noun the HUD does not already use — H introduces no vocabulary;
- the bribe gets the price, the rot, the arrest countdown and the one-per-visit
  rule, and no advice (see *the bribe*);
- the two easter eggs ship as cards, not as help text:

```
P: what is the meaning of life?
H: wrong address — the mission I can do. Collect, carry, report: up to the
   cluster Capital, which forwards to the Capital of the galaxy, which
   forwards to the Capital of all capitals, which sits outside space and
   time. Circus skills welcome. Not required.
   [ the letter of introduction ]
```

## the bribe: reported, never ranked

The scans already refuse to price a bribe into a landing (`careerLandingFacts`
ignores it; only `careerBribeProne` rivals price it), and that asymmetry is
deliberate. H inherits it: it **prints the offer with its value, its rot, its
arrest countdown and that it is once per visit**, and it never puts the offer
in a ranked *fix* list. A player learns it is there and what it costs; the
decision stays theirs. One button, one press, no confirmation dialog invented.

Any company may take the rulers' offer, one per visit; a rival's difference is
only whether its controller prices that offer. The README wording is corrected
in the same change as the dialog, because H quotes it.

## invariants — each one is a test, not a style note

1. **no literal digits in authored copy.** Every number arrives through a slot
   from the rules layer or the snapshot. Grep-able: a test walks the copy
   tables and fails on `[0-9]` outside a slot. This is the one rule that keeps
   H from becoming the fourth source of truth about a price.
2. **no new constants.** A threshold H needs either exists in the rules layer
   and the HUD reads it too, or it does not exist — and then H prints the
   condition and the repair price and warns nothing. Only `< 1` and `0` are
   real wear thresholds.
3. **H changes no state** — no purse, clock, seed, replay hash, no
   `Math.random`, nothing in the frame loop, no per-frame allocation.
4. **no orphan CTA**: every `act` resolves to a real handler, and a CTA the
   purse cannot pay is dimmed **with its reason printed** — never a tooltip
   (the launch list's own rule: `fee 2.27 > purse 0.50`).
5. **no unimplemented feature is ever described**: if a mechanic has no button
   and no state, H has no topic for it.
6. **H works in every rule or says so.** `tour` / `money` / `route` get an
   honest two lines (`this rule scores distance; no purse`) instead of career
   advice with `undefined` in it.

## the entry point: H calls the player, and the icon is the contract

H does not speak first: it raises one small icon, the player decides whether to
answer. The three states are the whole specification:

| state | shown | cleared by |
|---|---|---|
| **quiet** | the `comms` button, dim, no badge | — |
| **called** | the same button, lit, with the finding's tag (`no rail`, `worn`, `fee 2.54 › purse`) and a `!` badge | the finding changes, the card is opened, or the player dismisses |
| **dismissed** | the button only, no badge, no tag | nothing. One silent re-call per fact-change |

**What counts as a problem.** Not "something is suboptimal" — that is the scan
engine's job and it already has its own button. H calls only for a **closed
gate the player is standing behind**, and the trigger is mechanical, so nothing
is authored for it: *called ⇔ the player has a shot armed from this planet
(`armed`, `aimBody` — the state the launch button reads), and `launchReason`
names a gate for it, and neither the gate nor the player's last armed shot
changed in the last second.* The one case that calls without an aim is the
ship worn to `0` (`WORN_OUT_BLOCK`): every shot is blocked by that fact alone,
so the gate is the problem whether or not a shot is armed.

**It never nags.** Three rules, and they are why this is not a tutorial:

- **one call per fact-key per planet visit** — the key is
  `gate id + planet + the numbers in it` (from the reason's `{ id, need, have }`),
  so *"fee 2.54 › purse 0.50"* called once is never called again, but the same
  gate with a new price after a purse change is a new fact and may call once
  more;
- **the ignore is remembered** for the whole planet visit
  (`commsState.dismissed[key]`), and the transcript reset clears it with the
  transcript — a dismissal is a statement about this planet, not about the game;
- **never while the clock is settling, during a replay, or while the card is
  open**, and never twice in the same second: the call rides the HUD tick in
  the same throttle the flight panel already uses.

**When the icon disappears.** *Problem solved → icon disappears* is taken
literally, and it is free: the call is a **rendering of the snapshot**, not a
record. `launchReason` returning `null` (gate cleared, or the ship left the
planet) puts the button back to quiet in the same tick, with no timer and no
"dismissed" flag to clean up. A dismissal hides a *call*, never a *fact*: the
tag still updates, so an impatient player who dismissed it can see the number
move when they sell the OBS data.

**What the call costs.** Nothing new in the frame loop: `launchReason` is
already computed for the launch button and the flight panel's state tag, and
the comparison `call key ≠ last key` is a string compare per HUD tick (twice a
second) — the same shape as `flightHud.state`. The counter and the dismissal
map live in `commsState`, are cleared by the same
`cancelHelperForChange`-style invalidation, and invariant 3 still holds: a call
writes a *log line and a badge*, never a purse, a clock or a replay hash.

**Why not the toast.** A toast is seen during a flight the player is losing,
cannot be re-read, and competes with the flight panel's own state tag, which
already prints the gate in words. The icon is the smallest object that survives
both.

## decisions

1. **Headline plus other blockers.** Show the first active launch blocker as
   the headline and the remaining active blockers underneath, in the shared
   `launchReason` ladder order. H has no independent blocker ranking. Example:
   "Repair your hull first", then "You need 20 more credits for launch." The
   shared checker exposes all active blockers (`launchReasons`) while
   preserving the first-result contract for existing launch callers; no rules
   are duplicated in H.
2. **H never speaks unasked.** It calls with an icon, never with text or a
   toast, once per fact-key per planet visit, and the call disappears by itself
   the moment the gate clears. The flight panel's state tag already prints the
   same gate in words, so the icon adds `!` and a tag, not a second story. H
   never opens the card by itself — that stays the player's press, and never
   during a replay.
3. **The one-step look-ahead may state arithmetic, never recommend.** "Take the
   offer, then the evacuator is paid" is arithmetic over live numbers, or it is
   a strategy the player did not ask for. Allowed: one step, printed as a line
   under the two dim options it connects — never as a chip, never with the
   bribe ranked.
4. **`launchReason` lands first.** It touches `gravity_game.js`, which four
   callers share. It lands alone, in M0, with its test — and nothing else in
   that commit.
5. **The file is this one.** Code in `gui_comms.js` + `comms_copy.js` if the
   copy table outgrows it. The prefix is `comms`, never `helper`. Player-facing
   name is **H**; the panel is `comms`.

**H is a small, testable reader of the rules layer with a dry voice: it walks
the same gate ladder the launch list already prints, raises one icon when the
player is standing behind a closed gate, shows the first closed gate with the
numbers that closed it, keeps every alternative visible but dim with its own
price, and never writes down a number of its own.**
