# 0.7.43 Plan — Seeded Map Opening Fairness & `+5` Gravity Ceiling

> **Roadmap position (Pre-FFT `0.7.*` · Single map-law baseline move):** Grouped with `0.7.44-plan-founding-colony.md` so all seeded-map changes (`+5` gravity ceiling, all-roster fairness solver, and empty heavy worlds) happen together on top of `planet_gravity.js` / `map-generator-helper.htm` / playable `map_fields.js` (`0.7.35`), regenerating `saved_maps.js` once rather than repeatedly.

Standalone spec: a fork can rebuild this from this file alone. Source notes:
`drafts/flight-lab-and-modes.md` §1.4 (`career map generator improve`,
`random gravity of planets -1...+5`) and `drafts/hud-input-and-help.md` §6.2

## what ships today

The opening is planned once for the whole run:
`GravityGame.prepareCareerStarts(galaxy, world, trade, mask, count, wanted,
sourceSim)` fills `galaxy.mapSeats`, and the page calls it with
`wanted = 1 + bot.count` before any career starts.

- Every HQ carries `g 1.00` (`HQ_GRAVITY_MAX`), like the Capital and the A.R.F.
  The seat search already traces a candidate home at that strength
  (`openingTraceHome`).
- `planCareerSeats` splits on `seatsWanted <= 4 && count <= 26`: inside that
  cutoff, `planHomeSet` searches candidate HQ combinations (bounded by
  `OPENING_EXACT_SETS = 400`, `OPENING_EXACT_MISS = 48`, pair-pinned ranking for
  `<= 14` candidates and unpinned cold ranking above that) and evaluates each set
  with `openingGroupStats` (`seatAssignment` maximizes `floor` first). Outside
  that cutoff (`SEATS >= 5` or `COUNT = 48`), it skips joint search and calls
  `pickFairHq` sequentially once per seat, preferring `g <= 1.0` (`shallowOnly`)
  and never checking distinctness or group ratio.
- Each company is matched to its **own** unclaimed first-flight landing at
  `g <= OPENING_BUILD_GRAVITY_MAX = 1.5` that an `EMC-1 + BAT-1` can leave again.
- Candidate maps are ranked by `compareOpeningGroups`, in this order: no company
  without a site; a distinct site for each; every site exitable; the weakest
  opening pays at least `OPENING_FAIR_RATIO = 0.55` of the best; then the higher
  ratio (`OPENING_RATIO_EPS = 0.02`); then the higher weakest pay; then more
  sites.
- `experiments/career_start_fairness.js` independently matches distinct,
  exit-safe sites in a positive-profit window in the final HQ-pinned field. It
  checks the game's chosen sites and their pay as well as the existence of a
  fair band, and supports `MATRIX=1` (`8, 13, 20, 26, 48` × `2…6`, seeds `1–12`,
  with `ALT=1` testing whether an alternative HQ set achieves exitability or
  `>= 0.55` fairness). `experiments/career_start_seat_test.js` asserts that the
  page seats that plan and pins the wells. `career_gravity_bench` starts careers
  the same way (`SEATS`, `HQWELL`).

The field itself lives in `planet_gravity.js` (`PlanetGravity.gravity(seed, planet)`,
re-exported by `gravity_game.js` and shared with `map-generator-helper.htm`): a
seeded hash draw on the `0.05` grid `PlanetGravity.MIN = −1 … PlanetGravity.MAX = 3.5`
(`STEPS = 20`, 91 values, softened through the `[0.6, 2.8]` middle band via
`BIAS_START`/`BIAS_END`/`BIAS_STRENGTH`).

## 1. the fair opening on every roster the page can start

The measured matrix separates the 18 failing cells into two distinct causes
inside `gravity_game.js` and one genuine small-universe constraint:

1. **`seatAssignment` / `seatBestRatio` maximizes `floor` first instead of
   searching pay windows.** Even when a pinned HQ set admits a fair
   distinct exit-safe assignment (`same-HQ oracle fair`: `12/12` on `48/2..5`,
   `9/12` on `48/6`, `3/12` on `20/5`, `4/12` on `20/6`, `6/12` on `26/5`,
   `4/12` on `26/6`), `seatAssignment` binary-searches only the highest
   reachable `floor` and pulls `ceiling` down at that fixed floor. Calling
   `seatBestRatio` does not search lower floors either because it delegates to
   `seatAssignment(..., fixedFloor=true)`. Walking positive pay windows
   `[floor, ceiling]` (lowest upper bound per positive lower bound, as in
   `bestRatioAssignment`) fixes every `same-HQ oracle fair` miss when the
   highest-minimum assignment includes an unnecessarily rich seat.
2. **`seatsWanted <= 4 && count <= 26` skips joint HQ selection and drops into
   sequential `pickFairHq`.** Outside that cutoff (`SEATS >= 5` or
   `COUNT = 48`), `planCareerSeats` never evaluates `openingGroupStats`, picks
   `g <= 1.0` (`shallowOnly = 1`) HQs greedily one seat at a time (consuming
   light buildable sites needed as first landings), and re-runs
   `careerOpenings` once per seat (`6.7 s` mean / `8.0 s` max on `48/6`,
   exceeding the `2–4 s` budget). For `SEATS >= 5` or `COUNT > 26`, enumerating
   all `C(N, S)` subsets is also unaffordable (`C(47, 6) = 10,737,573`), so
   joint selection must rank a bounded candidate set generated from one unpinned
   `careerOpenings` table — preferring heavy (`g > 1.5`) HQ candidates when
   pinning light worlds would starve buildable landing sites (`lightBefore -
   seatsWanted` tight) — pre-filter with cached `openingTracks(...,
   strictExit=false)` distinctness before exit checks, and score exact tracks
   until an accepted set is found.
3. **Walk bounds on `13/4` and `13/5`.** On `13/4 seed 1`, `C(12, 4) = 495 >
   OPENING_EXACT_SETS = 400` and `OPENING_EXACT_MISS = 48` stop before an
   unfair (`0.19`) exitable set (`alt-HQ exit 10/12` vs `9/12` shipped). On
   `13/5`, pruning candidate sets that consume more than `lightBefore -
   seatsWanted` light sites keeps only viable combinations from `C(12, 5) = 792`
   and surfaces all `6/12` fair / `9/12` exitable HQ sets.

Required behaviour and contract for §1:

- **Default cell invariant:** `COUNT=13 SEATS=3` (`SEEDS=1-8`, `REFUSED_SEED=10`,
  and `saved_maps.js`) keeps identical HQs, chosen assignments, and payouts to
  the printed digit. On `seatsWanted <= 4 && count <= 26`, fall back to a
  lower-floor pay-window search only when the max-floor match fails
  `OPENING_FAIR_RATIO` (or restrict joint-search changes to rosters outside
  the default path / when the default assignment misses fairness), so no
  already-fair `13/3` plan or saved map shifts.
- **Full-fair rosters (`COUNT >= 20`, `SEATS=2..6`):** every seed (`12/12` across
  all 15 cells) must produce distinct, exit-safe first landings within the
  `0.55` pay band, without returning `null`.
- **Constrained rosters (`COUNT <= 13`):**
	- Wherever an HQ set admits distinct, exit-safe sites (`13/4` 10/12, `13/5`
	  9/12, `13/6` 5/12, `8/2` 11/12, `8/3` 7/12), choose a distinct, exit-safe
	  set, and hit `>= 0.55` wherever attainable (`13/5` 6/12, `13/4` 9/12,
	  `13/3` 11/12, `8/2` 10/12, `8/3` 4/12).
	- Relaxed distinct-site contract *only* where no HQ set admits distinct
	  exit-safe sites (`nonCap < 2 * SEATS`, `lightBefore < SEATS`, or
	  exhaustively `0` distinct sets across all valid HQ sets, e.g. `8/4..6`,
	  `13/3 seed 10`, `13/4 seeds 8,10`, `13/5` 3 seeds, `13/6` 7 seeds, `8/2
	  seed 10`, `8/3` 5 seeds): every company still gets a buildable, exit-safe
	  site when any exists (distinct while sites allow, shared otherwise, never
	  returning `null` when `nonCap >= SEATS`); when exitable distinct sites
	  exist but positive fairness `< 0.55` (e.g. `8/2 seed 8` negative A.R.F.
	  payouts, `13/4 seed 1`, `8/3` 3 seeds, `13/6` 5 seeds), keep distinct
	  exit-safe sites at the highest achievable ratio.
- **Plan time budget:** `prepareCareerStarts` runs at career start on the page;
  every matrix cell must complete within the default cell's budget (`<= 4 s`
  target mean / bounded worst case in `node`) without slicing.

`MATRIX=1` in `experiments/career_start_fairness.js` prints all 25 cells (`8, 13,
20, 26, 48` × `2…6`, `SEEDS=1-12`) with `built`, `exit`, `fair`, `worst`, `light
before->after`, `ms mean/max`, `sameHQ`/`altExit`/`altFair`, and the first
failing seed; `ASSERT=1` asserts the §1 target contract across those cells.

## 2. the blocked share as a contract

`hq_gravity_probe.js` already sweeps `PLANET_GRAVITY_MIN…MAX` and prints the
share as `x.x of 10`, so it follows the constant when the ceiling moves. What is
missing is the assertion: `career_start_fairness.js` checks the *drawn* field
(not the sweep) — over seeds 1–12, between 2 and 4 of every 10 non-HQ planets
cannot be left by the dry ship on `EMC-1 + BAT-1`.

## 3. the ceiling at +5 (last, and as a baseline break)

Decide the shape of the draw from a measurement, not from the constant:

- run §1's matrix and §2's share with `PLANET_GRAVITY_MAX = 5` as a local,
  uncommitted change;
- if the default career keeps a fair opening on every seed **and** the blocked
  share stays in 2–4, ship the uniform draw;
- otherwise keep the share of light planets and stretch only the tail: grid
  values above `3.5` are drawn with the weight that returns the blocked share to
  the band (one weight constant beside `PLANET_GRAVITY_MAX`, same hash, same
  salt). Both notes are then true at once.

Whichever shape wins ships as one commit that changes only the draw, with:

- `gravity_seed_test.js` re-pinned (it asserts that `3.5` is drawn and that the
  values sit on the `0.05` grid);
- the two literals that state the range: the top tick of the potential legend in
  `index.html` (`--z: 3.5`, `+3.5`) and the sentence «seeded from −1 to +3.5» in
  `COMMON_HELP` (`gui_tables.js`). The legend *bar* already follows the constants
  (`paintZoneLegend` in `gui_view.js`) and the lab's `g` slider already reaches
  `5`;
- every bench re-run and logged as the new baseline
  (`experiments/logs/0.6.8-gravity-max5.txt`), because the earlier reference
  numbers are then historical.

One design answer the note does not give must be written into that log: what a
`g 5` world is *for*. The table above says who can use the top of today's
field: at `g 3.5` the starter rail leaves one time in a hundred, an
`EMC-2 + BAT-2` still lifts the dry ship 96 times but a loaded `HOLD-24` once,
and an `EMC-3 + BAT-3` lifts that load 30 times. So everything above `3.5` is
freight country for `EMC-3` and up — the demand `archive/0.6.2-plan-pad-fees.md` §3
prices — and the same probe, re-run with the ceiling at 5, is the check.

## Scope boundary

No new planet kinds, no change to the orbit geometry or to the trade world's own
seed stream (the gravity draw is a separate hash). No change to what a heavy
planet *does* beyond being harder to leave. A company added in mid-career by the
scoreboard `+` uses the separate one-seat expansion planner; this plan is about
the companies a career starts with.
