resumable tiered search, H topics, start selectors, space/capital starts,
record/URL fields, bot space burns and no-HQ evacuation. The older worklog
records their checks, but that is not full acceptance of the plan.

The 2026-11-24 review keeps only the archived simulation patch's active
visit-log list and unbudgeted clock optimization. The rejected fused scan's
quest regression was reproduced and explained: `prepareLegProbe` manually
copies geometry but never copied the patch's new `impactR2` collision cache.
Adding that copy alone passes the two-leg test. Do not blame the inline
membership arithmetic or reapply the full patch without probe parity tests.

`createSeatSearch.step(0)` now really is read-only. Previously it consumed
one atomic unit, so H report polling performed unbudgeted physics work. New
`seat_search_test` covers zero/negative budgets, synchronous/sliced parity,
report polling, completed-tier-only plans and readout copy ownership.
`route_log_test` covers dwell logs, overlaps, re-entry, masks, saturation,
slice boundaries, restart and body-only impact.

## Next development priorities

1. Resolve WS4's decision lifecycle. The current page auto-advances tiers
   and automatically starts even an unaccepted plan at exhaustion. The plan
   instead specifies explicit play-as-is / fair-save picker / wait-more and
   start-fair choices. Do not confuse a harness-drained page with coverage of
   an actual pending decision. Add tests that hold planning open, render H,
   make each decision, cancel by changing roster/mode, and check recordings
   and clock state. Decide/document the exact UX before changing the drain
   helper used by existing tests.
2. Measure worst atomic search-unit cost. Eight light probes, one home fan,
   a whole exact proposal or set construction can exceed the requested
   8 ms frame slice. Break oversized work into deterministic resumable units
   if measured responsiveness needs it; never use elapsed time to choose HQs.
3. Reconcile composition heavy classes with the plan. Current code tests
   EMC-2/BAT-2 and EMC-3/BAT-3 rather than BAT-1, and the EMC-3 class can
   include a full-power EMC-2 escape or full-power-only EMC-3 escape. These
   classes control fairness-test exclusions, so remeasure/report them rather
   than silently moving the fair contract or re-pinning saved maps.
4. Run the full roster/oracle matrix after these contracts are resolved.
   Keep fairness, timing and economic assertions intact. The earlier worklog
   documents known test failures, but reproduce them at the current base
   before attributing any new red to pre-existing behavior.
