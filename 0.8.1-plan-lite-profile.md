# 0.8.1 Plan — Lite Profile (Fast Boot, Quiet Background, Lean Frame)

Source notes: `drafts/new/lite-version.md`.

---

## Why first in `0.8.x`

Every subsequent feature and test runs faster and cleaner when the page has a
first-class **lite profile** (`?lite=1` and a persistent UI toggle): instant
career boot from proven saved maps instead of a ~2 s opening search, optional
suppression of non-gameplay background orbital traffic and decorative redraws,
and one-switch muting of audio and postcard popups — with **zero** change to
physics, economy, or replay determinism.

---

## Goal

Give players, laptops on battery, and test sessions a lightweight mode (`?lite=1`
or a **lite mode** checkbox in the cargo/settings panel) that:

1. Starts career runs immediately from `saved_maps.js` when no explicit custom
   seed is requested.
2. Freezes non-gameplay background orbital traffic and decorative canvas passes
   while keeping the game world and moving-port physics 100 % deterministic.
3. Disables Web Audio synthesis and postcard image popups without touching
   individual sub-settings when lite mode is turned back off.

---

## Design

### 1. Fast default career boot (`gui_maps.js`, `gui_game.js`, `gravity_gui.js`)

- When starting a career run without an explicit `?seed=` or `#game=1` hash:
  - In lite mode (and optionally as the default first-boot career path when
    `SAVED_MAPS` has a matching `kind: 'start'` record for the requested
    `universe` and `players` count at neutral `gs = fs = 1`), pick a proven
    record from `SAVED_MAPS` and arm its `seats` + `targetPay` via
    `GravityMaps.arm(record)`.
  - Boot latency drops from ~2 000 ms (`prepareCareerStarts`) to `< 50 ms`.
- Clicking `new seed` while lite mode is on cycles through matching saved maps
  first, with `Shift+click` (or an explicit `?seed=<n>` URL) still rolling a
  fresh arbitrary 32-bit seed and running the live planner.

### 2. Quiet non-gameplay background (`orbit_view.js`, `gui_frame.js`, `gui_draw_econ.js`)

Separate **initial world state** from **ongoing cosmetic background simulation**:

- `scene.reset(seed)` still runs the deterministic 420-minute pre-history once
  at world creation so colonies, ports, partner links, and starting economy are
  byte-identical to normal mode.
- When lite background is active (`liteBg` on):
  - In `MODE_PLANETS` (static planets, the default for career and classic modes),
    skip per-frame `OrbitSim.step` background merchant flights, builder ships,
    moon-system animation, and decorative trade-ship/lane/colony-ring overlays
    on the `o` canvas; redraw the static planet backdrop only when `dirty` or
    `resize` fires instead of 60 Hz!
  - In `MODE_PORTS` (moving orbital stations), keep `OrbitSim` station orbital
    motion stepping on the game clock (since port positions *are* the gravity
    sources), while still skipping decorative merchant/migrant particle draws.

### 3. Audio & postcard suppression (`gravity_sound.js`, `photo_deck.js`, `gravity_gui.js`)

- Lite mode suppresses `PhotoDeck` popup opens and image fetches (`photo_deck.js`
  never creates `Image()` requests while lite mode is active; purse toasts
  still credit any discovery reward if applicable, or postcards stay silent).
- Lite mode forces sound engine silent without overwriting the user's saved
  `gravity-sound-engine` preference in `localStorage`, and avoids constructing
  `AudioContext` on pointer gestures while active.

### 4. URL & UI controls (`index.html`, `gui_share.js`, `gui_world.js`)

- Query param `?lite=1` enables the full lite profile for the session (`?lite=0`
  forces it off); `syncSeedUrl` preserves `lite=1` when set via URL or toggle.
- Compact **lite** toggle in the cargo/settings strip (with sub-toggles or
  clear tooltip: `saved-map boot · static backdrop · no sound/photos`), stored
  in `localStorage` (`gravity-lite`).

---

## Scope & non-goals

- Lite mode **never** alters `PlanetGravity`, `GravitySim`, `GravityGame`,
  `OrbitEcon` task generation, `GravityBot` search budgets, or `CareerActions` /
  `CareerReplay` hashes. A run played or replayed under `?lite=1` must be
  step-for-step identical to the same seed/map without `?lite=1`.

---

## Verification

- `experiments/lite_mode_test.js` (fast tier, `< 1 s`):
  1. `?lite=1&mode=career` boots from `SAVED_MAPS` without running a cold
     opening search (`< 150 ms`).
  2. `?map=0&you=bot&lite=1` and `?map=0&you=bot` produce byte-identical
     `GravityMaps.captureState` after 1 000 career steps.
  3. Over 60 frames at rest in `MODE_PLANETS`, `?lite=1` performs zero
     per-frame background merchant ship draws and zero `PhotoDeck` DOM opens.
  4. `node experiments/run_fast.js` stays green.
