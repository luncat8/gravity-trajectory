Gravity Map map generator helper

Click on or above the line to add a planet row. Drag to move. Arrow keys nudge the selected row, Delete removes it, Escape deselects. The shaded band is the row's gravity range (gravity ± margin). Colours are the launch tier of the well: what a starter rail of the given ship mass can climb out of to reach a typical neighbour.

design notes 
	minimal css html js

	map generator helper

	horizontal line from negative to positive gravity of planet.

	user can position planet ico (simple circle) on this line: GUI allow set, drag move, remove

	margin of gravity from values, default is +-0.5, to generate randomness.
	Configurable default gravity margin for new planets.

	Configurable gravity min/max , default is -1 .. +4

	→ the design range is clamped to the field's own range (−1 … 3.5, 0.05 grid);
	  a design outside it cannot be generated, so the inputs refuse it.

	click on or above line to add new, click below planet to remove (small red cross draw below)

	preview margin range on line

	color planet based on EMC-1 EMC-2 ability to typically launch from this planet (no hardcoded power, because EMC can be changed in new versions). typically mean on typical map, because it depends on near planet gravity. for my observation -0.2 ... 1.1 is green (EMC-1) and >2.5 || < -1 is red (cant on EMC-2). but this is subject to do some fast tests to find range.

	→ the colour is the climb from the surface to a typical neighbour (`MapGen.launchSpeed`),
	  compared against `OrbitTech.speedLimit` of EMC‑1 and EMC‑2 with the ship mass
	  beside it, so a retuned rail recolours the roster. On a dry 10 t ship that is
	  green to g 0.9 (the probe measures 100 % exits at g 1.0) and heavy above 3.4
	  (measured 96 %); with a loaded 38 t ship green only to 0.2 — which is the
	  "depends on the near planet gravity" the note calls out.

	table of result
	Planet | number to generate	| Gravity	| Margin (±)	| Range 	| Rolled preview

	→ the table keeps those columns and adds the launch tier of each row.

	## integration:
	- ability to load js that 'random saved maps' pre-generated maps to view distribution.
	- press generate to make map from planet list and see result distribution (adjusted by generator).
	- separate panel with planet num input and button to generate original seed maps without this defined planets. and show result planets on the line to visually debug main generator.
	- save result to pre-generated saved maps. to make this possible probably we need note this script should be run from http, otherwise file save dialog.
	- to game add dropdown to select specific saved pre-generated map (near random).

	→ saved maps: `saved_maps.js` is loaded and its real `planetGravity` field is drawn
	  over the design (orange line); "all saved maps" aggregates every record.
	→ generate: the rows are drawn in order onto the field's 0.05 grid and the result is
	  the blue histogram, with the generator's own draw (grey) behind it for comparison.
	→ save: the design is written to `map_fields.js` beside this page (a data script
	  like `saved_maps.js`). The game cannot play a designed field yet — that is
	  `0.7.35-plan-playable-fields.md`, and it is the one open integration.
	→ the game's saved-maps group has a picker beside `load map`, so a specific
	  pre-generated map boots instead of a random one.
