# 0.7.3 plan — buy more ships

Standalone spec: a fork can rebuild this from this file alone. Source note:
`drafts/career-economy.md` §buy more ships:

	settings checkbox:
	allow buy new automatic ship to earn money; acts like bot, shown under player name, shares player purse and all owned property (science/gear) without repaying research.

The checkbox is the feature; the company, not the scoreboard, owns the fleet.
Depends on `0.7.2` for `career.ship.condition` and `wearScale`.

## problem

The page's roster is a fixed 17 slots: `MAX_PLAYERS = MAX_RIVALS + 1 = 17`,
`PLAYER_INDEX = GravityBot.PLAYER_INDEX = 16`, one `sim` per slot, one row per
slot, and `planCareerExpansion` gives each company one new planet per expansion.
A bought ship cannot be a slot:

- it is not a company with its own purse, pads, science or HQ;
- it must share the human company's purse, pads, owned gear and science;
- unlimited ships would overflow `MAX_PLAYERS`, the score rows, and the
  one-planet-per-company map rule;
- a slot's `career` has its own `pads` and `ledger`, so "shares property" would
  mean duplicating every build and every purse update.

The fleet is therefore **inside the company career**, not beside it. One
`career` keeps one ledger, one pad network, one science hull and one set of
owned parts; each ship is a context record that borrows them.

## 1. the ship record

`createCareer` gains:

	career.fleet = [];          // bought ships, flagship excluded
	career.fleetSeq = 0;
	career.fleetSpent = 0;
	career.fleetUnlocked = false; // mirrored by #expFleet
	career.contextBase = {};    // one reusable save slot, no per-step allocation

A fleet ship is a plain record, no arrays allocated per frame:

	{
		id: 1,                  // 1…n, the label after YOU
		at: career.hq,
		ship: {
			hold, engine, tank, obs,
			cargoTons: 0, fuelKg: 0, mass: 0,
			condition: 1
		},
		contract: -1,
		tasks: career.fleetTasks,
		stranded: false,
		flying: false,
		wearScale: 2,
		sim: GravitySim,
		readyStep: 0,
		idleTries: 0,
		waitTries: 0,
		turret: null,
		shots: []
	}

`career.fleetTasks` is a second `BOARD_SIZE` array of empty tasks, created once
in `createCareer` (the same `createTask()` the board uses). A fleet ship never
takes a contract; `careerLandingFacts` still reads `COMPETE_SLOT`, so the array
must exist. `startCareer` **clears** `career.fleet`, `fleetSeq` and
`fleetSpent`: a restart is a new company, not a new ship for the old fleet.

## 2. context swap, not a second career

The existing code reads the ship's context directly from `career`: `at`,
`ship`, `contract`, `tasks`, `stranded`, `flying`, `commercialPlanet`,
`fragileLost`, `wearScale` and the `last*` flight fields. Duplicating those
into a second career would duplicate the purse logic; instead, swap the
company's context for one synchronous step. `wearScale` is part of the swap:
without it the fleet ship would wear at the flagship's ×1 instead of ×2.

	saveCareerContext(career, out)          // `out` = career.contextBase
	loadCareerContext(career, shipRecord)   // copy from `fleet[i]` into career
	storeCareerContext(career, shipRecord)  // copy back after the step
	restoreCareerContext(career, saved)     // the flagship's fields

`contextBase` is allocated once in `createCareer`; the save slot is reused every
step. `stepFleet` in `gravity_bot.js`:

	const saved = GravityGame.saveCareerContext(career, career.contextBase);
	for (let i = 0; i < career.fleet.length; i++) {
		const f = career.fleet[i];
		GravityGame.loadCareerContext(career, f);
		GravityGame.careerAdvanceShip(career, rate, 1);   // wear only, no pads
		if (f.sim.status === STATUS_FLYING) {
			this.careerFlightBurn(career, f.sim, market, runStep, f);
			f.sim.stepOne();
			GravityGame.stepHarvest(f.ledger, market, f.sim, runStep);
			if (f.sim.status !== STATUS_FLYING) this.careerFleetLand(f, trade, runStep);
		} else if (career.ended === CAREER_OPEN && runStep >= f.readyStep) {
			this.careerFleetLaunch(f, market, trade, rate, runStep);
		}
		GravityGame.storeCareerContext(career, f);
	}
	GravityGame.restoreCareerContext(career, saved);

`career.fleetShip = f` is set by `loadCareerContext` and cleared by
`restoreCareerContext`, so every shared function knows it is on a fleet ship.
The company's `ledger`, `pads`, `launchPads`, `padCount`, `science`, `owned`,
`prototypes`, `galaxy`, `market`, `index`, `hq`, `planetMask`, `planetCount`,
`light`, `forceScale`, `seed`, `cheat` and `ended` are never swapped: they are
already the same object.

Pads are advanced **once** by the owner's existing
`GravityGame.careerAdvance(career, rate, 1)` in `stepGame`; `stepFleet` must
not call it or every pad would charge n times. `careerAdvanceShip` is the wear
half split out by `0.7.2` (pads + ship in `careerAdvance`, ship only here).

### what the shared functions do on a fleet ship

- `careerBeginFlight` spends the shared pad's energy, pays the shared purse,
  and sets `career.flying`; `storeCareerContext` keeps it on `f`.
- `careerEndFlight` pays visit income into the shared ledger and writes
  `career.visitIncome`, `flownPx`, `feesPaid`, `flights`, `burns` and
  `maintenanceSpent` on the **company** (they are company totals), then skips
  `refreshBoard` and `checkEnded` when `career.fleetShip` is set. Stranding is
  `f.stranded`, not the flagship's.
- `careerBurn` spends the ship's own `fuelKg`, updates company `burns`, and
  wears `f.ship.condition`.
- `careerDeparture` sees the shared pads and the ship's own mass/fuel; a fleet
  ship can use any pad the company owns and pays tax on a rival's, exactly as
  the flagship does.
- `careerBetweenFlights` returns 0 immediately when `career.fleetShip` is set.
  `careerFleetBetweenFlights` is the reduced shop: repair, buy fuel, nothing
  else. No pads, no research, no expansion, no contracts.
- `careerLand` takes the same path; `careerFleetLand` calls
  `careerEndFlight`, sets `f.readyStep = runStep + CAREER_RIVAL_GAP +
  gapPhase`, then calls `careerFleetBetweenFlights` once (repair/fuel); it does
  **not** call `careerBetweenFlights`.

## 3. buying

Constants:

	FLEET_COST = 30            // cr, flat
	FLEET_RESERVE = 0          // the price is 30, not 30 + a fee
	FLEET_GAP = CAREER_RIVAL_GAP

`buyFleetShip(career, trade, sim, runStep)`:

- refuse unless `careerRule()`, `career.ended === CAREER_OPEN`,
  `career.at === career.hq`, the flagship is landed (`sim.status !== FLYING`),
  not paused at an armed queue, and `purse >= FLEET_COST + FLEET_RESERVE`;
- subtract the price (`price(career, FLEET_COST)`; communism free), add
  `career.fleetSpent`;
- copy the flagship's **current fit** into a fresh `ship` record
  (`hold`, `engine`, `tank`, and a shallow copy of `obs`; fuel 0, cargo 0,
  condition 1, mass via `OrbitTech.shipMass`); this is the "shares owned
  property" promise — the new ship needs no research and no repurchase, but a
  later refit of one ship does not mutate the other's fitted device;
- create its `sim` with the page's world dimensions, planet mask, scales and
  gravity field; `sim.attachCareer(career)` for the launch gate;
- `at = career.hq`, `readyStep = runStep + FLEET_GAP + gapPhase`, `gapPhase =
  fleetSeq * CAREER_RIVAL_PHASE`;
- push, increment `fleetSeq`, expose `GravityScene.fleetCount` for tests.
- Do **not** call `planCareerExpansion`, `setPlanetUniverseSize`, or touch
  `MAX_PLAYERS` / `PLAYER_INDEX`: a bought ship does not need a new planet and
  is not a scoreboard company.

Unlimited: no `FLEET_MAX`. The only limits are the 30 cr price, the shared
purse reserve and the frame budget. If a fleet of dozens becomes a frame cost,
the next knob is a **budget per step** (`FLEET_STEP_MS`), not a cap on the
count; measure before adding one.

## 4. the fleet controller

`GravityBot` gains a fleet list next to `rivals`:

	this.fleet = [];            // records with career/sim for the human company
	this.fleetOwner = null;     // the career they belong to

`attachFleet(career, sim, trade)` is called when a career starts or a ship is
bought; it pushes `{ career, sim, index: PLAYER_INDEX, fleet: true, shots: [],
turret: null, readyStep, gapPhase, idleTries, waitTries, burn... }`.

`stepFleet(runStep, market, trade, rate)` runs after `stepCareer` in
`stepGame` (and after the human's `careerAdvance`), so pads are already
advanced. It uses the existing controller:

- **planning**: `careerFleetLaunch` calls `careerNextShot` with
  `career.contract = -1`, `career.tasks = career.fleetTasks` and
  `career.fleetShip` set. `careerScoreFacts` prices cash + padValue + exit
  exactly as for a company, so a fleet ship chooses a paying landing it can
  leave; no research, no gear, no contract.
- **fuel**: `careerCommitFuel` / `careerPrepareFuel` are allowed (the shared
  purse pays); a fleet ship with an engine may buy fuel like a rival.
- **turret**: `f.turret` is its own queue; `careerLaunch` can queue on the
  shared EMC. `reserveEnergy` already handles the shared pad.
- **landing**: `careerFleetLand` calls `careerEndFlight`; if `f.sim` is lost
  (`at < 0`), `GravityGame.evacuate(career, f.sim)` may fly it home for the
  shared fee; if the purse cannot, the ship is decommissioned
  (`career.fleet.splice`) and the loss is a notice, not a company end.
- **repair**: `careerFleetBetweenFlights` calls `repairCareer` when
  `condition <= CAREER_REPAIR_AT` and the shared purse covers it + reserve;
  a fleet ship wears at `wearScale = 2`, so this is its main upkeep.

The controller deliberately does **not** let a fleet ship:

- build or claim a pad (`buildGear`, `claimOwner`);
- research (`careerResearch`);
- accept a contract or competition (`careerAccept`);
- expand the universe.

Those remain the flagship's actions. This is what keeps one pad network and one
science hull consistent.

## 5. the UI

### scoreboard

The fleet appears **under the YOU row**, not as rival slots. Add a
`#scoreFleetTemplate` (a compact row: name, status, condition, no bot box) and
a `#scoreFleetRows` container after `#scorePlayer`.

- `refreshFleetRows()` runs from `refreshGameUi()`; it reuses rows by index and
  allocates only when the fleet grows.
- Each row: `YOU · ship 2` (player colour), meta `P12 · cond 84 % · flying` or
  `P12 · cond 84 % · ready`, value `+0.00` (its last visit) or empty.
- No `bot` checkbox: a fleet ship is always automatic. The player's own `bot`
  checkbox still controls the flagship.
- The row does not consume a `slot`; `slotCount`, `MAX_PLAYERS`, `RIVAL_TAGS`
  and the `+` / `−` player buttons are untouched.

### settings

The draft asks for a settings checkbox, not a button that is always live. Put
`#expFleet` in the experimental panel next to `stay-pay`:

	<label class="ctl" title="career only · allow buying automatic ships
		that share the purse and property"><input id="expFleet"
		type="checkbox"> allow automatic ships</label>

- Default **off**, per page load, not a URL flag: a career begun without the
  checkbox behaves exactly like today. `career.fleetUnlocked` mirrors it.
- `buyFleetShip` refuses while it is off; the drawer shows the button disabled
  with `enable allow automatic ships in experimental` instead of `buy ship`.
- Turning it off while ships exist does **not** delete them: they keep flying
  and earning, and the drawer says `fleet 2 · buying disabled`. Deleting a live
  ship from a settings toggle would be a trap.

### career drawer

- Header line: `fleet N · 30 cr each · wear ×2`.
- `buy ship · 30` button (disabled unless the checkbox is on, at HQ, and
  `purse >= 30`), calls `careerAct({ act: 'buyShip' })`.
- Each fleet row has a small `decommission` action? Not in v1; the ship is an
  asset. If one is lost, the row disappears with a notice.
- `careerStats` shows `fleet 2 · 60.00` in the property block (add
  `career.fleetSpent` to `out.property`); `maintenance` stays running cost.

### selection / camera

The fleet is visible in the scoreboard and on the map (its own ship marker,
same owner colour, a small `2` tag). Clicking a fleet row does **not** change
the active slot in v1; the flagship remains the hand-flown ship. Selecting a
fleet ship for the aim UI would be a second `slot` and is out of scope.

## 6. replays, links, tests

Career links do not replay builds, pads or purchases (`encodeLink` already
omits career shots); a fleet is a live-career feature. `GravityScene.fleetCount`
and `GravityScene.fleet` (read-only status) are the test contract. No URL flag.

New `experiments/career_fleet_test.js`:

1. **Buy:** with the checkbox on, at HQ with 40 cr, one buy leaves 10 cr,
   `fleet.length` 1, `fleetSpent` 30; away from HQ / in flight / with 29 cr /
   with the checkbox off refuses.
2. **Shared purse:** a fleet flight's visit pay increases the one
   `career.ledger.purse`; a fleet repair subtracts from it.
3. **Shared property:** the fleet ship launches from a pad the flagship built,
   pays no fee on its own rail, and uses the flagship's owned engine/tank
   without a research charge.
4. **Shared science:** `career.research` is unchanged by the buy; a prototype
   bought once is usable by both ships.
5. **No new planet / slot:** `planetCount`, `MAX_PLAYERS`, `PLAYER_INDEX` and
   the score-row count are unchanged; `planCareerExpansion` is not called.
6. **Wear:** the fleet ship's condition falls at twice the flagship's rate for
   the same flight; a repair costs the same 2 cr scale.
7. **Concurrent:** flagship and two fleet ships fly at once; each has its own
   `sim.at`, `fuelKg`, `condition`, turret; the shared pad charge is advanced
   once per step, not three times.
8. **Unlimited:** ten buys in a headless career leave ten flyable ships and one
   purse; no array index error.
9. **No allocation in the frame:** `stepFleet` reuses records; the only
   allocation is a new record on a buy.

`dom_smoke`: the `#expFleet` checkbox exists and is off by default; the `buy
ship` button is disabled until it is on and the ship is at HQ; one buy creates a
`YOU · ship 2` row under YOU; the rival rows are unchanged.

## scope boundary

No rival fleets, no fleet-vs-fleet contracts, no new planets, no new scoreboard
slots, no hand-flying a fleet ship. No resale or insurance. Bought ships share
property and science; they do not share a contract board. `0.7.4` (max
distance) is a different mode and does not need this fleet.
