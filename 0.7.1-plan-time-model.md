## the contract in one paragraph

**A game second is the unit of the whole game.** One physics step is
`DT = 1/120` of a game second, every duration in the game — a flight, a board
deadline, a contract, a barrel turn, an arrest, a pad refill, a political grace
— is a number of game seconds, and no table carries a second unit. Two
multipliers sit **outside** the step and only convert game seconds to real
ones: the **pace** (`play ×N`, game seconds per real second, one ladder
`×0.25…×32`) says how fast the player watches, and the **animation rate**
(`background animation`, ×1…×24, a decoration knob) says how fast the trade sky
drifts. Neither changes a single number the economy reads. A duration the
player *spends* reads in real seconds; a duration the player *buys* reads in
game seconds; a balance still costs the same.

## problem

The tree had four conversions and no written contract:

- `GravitySim.DT = 1/120`. `game.clockSteps` counts steps and `flightTime` is
  `liveSteps · DT` — **flight seconds**, the clock the HUD, board deadlines,
  contracts, barrels and arrests read.
- Pad energy ran on **world time**: `careerAdvance` computed
  `minutes = steps · DT · rate` and charged a panel at
  `power · light · (minutes · 60) / 3600`. With `rate = scene.trade.speed`
  (the background slider, default `0.5`), one game second bought **30 pad
  seconds**: one wait was 60 game seconds and 1800 pad seconds. The battery's
  `leak` is per pad **minute**, the panel's `kW` per pad **second**, and the
  only label either had was the shop's `leak 0.001/y`.
- `politicsSeconds` returned `step · DT · rate` — half a game second per game
  second at the default — while `OrbitEcon`'s `*_SECONDS` constants are priced
  in those half-seconds and `ARREST_SECONDS` really is game seconds
  (`runStep + round(120 / DT)`). One table, two units. The consequence is worth
  stating plainly, because the first draft of this plan missed it: at the
  shipped rate every political constant ran at **half** its named value, so the
  fix is to drop the `rate` factor and leave the table alone, not to double it.
- The labels then mixed all of it: `wait · 30 min` (pad minutes), `ready in
  N s` (game seconds), `play ×4` (game seconds per real second labelled ×1 by
  dividing by the balance's pace), `rate ×0.5` (pad minutes per game second,
  a *gameplay* knob), `leak …/y` (colony years).

Three traps a reimplementer falls into:

1. `steps · DT · rate` is **not** a flight second, and the fact that the pad
   clock ran 30× the game clock is not a property of the sun — it is the
   balance's price, and once the slider moves it becomes a cheat knob for
   pad charge and for the whole political clock.
2. The wait button does **not** cost 15 real seconds. `CAREER_WAIT_MS = 2000`:
   it fast-forwards its whole span in 2 s of eased real time (stretching below
   ~50 fps). 15 s is what watching the same span at the balanced pace costs.
3. The orbit clock (`tradeSim.t`, `START_MINUTES = 420`) is the **animation's
   own clock**, not a gameplay clock. It owns station positions and colony
   flavour and nothing a company's money reads. It keeps its own minutes
   (§out of scope).

## 1. the constants and the helpers

One contract, in `gravity_sim.js` (no new file: every consumer already requires
it, page and node alike):

	GravitySim.DT                   // 1/120, the one physics step, in game seconds
	GravitySim.SUN_SEC_PER_GAME_SEC // 30, the career's sunlight clock (see below)
	GravitySim.WAIT_SEC             // 60, one press of wait in game seconds
	GravitySim.WAIT_PAD_SEC         // 1800 = WAIT_SEC · SUN_SEC_PER_GAME_SEC
	GravitySim.WAIT_PAD_MIN         // 30 = WAIT_PAD_SEC / 60
	GravitySim.gameSeconds(steps)              // steps · DT
	GravitySim.padSeconds(gameSec)             // gameSec · SUN_SEC_PER_GAME_SEC
	GravitySim.padMinutes(gameSec)             // padSeconds / 60
	GravitySim.stepsForGameSeconds(sec)        // ≥ 1, rounded
	GravitySim.wallSeconds(steps, pace)        // gameSec / pace, 0 when paused

Deleted: `WORLD_SEC_PER_MIN`, `WORLD_RATE_DEFAULT` (the name becomes
`TRADE_RATE_DEFAULT` in `orbit_view.js`, where the animation lives),
`WAIT_WORLD_SEC`, `worldMinutes`, `worldSeconds`, `stepsForWorldSeconds`,
`flightSecondsForWorld`.

**`SUN_SEC_PER_GAME_SEC = 30` is the one factor left, and it is named.** A
career's panels see 30 s of sunlight per game second — exactly one trade-world
minute, which is what the sliding background clock used to provide. It is a
*price* of the balance, not a clock: it never appears on screen, and it is the
only place where a pad second is not a game second. Every pad number is
derived from it through `padSeconds`/`padMinutes`, so a future re-price of the
panels is one constant (and the follow-up in §7 would make it 1).

One wait, at the defaults:

	7200 steps = 60 game s = 1800 pad s = 30 pad min of sunlight
	           = 15 real s to watch at ×4 = 2 real s through the button
	           = +0.50 kWh on an SP-1 in full sun (BAT-1 full in 3 waits)

| clock | unit | readers |
|---|---|---|
| game | game second | every table: flights, `flightTime`, board and contract deadlines, barrels, arrest, visit-profit age, pads (`· SUN_SEC_PER_GAME_SEC`), politics, wear (0.7.2), ship age, stats samples |
| real | second of wall clock | `wallSeconds(steps, pace)` — the wait's 2 s, nothing else |
| animation | trade minute | `tradeSim.t` only — station positions, colony flavour, the background panel |
| real (animation) | trade minute per real second | the `background animation` slider, decoration for the lab sky |

`pace` is `playScale()` — the ladder rung, capped at `PLAY_MAX` exactly as the
step loop caps it, in game seconds per real second. It is the only knob that
changes how fast anything gameplay does.

## 2. the labels

The one rule: **a duration the player spends reads in real seconds, a duration
the player buys reads in game seconds, and a speed reads in game seconds per
real second.**

- `play ×N` — **one ladder in every mode**: `PLAY_SPEEDS = [0.25, 0.5, 1, 2, 4,
  8, 16, 32]` game seconds per real second, where ×1 is real time. Career opens
  at **×4** (index 4) — the pace the economy was balanced at; the lab opens at
  ×1 (index 2). `playScale()` returns the rung, `playPace()` the same rung
  capped at `PLAY_MAX = 32` (the loop's own cap, which only a replay's ×16 can
  reach), and `paceTag()` is `×` + the rung. The `game` slider in the game HUD
  is **deleted**: two multipliers over one clock was the confusion this pass
  removes, and the ladder already covers the product range. A mode switch calls
  `resetPlayback()`, which lands on that mode's default index.
- `wait · 60 s` — the game seconds one press fast-forwards. This is the number
  a player can imagine: a board deadline moves 60 s, a contract ages 60 s.
- its live line — what the press buys, in the units those gains are in:
  `wait → P3 +0.50 kWh · board −60 s · visits +0.30`.
- its tooltip — the press cost and the alternative, then the gains:
  `fast-forward 60 s of game time in 2 s of real time (15 s to watch at ×4):
  P3 +0.50 kWh · board −60 s (2 offers rotate) · planet visits +0.30 (3 growing)`.
- while it runs — the button counts percent (`waiting · 41 %`), the line the
  elapsed real seconds and the game seconds they buy:
  `fast-forward · 0.8 / 2 s · clock +24 s · P3 0.90 / 1.50 kWh`.
- the notice at the end — `clock +60 s · P3 pad +0.50 kWh`.
- `background animation ×N` in settings keeps a **separate unit and says what
  it is**: ×1 is the default look, ×1…×24 = `scene.trade.speed` / 0.5 trade
  minutes per real second. Title: `decoration only: how fast the trade sky
  drifts; ×1 is the default look. Nothing a company earns reads it.` The URL
  params (`&rate=`, `&speed=`) keep the raw value, so every link still re-flys
  with the same sky.
- `ready in N s`, `gun · N s`, `board −N s`, `t+ 0:01:00` stay game seconds:
  they are deadlines on the game clock, and a deadline that moved with the pace
  slider would be unusable. The pace tag is the conversion.
- the battery's spec line stops saying `/y`: `leak 3 %/wait` (`leak` is a
  fraction per pad minute; one wait is 30 pad minutes, so BAT-1 loses
  `1 − e^(−0.001 · 30) = 3.0 %` of its charge per wait). Research axis label
  `leak` with the panel's help saying "fraction of charge lost per pad minute".
- Because the wait's tooltip names the pace, it follows it: `refreshPlaybackUi`
  ends in `refreshCareerWaitPreview()`, which repaints the button and its line
  (not the drawer) whenever the rung or a mode switch moves the pace — and only
  while the preview is on screen, since `startGame` resets the pace before the
  career it starts has pads.

## 3. the tables that were priced in another clock

**Politics runs on game seconds by *removing* the old multiplier, not by
re-pricing its table.** The political clock was `step · DT · rate`: at the
shipped `0.5` a "120 s" grace was really 60 game seconds, and every named span
sat at half of itself. That is the same layering this plan deletes, so the fix
is to let each constant mean the game seconds it names — do **not** double the
table (that was this plan's first draft, and it halved every political rate):

| constant | was (name / real at 0.5) | now |
|---|---|---|
| `CORRUPTION_GRACE` | 120 / 60 s | 120 s |
| `CORRUPTION_PASSIVE_RATE` | 0.1 per political s | 0.1 /s |
| `CORRUPTION_REPORT_RATE` | 0.02 per political s | 0.02 /s |
| `REBEL_CHECK_SECONDS` | 60 / 30 s | 60 s |
| `FLYBY_RAMP_SECONDS` | 240 / 120 s | 240 s |
| `ARREST_SECONDS` | 120 / 60 s | 120 s |

Pinned by the bench, not by argument: a stale world grows `21.666667` rot over
20 000 game steps and a reporting ship's decay is `3.333333` points, both
identical to HEAD at the shipped rate. `market.politicsRate` and
`market.politicsSec`'s rate factor disappear; `advancePolitics(market, trade,
runStep)` loses its `rate` argument. The one place a political span was turned
into steps by hand — `seizePlanet`'s cooldown — must stay the span it was: with
the epoch back at 60 s, two epochs is `round(REBEL_CHECK_SECONDS · 2 / DT)`.
`rebellionChance`/`REBEL_K` are per epoch and do not move.

**Pads read pad seconds through one helper.** `careerAdvance(career, steps)`
loses its `rate` argument:

	const padSec = GravitySim.padSeconds(GravitySim.gameSeconds(steps));
	const padMin = padSec / 60;
	const charge = OrbitTech.batteryLeak(pad.battery, pad.chargeKwh, padMin) +
		OrbitTech.solarCharge(pad.panel, career.light[i], padSec);

Byte-identical at the default rate, detached from the slider for good.
`batteryLeak(battery, chargeKwh, padMin)` and `solarCharge(panel, light,
padSec)` keep their units and say them; the `BATTERIES` table says “leak
fraction per pad minute”; the research-unit note in `orbit_science.js` says the
same. **No table value moves.**

## 5. why ×1 is a real second and the ladder starts at ×4

The first pass kept the engine's raw pace and divided the *label* by four, so
career showed `×1` at 4 game seconds per real second and the lab showed `×1` at
one. Two modes, two meanings, and a player could not compute a duration. This
pass moves the meaning into the engine instead: a rung is game seconds per real
second in every mode, so `×4` is 4 game seconds per real second wherever it is
shown, and “a 1 h tech goal” is 3600 game s = 360 real s at ×10.

The balance does **not** move, because nothing reads the label: the step loop
still gets `playScale()`, career still opens on the rung that equals the old raw
pace 4, and the benches reproduce HEAD at the same rate. Only the *ceiling*
changes: the old career ceiling was raw 32 (labelled ×8); the one ladder's
`×32` keeps that ceiling and adds nothing above it.

Rejected: literal `1 game s = 1 real s` at the career default (four times
longer to watch, every flight-second number invalidated); and the label-only
division (`CAREER_PACE_UNIT`) this pass replaces.

## 7. out of scope, and the next plan

- **The orbit clock keeps trade minutes** (`tradeSim.t`, `TICK_MINUTES = 3`,
  `ECON_YEARS_PER_MIN = 1`, `START_MINUTES = 420`). Converting it to seconds
  would touch the colony economy's own “year”, the trade tests and the
  background panel for no gameplay gain: it is a display clock. It is the only
  clock left with a unit of its own, and the plan says so in one place.
- **Separate balance sliders** (pad charge, political pace, profit growth) are
  `0.7.6-plan-balance-knobs.md`, not this pass. A knob that moves the balance
  must be a knob the balance is *measured* against, which is a bench job.
- **Re-anchoring the panel tables to game seconds** (divide every panel `kW`
  by `SUN_SEC_PER_GAME_SEC`, divide every `leak` by 120, and re-anchor the
  merit pars and `METRIC_SCALE` so every price is identical) would make
  `SUN_SEC_PER_GAME_SEC = 1` disappear. It is a cosmetic table job with a
  research-price risk; the balance-knobs plan owns it.
- No wear, no repair prices, no fleet. No change to `DT`, the ladder's physical
  rungs, panel power, the wait's 60 game seconds, or any table value outside
  the political re-expression.
