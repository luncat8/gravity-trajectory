# 0.5 plan — split the cargo GUI into one file per panel

## Goal

`gravity_gui.js` is 8,419 lines / 315,670 chars ≈ 88k tokens, wrapped in a
single IIFE, so any edit costs loading the whole file. Break it into ~20
classic scripts of 200–600 lines, one per panel/subsystem, so that:

- a typical edit loads **at most 2 files** (the area file + the composer);
- every file is small enough to read whole, so no offset/limit guessing;
- an area's state, its DOM refs and its functions sit in one place, so nothing
  has to be searched for across a chain of files.

The split is a pure move: no behaviour, no layout, no API change. It must stay
`file://` friendly with classic `<script>` tags, no modules, no build.

## Why plain global scripts (not a per-file IIFE)

Two mechanisms were considered. The chosen one is: **drop the outer IIFE and let
the declarations become top-level `const`/`let`/`function` in ordered scripts.**

Measured properties of that mechanism, which the encapsulated alternative lacks:

- top-level `let`/`const` of one classic script are visible to the next script
  in the same global scope, and the *same object* is shared — so all 386 call
  sites stay byte-identical and the 106 state variables need no prefix, getter
  or dependency-injection plumbing;
- the same holds inside the headless vm page stub, because `dom_stub.js` runs
  every script in one context; `experiments/` therefore needs no edit at all
  (it discovers the script list from `index.html`);
- a duplicated top-level `const` across two files is a `SyntaxError` at load —
  a wrong boundary fails loudly on the first smoke run, not silently;
- `let`/`const` at top level do **not** become enumerable `window` properties,
  so the global namespace is not polluted;
- each file starts with `'use strict'`, which turns a declaration dropped
  during a move into a `ReferenceError` instead of a global leak.

The rejected alternative — keep an IIFE per file and pass a `create(deps)`
object — preserves module hygiene but rewrites every cross-area reference and
every state access. That is a larger diff, more tokens per file, and a worse
result for the goal above. Encapsulation is not lost where it matters: the
sim/game/bot/econ modules keep their own exported objects unchanged.

### Required pre-flight: the 7 id-shadowing renames

Element `id`s are implicit `window` globals, so a top-level declaration whose
name equals an id silently changes what the name means outside the file. Of the
840 top-level names, 20 collide with the 221 ids in `index.html`; 13 of those
are `const foldBtn = $('foldBtn')` — same meaning as the element, harmless
no-op. The remaining **7 mean something different** and must be renamed before
the first file is created. The renames are narrow — the DOM side already
follows the `El`/`Slider` convention, so only the non-element binding moves and
no `$('id')` string changes:

	line	name	to	collides with
	248	`gravity`	`cargoSim`	`#gravity` `<input>` (the gravity slider)
	636	`gameSpeed`	`gameRate`	`#gameSpeed` `<input>` (the rate slider)
	405	`soundVolume`	`soundVolumePct`	`#soundVolume` `<input>`, and the value is a 0..100 int
	427	`soundAim`	`aimSoundState`	`#soundAim` `<select>`, and the value is `{ sim, ready, tracing, … }`
	1778	`launch`	`launchShot`	`#launch` `<button>`
	5908	`careerWait`	`waitCareer`	`#careerWait` `<button>`
	2450	`helperStop`	`stopHelper`	`#helperStop` `<button>`

Each colliding id is an interactive control — exactly the nodes a bare-name
`launch.click()` would want — so leaving them shadowed is how a split quietly
breaks a click. All 7 replacement names are confirmed unused as both a
declaration and an id. `gravitySlider = $('gravity')`,
`gameSpeedSlider = $('gameSpeed')` and `soundVolumeEl = $('soundVolume')` keep
their names, so the renamed scalars stay visibly fed from them. `careerWait`
carries a family (`careerWaitBusy`, `careerWaitTick`, `cancelCareerWait`, …)
which stays; only the bare entry point moves to `waitCareer`, matching the
`waitSettlement` verb beside it.

Audit gate, run after each move (must print nothing but the header; it works
only once a file's IIFE is gone, since declarations are then at column 0):

```sh
grep -ohE '^(const|let|var|function) [A-Za-z0-9_$]+' gravity_gui*.js gui_*.js \
	| awk '{print $2}' | sort -u > /tmp/n
grep -ohE 'id="[A-Za-z0-9_-]+"' index.html | sed 's/id="//;s/"//' \
	| sort -u > /tmp/i
comm -12 /tmp/n /tmp/i	# every survivor must be an `X = $('X')` element const
```

Also confirmed clear, so no further work is needed: 0 collisions with the globals
the other scripts export (`OrbitScene`, `GravitySound`, `GravitySoundFiles`,
`GravityTrajectorySound`, `GravityVoronoiSound`, `GS`, `PhotoDeck`), 0 collisions
with `Window` built-ins (`name`, `status`, `open`, `frames`, `top`, `origin`, …),
and `index.html` has no inline `on*=` handlers that resolve through `window`.

## Ownership rules

These are what make an edit local; the file boundaries are only their result.

1. **One contiguous range per file where the area is contiguous.** Cutting
   `4405–4764` is a reviewable move; stitching four disjoint ranges into one file
   makes the filename stop predicting the content and the diff unverifiable.
   Three ranges are allowed only when the code genuinely interleaves and the
   alternative is misfiling a whole block to stay inside the limit — measured on
   the current file, `gui_aim.js` has three substantial blocks (4.4k, 8.6k and
   11.2k chars: aim drag, turret/burns/launch, and the pointer + trim handlers
   that sit beside the game clock) and `gui_predict.js` likewise (9.9k, 3.9k,
   3.7k: gain readouts, rule gating, the aim trace). Four or more stays
   forbidden, and a small trailing range should be merged into its neighbour
   instead of becoming a file's second home.
2. **A file declares the state and the DOM refs it owns**, at its top. An agent
   reads ~15 lines and knows everything mutable in that area, instead of
   hunting 106 `let`s. Do not create a shared `state.js`, `selectors.js`,
   `dom.js` or `utils.js` — those force the chain this plan exists to remove.
3. **The composer owns only the six shared objects** (`cargoSim`, `game`,
   `replay`, `helperState`, `bot`, `sound`) plus the cross-panel nodes
   (`canvas`, `ctx`, `tradeControlsEl`). Everything else moves out.
4. **Never split a function away from the state or helper it uses directly**
   just to hit a line target. A 650-line file beats a correct-looking pair that
   each need the other.
5. **Keep each per-frame loop body inside one file.** `frame`, `syncField`,
   `updateHud` and the `draw*` inner loops currently read closure locals; after
   the move they read global bindings and shared-object fields. Splitting a
   hot loop across a boundary would add lookups for no locality gain, and
   `game_bench.js` is the gate that proves it stayed free.
6. **Data flow stays one-directional:** `draw*` reads state and paints, never
   mutates game state; event handlers translate an event into one call on the
   owning area; only the owning area writes its own state.
7. **File header, every file**: 3–6 lines naming what the file owns and what it
   must not touch, then a `provides:` / `depends:` symbol line. That header is
   what lets an agent decide relevance from `head -12` instead of opening the
   body, and it is the substitute for the closure that used to document scope.
8. **No definition-time cross-file reads.** `const scene = root.OrbitScene`
   already pins script order, so a new file may touch another file's bindings
   only inside a function body or in the composer's boot tail.

## Files

The partition is defined by **anchor symbol**, not by line: a file owns every
top-level declaration from its first named declaration up to the next file's
anchor. Anchors are what survive an edit, and the assertion that matters is that
the anchors cover every top-level declaration exactly once, in order — stage 0
established that for 840 declarations across 32 blocks (three files take two
ranges, so blocks exceed files). The line numbers in the table are orientation
only, measured once against the untouched file.

**The line numbers are anchors, not cut points.** Only 3 of the 21 boundaries
happen to fall between declarations; the rest land inside a function body,
because a region's first declaration is not where the preceding statement ends.
So before cutting a region, walk the boundary outward to the enclosing
top-level boundary:

- move a start line *back* to the line after the previous `\t}` / `\t};` that
  closes the last declaration of the region before it;
- move an end line *forward* past the closing brace of the declaration it lands
  inside;
- a block comment that introduces a declaration (e.g. the `/* exact net kWh,
  board ageing … */` before `careerTab`) travels with the declaration it
  documents, not with the region above it;
- the boot tail (`addEventListener` calls, `requestAnimationFrame(frame)`) and
  the `root.GravityScene` literal belong to the composer, so the last region
  ends where the boot begins.

The gate below proves the snap was done — an unbalanced brace means a function
was sliced in half:

```sh
for f in gui_*.js gravity_gui.js; do	# after every cut
	node --check "$f" >/dev/null 2>&1 && echo "ok    $f" || echo "BROKEN $f"
done
```

`node --check` parses the file as a standalone script, so a mid-function cut
fails immediately, per file, before any browser is involved.

### Edit map

The table above doubles as the routing table; copy it into `AGENTS.md` under
`## files` so an agent needs one read and zero searches to pick a file. Two
lookups are unavoidable and cheap: *area → file* (the map) and *symbol → line*

## Stages

Stage 0 is the whole value for agents that never touch the split, and it is
reversible in one commit.

0. Add `/* ── area · file.js ── contents */` banners at every block boundary
   (32 of them, snapped to declaration anchors: twelve files take one block,
   seven take two, and `gui_aim.js`/`gui_predict.js` take three) and
   the `AGENTS.md` edit map. **No line numbers are committed anywhere**: the
   banner *is* the index, so `grep -n "── " gravity_gui.js` returns the areas with
   fresh lines, and it cannot go stale the way a list of ranges would. An agent
   then reads one ~400-line range instead of the file, which is already most of
   the saving and is reversible in one commit.
1. The 7 renames + the id gate. Then `gui_tables.js`, `gui_help.js`,
   `gui_share.js`, `gui_primitives.js`, `gui_science.js`, `gui_shop.js`,
   `gui_book.js` — the low-coupling leaves, mostly pure formatters and HTML.
2. `gui_view.js`, `gui_world.js`, `gui_replay.js`, `gui_hud_game.js`,
   `gui_helper.js`, `gui_route.js` — one panel each.
3. `gui_aim.js`, `gui_predict.js`, `gui_game.js`, `gui_career.js` — where the
   shared `let` state concentrates; here the ownership rules do the work.
4. `gui_draw_world.js`, `gui_draw_econ.js`, `gui_hud_text.js`, `gui_frame.js`,
   then shrink the composer to under 400 lines.

Per file, in this order: cut the range into the new file with the IIFE removed
and `'use strict';` added → move that panel's `$(id)` consts with it → collapse
its loose `let`s into a state block at the top → run the id gate →
`node experiments/dom_smoke.js` → grep the moved names across `*.js` to confirm
no other file referenced them → `git commit`. **One file per commit**, so any
stage is independently revertable and `git bisect` stays usable.

For stages 1–2 the cut is `node --check`-verified text surgery: extract the
snapped range, wrap nothing, and let the composer keep the boot. Because the
boundaries need the outward walk described under **Files**, extract by
declaration name rather than by raw line number when a script does the move.
After the last move, `gravity_gui.js` (the original) goes
to `archive/` as `archive/gravity-monolith-8419.js` and stays out of `index.html`;
`README.md`'s `## files` entry for `gravity_gui.js` is replaced by the map.

## Validation

- `node experiments/dom_smoke.js` after **every** file move, not per stage. It is
  the behavioural net: it reads the script tags from `index.html`, so it follows
  the split with no edit, and it records text paints, frames, events, the URL
  hash and the clipboard.
- The id-shadowing gate and the duplicate-`const` load error as structural
  checks.
- `node experiments/game_bench.js` before stage 1 and after stage 4, plus
  `experiments/logs/` entries: frame time and the `emaFrameMs`-driven budget
  must not regress, since global bindings replace closure slots in the hot path.
- `node experiments/career_bench.js`, `career_bot_bench.js`,
  `career_departure_test.js`, `career_guidance_test.js`, `gravity_bench.js`,
  `route_bench.js`, `layout_check.js` at the end of each stage.
- Manual pass once: aim a shot, land, re-launch from the landed body, switch
  `planets · ports`, open a rule help, switch views, career wait + build,
  open a replay link, change the sound settings.
- `root.GravityScene` keys keep their exact names and values — `bot_bench.js`,
  `dom_smoke.js` and `career_guidance_test.js` read them. `findings-pitfalls-skills.md`
  gets one entry: the id-shadowing audit that a flat-global split requires, and
  the strict-mode/loud-`SyntaxError` properties that make it safe.

## Acceptance

- 8,419 lines become ~20 files; none over 600 lines, and the composer under 400.
- Every listed edit scenario resolves in ≤2 files, checked by picking 10 real
  past tasks and timing the lookups rather than trusting the map.
- `dom_smoke` and every bench report identical behaviour; `game_bench` frame
  time within noise.
- No file needs another file loaded in-context to be *understood*: its header
  plus its own state block names everything it reads.
- `index.html` still runs from `file://` with no build step; `experiments/`
  unchanged apart from added log lines.

## Scope boundary

This plan moves code and renames the 7 id-shadowing bindings. It does not change
physics, economics, aim mapping, replay encoding, bot decisions, the visual
result, `style.css`, or any other module's internals; it does not introduce ESM,
a bundler, a `src/` tree, or subdirectories. It does not dissolve the shared
`game`/`cargoSim` objects into per-area state — those six objects are the
deliberate interface between areas and stay in the composer. Refactoring,
deduplication and the removal of any awkwardness the split reveals are separate
plans; record them in the worklog as findings, do not fold them into a move.
