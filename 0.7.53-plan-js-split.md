## 2. LLM-Agent Locality Rules (Anti-Chain Design)

Naive splits fail agents in two opposite ways: a monolith wastes 80k+ tokens per read, while horizontal micro-files (`constants.js`, `state.js`, `types.js`, `validators.js`, `utils.js`) force a 5–6 file search chain for one feature edit. Every boundary below obeys six hard rules:

1. **Vertical domain slices, never horizontal technical layers.** Never create `game_utils.js`, `game_state.js`, `game_constants.js`, `bot_helpers.js`, or an empty `index.js` re-export hub. A domain file owns its constants (`WEAR_*`, `RADAR_*`, `BRIBE`, `SPORT_*`, `LEG_*`, `OPENING_*`, `ROUTE_*`), its closure-scoped scratch buffers, its refusal predicates, and its state transitions together.
2. **Target 350–1,000 lines (~4k–11k tokens) per file; allow up to ~1,370 lines rather than slicing one algorithm across two files.** Every file fits comfortably in a single `read_file` call with no `offset`/`limit` guessing, and tightly coupled solvers (`game_openings.js` 1,191L, `game_seats.js` 1,369L, `game_legs.js` 1,029L, `comms_facts.js` 1,015L) keep their scratch typed arrays and inner loops in one file.
3. **Contiguous block cuts first.** 8 of 10 `game_*.js` files, 3 of 5 `bot_*.js` files, and all 3 `comms_*.js` files come from **one single contiguous declaration range** in their source file. Two or three blocks are permitted only where the monolith interleaved one domain across sections (`game_career.js`, `game_ship.js`, `bot_burn.js`, `bot_career.js`); four or more blocks are forbidden.
4. **Zero-search routing in `AGENTS.md`.** `AGENTS.md` gains routing tables for `GravityGame`, `GravityBot`, and `CommsCopy` plus a **Cross-Layer Feature Pairing Table** mapping each gameplay subject to its exact `game_*.js` + `bot_*.js` + `gui_*.js` + test script, so an agent opens the right 1–2 files immediately with zero `grep` calls.
5. **Self-describing 6-line header on every file (`head -12`).** Each file header states:
   - what domain and invariants it owns,
   - what neighbour file owns adjacent concerns (to stop wrong-file edits immediately),
   - `exports:` (public symbols attached to `GravityGame` / `GravityBot` / `CommsCopy`),
   - `kernel:` (the tiny set of internal `K.*` hooks it reads or registers).
6. **`/* ── section ── */` banners in every file ≥ 500 lines and all Tier 2 files.** `grep -n "── " <file>` returns fresh line numbers for every internal section without maintaining line numbers in docs that go stale.

## 3. Dual-Environment Module Mechanism (`<script>` + Node `require()`)

### Why `0.5`'s unwrapped-global pattern cannot be used here

`gravity_gui.js` ran only inside `index.html` (and `dom_stub.js`'s single shared `vm` context), so dropping its IIFE into top-level `const`/`function` worked. In contrast:

- **55+ Node scripts in `experiments/`** plus `career_replay.js` and `saved_map.js` load `require('../gravity_game.js')`, `require('../gravity_bot.js')`, and `require('../comms_copy.js')` directly under CommonJS, where top-level bindings are file-private.
- **`experiments/seat_search_test.js`** executes `gravity_game.js` three times via `vm.runInNewContext(source, { module, require: createRequire(gamePath), performance: { now: () => clock++ } })` expecting fresh seat-search memo caches and the `vm`'s mocked `performance.now()` on every run.
- **`Object.keys(...)` and zero `window` pollution** must hold in both environments with no HTML `id`-shadowing risk.

### Chosen mechanism: One-way `attach(Target, K)` parts

The entry file (`gravity_game.js`, `gravity_bot.js`, `comms_copy.js`) remains a real base module — **never an empty hub** — and passes the public target object plus a private closure-scoped kernel bag `K` into each domain part:

```js
/* inside gravity_game.js (loaded FIRST among game scripts in index.html) */
(function (root) {
	'use strict';

	const isNode = typeof module !== 'undefined' && module.exports;
	const K = {
		GravitySim: isNode ? require('./gravity_sim.js') : root.GravitySim,
		OrbitWorld: isNode ? require('./orbit_world.js') : root.OrbitWorld,
		OrbitEcon: isNode ? require('./orbit_econ.js') : root.OrbitEcon,
		OrbitTech: isNode ? require('./orbit_tech.js') : root.OrbitTech,
		OrbitScience: isNode ? require('./orbit_science.js') : root.OrbitScience,
		PlanetGravity: isNode ? require('./planet_gravity.js') : root.PlanetGravity,
		now: () => (typeof performance !== 'undefined' && performance.now ? performance.now() : Date.now())
	};

	/* ... base constants, rule knobs, universal money/PRNG primitives, link codec ... */

	const GravityGame = { /* base exports */ };

	if (isNode) {
		for (const part of [
			'./game_market.js', './game_pads.js', './game_career.js',
			'./game_ship.js', './game_openings.js', './game_seats.js',
			'./game_politics.js', './game_contracts.js', './game_legs.js', './game_flight.js'
		]) {
			require(part)(GravityGame, K);
		}
		module.exports = GravityGame;
	} else {
		Object.defineProperty(GravityGame, '_part', { value: fn => fn(GravityGame, K) });
		root.GravityGame = GravityGame;
	}
})(typeof globalThis !== 'undefined' ? globalThis : this);
```

And every domain file (`game_*.js`, `bot_*.js`, `comms_*.js`) uses the identical 8-line shell:

```js
(function (root) {
	'use strict';

	function attach(G, K) {
		const { GravitySim, OrbitWorld, OrbitEcon, OrbitTech } = K;
		/* ... domain constants, private scratch buffers, functions ... */
		Object.assign(G, { /* public GravityGame exports owned by this domain */ });
	}

	if (typeof module !== 'undefined' && module.exports) module.exports = attach;
	else root.GravityGame._part(attach);
})(typeof globalThis !== 'undefined' ? globalThis : this);
```

**Properties of this mechanism:**

- **Zero circular `require()`:** `gravity_game.js` → `game_*.js` is a strict tree; no part ever `require`s its parent.
- **Byte-identical public API:** `_part` is non-enumerable in the browser and absent in Node, so `Object.keys(GravityGame)` (328 keys), `Object.keys(GravityBot)` (18) + `Object.keys(GravityBot.prototype)` (165), and `Object.keys(CommsCopy)` (22, `Object.freeze`d after parts attach) stay 100% unchanged. Internal cross-file helpers (`refitShip`, `openFlight`, `clearTask`, `fitPad`, `syncCareerNetwork`, etc.) live on `K`, never leaking onto the public object.
- **Zero new browser globals & zero `id`-shadowing:** every part stays inside an IIFE; private `let`s (`openingSim`, `legProbe`, `compositionSim`) stay closure-private per instance.
- **`seat_search_test.js` & `map_gen_test.js` pass unchanged:** each `vm.runInNewContext` call invokes `require(part)(GravityGame, K)` freshly, allocating clean closure caches and reading `K.now()` from the `vm`'s `performance.now`, while `planet_gravity.js` stays ahead of `gravity_game.js` in `index.html`.
- **Zero hot-path allocation or indirection inside loops:** intra-file calls (`stepHarvest` → `harvestPlanet`, `careerLegPlan` → `considerLegHit`, `openingTraceHome` → `openingStarterCanExit`) remain direct closure calls; cross-file calls (`G.padAt`, `K.refitShip`) occur once at flight/shop/board boundaries, matching existing `GravityBot` → `GravityGame` calls.
