# 0.5.4 — Stage 4: draw, frame, wiring — and the split is closed

Five blocks moved, then a sixth refusal worth writing down.

`gui_draw_world.js` 647 · `gui_draw_econ.js` 307 · `gui_hud_text.js` +176/+245 (now 553, its
remit is finally filled) · `gui_frame.js` 216. `gravity_gui.js` 2,590 → **1,025 lines**:
header, the state block, the wiring, `root.GravityScene`, boot. Nothing else in it is area code.

**The draw files came out over the 600 cap and stayed that way.** `gui_draw_world.js` is 647
lines of pure draw functions that write *no* composer state; the plan's own split candidate
("the aim overlay out on its own") was measured and rejected — an aim-behaviour edit touches
`gui_aim.js` plus the overlay either way, so a third file buys 100 fewer lines and one more
hop. That is the cap doing its job (it forced the measurement) and the measurement winning.

**Frame is where the plan's rule 5 stopped being a nicety.** "hud throttle & frame loop"
carried 172 top-level `addEventListener` lines and the fold/sound block another 133, and all
of them read element consts (`gravitySlider`, `trimSlider`, …) at *definition* time. Moving
them was a load-time `ReferenceError`, since the composer declares those refs and now loads
last. So the extractor splits each region two ways: declarations move, top-level wiring stays
in the composer at its original position, and the seam gets a banner so `grep -n "── "` still
lists it. `gui_frame.js` is consequently small (216 lines of loop + throttle functions) — the
wiring really does belong with the state it mutates.

**One over-reach to report honestly:** mid-stage I let the definition-time closure pass move
*whatever* a top-level statement read — including `let aiming` and `let selected`, i.e. shared
mutable state stage 3 had just decided must not move. Smoke caught it; the pass is now
`const`-only. Same lesson as the rest of 0.5: the automation needs a hard rule, not just a
mechanism.

**Tooling bugs found on the way** (all caught by the verification chain, none shipped): my
`split_between.py` wrote a header line outside its block comment and consumed the source
banner, leaving an unlabelled seam; and one `git`-diff "comment-only" check I ran *after* a
commit chain had already mixed two steps' hunks, which is why the banner step and the
extraction step are separate assertions in the recipe now.

**Validation.** Every move: `node --check` both sides, `dom_smoke` byte-identical, `GATE: PASS`.
At the end, the whole experiments dir (29 scripts: benches, career/guidance/departure tests,
sound + voronoi tests, layout check, probes) — **all green**. `game_bench` deterministic
quantities unchanged from `0.5.0`: 26/26 ends · 5404 steps · 1940/1991/223 replay frames ·
1385 steps in one sliced frame · 1944 px · purses 6.97 / 5.20 +2.20 / 11.01 +8.01 / 0.00.

**Where the split landed:** 8,419 lines / 315,670 chars in one file → 315,637 chars in 21
(–33 chars, i.e. headers and banners paid for by trimmed seams), largest editable unit
~88k tokens → **~10.7k** (the composer) and a median area file of ~4.2k. The plan's acceptance
criterion — a typical edit inside ≤2 files — holds: each area file is self-describing and the
state it reads is all in one place that no typical edit needs to touch.

**Left as follow-up, not started:** routing cross-area writes through owning-area APIs (the
100 multi-writer declarations), which is a behaviour-visible refactor and needs its own plan.
