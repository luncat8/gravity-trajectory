# 0.7.37 Worklog — Plan Numbering/Order Fixes, `0.7.36` Field-Map Fixes & Upcoming Plan Review

## 1. Roadmap renumbering & dependency ordering

Revised the `0.7.36` plan numbering and dependency order across all root plan
specs and `drafts/*.md`:

- **Pre-FFT plans moved back into `0.7.*` (`0.7.38`–`0.7.45`), Periodic FFT and
  later moved to `0.8.*` (`0.8.0`–`0.8.6`):** eliminates artificial `0.9.*`
  version splits, avoids any collision with `archive/0.7.0..0.7.37`, and keeps
  both ASCII/GitHub file order and version order strictly monotonic.
- **Max-Distance Modes moved immediately after Periodic FFT
  (`0.8.1-plan-max-distance-mode.md` after `0.8.0-plan-periodic-fft.md`):**
  `maxdistEmc` / `maxdistImp` (`4800×1000`, `78` bodies) depend directly on
  `0.8.0`'s `PLANETS = 192` / `MAX_BODIES = 192`, 3-digit shot/end codec,
  non-48-body field rendering, and radix-2 `GravityFFT` (`512×256` periodic wrap
  by default so `maxdistEmc` can return from either direction, or open strip
  when `&fft=0`). `0.8.0` now parameterizes `(gridX, gridY)` from day one, and
  `0.7.41` ships `galaxy.sport` with `SPORT_LENGTH` first so `0.8.1` §7 plugs
  `SPORT_MAXDIST` cleanly into the live sport table.
- **Helper Dialog, Accessibility, and Sound Improvements placed after all
  gameplay & balancing (`0.8.4`–`0.8.6`):**
  - `0.8.4-plan-helper-dialog.md` (finishes M3/M4 once all modes, sports,
    colonies, fleets, FFT, and rival personas are settled).
  - `0.8.5-plan-accessibility-readout.md` (`#srStatus` & HUD landmarks over the
    final HUD and rule set).
  - `0.8.6-plan-improve-sound.md` (new standalone plan from
    `drafts/sound-and-photos.md` §7.1 covering smooth circle-of-fifths Voronoi
    neighbor-scale consonance in `gravity_voronoi_tones.js`, pruned toroidal
    `192`-body adjacency in `gravity_voronoi_sound.js`, destination-linked
    Voronoi arrival one-shot, and `emcBeacon` block pitches).

## 3. Review fix on `0.7.36` (`gui_maps.js`)

- Fixed three edge cases in `gui_maps.js` from `0.7.36` playable fields:
  1. `fieldParamKey(record)` now verifies `(seed, fieldTag)` and exact resolved
     record identity before emitting a `?map=` name, avoiding collisions when a
     designed field shares a default label with a `SAVED_MAPS` `start` entry.
  2. `mapSameStart` and `mapAppend` now compare `PlanetGravity.fieldTag` and
     deduplicate `kind === 'field'` (and `kind === 'run'` on the same step with
     different fields).
  3. `saveStartMap` updates `activeFieldMap` and `syncSeedUrl()` when saving an
     unregistered field run to `SAVED_MAPS`.
