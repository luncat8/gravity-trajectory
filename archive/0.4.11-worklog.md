# 0.4.11 — Exact Hull Distance & Research Prototypes

## Review of 0.4.10 (`4857726`)

The 0.4.10 worklog said the distance solver was fixed by an exact-vertex short
circuit and that "genuine interior/exterior math is untouched". Checking that
against independent oracles showed it was not:

1. **Interior points were priced as outside.** The projected gradient (step
   `1/‖P‖_F²`, 200 iterations) barely leaves the uniform start on the real tech
   tuples, because `maxForce` ≈ 10² dominates the Frobenius norm. All 20
   provably-interior catapult midpoints and centroids were reported outside with
   distances up to 0.85, which charges about 6 extra purse per unit of distance.
   The engine family had the same failure at smaller scale: `(26, 1.75)` was
   charged 2.085 for a point on the `IMP-1/IMP-3` chord. The vertex short circuit
   hid only accepted vertices.
2. **The "just outside" defaults were partly wrong.** The catapult default
   `(100, 0.74)` is inside the hull (the hull spans efficiency 0.730–0.754 at
   `x = 100`), so its fee was the base 3.00, not `3.04`. The engine default
   `(26, 1.8)` is genuinely outside, at dist 0.0499 and fee 2.30, not 2.38.
3. **§10 was only half built.** The spec says "on accept, the item becomes
   available". 0.4.10 accepted points only grew the hull; nothing became
   purchasable.
4. **The suggested "smallest first" 0.4.11 was not small.** Custom records on
   the shop ladder collide with the tier-keyed logic (`nextTier`, `lighterTier`,
   `upgrades`, `tierIndex`): a record with no numeric tier silently loses its
   next and back rungs. That shaped the design below.

## Design & Implementation

### 1. Exact nearest-point distance (`orbit_science.js`)

- **Wolfe's min-norm active-set method** on the translated vertices
  `x_i = p_i − target`, with a major cycle (add the vertex most against the
  nearest point) and a minor cycle (affine min-norm step, then move back into
  the simplex). It is finite and needs no step size.
- **Affine min-norm via modified Gram-Schmidt** on the vertex offsets, not on
  the Gram matrix. A first attempt used the KKT system with normal equations,
  and it failed in two different ways: an absolute pivot threshold declared
  legitimate corrals singular, and the Gram matrix squared the condition number,
  losing about 4e-6 on a thin sliver. A vanishing `R` diagonal now marks an
  affinely dependent corral.
- **Relative stop.** `(‖x‖² − min_i x·x_i) ≤ ε‖x‖²`. An absolute `ε` on squared
  distances caps distance resolution at about `1e-6` and misclassified a genuine
  sliver interior point. A small absolute floor only ends exact-zero targets.
- The vertex short circuit is removed; Wolfe handles accepted vertices exactly.
- Public API unchanged. `distToHull` no longer returns a `cost` field; it was
  internal only.

### 2. Prototype records on the ladder (`orbit_tech.js`)

- `interpolate(table, key, value, field)`: linear on the bracketing rungs, with
  the end segments extrapolated, so a point past the top rung keeps climbing.
- `engineRecord(id, thrust, mass)` and `catapultRecord(id, maxForce, efficiency)`.
  The rung (`tier`) follows thrust or force, clamped to `≥ 0.5` so it still
  outranks the empty slot. Isp and build cost are read off the same rung. The
  record keeps the table field set, so `copySpec` prints it unchanged.
- Chosen over a separate "custom" tier scheme because every ladder rule then
  works without change.

### 3. Research unlocks prototypes (`gravity_game.js`)

- `researchPoint` accepts the point into the hull, then `unlockPrototype` adds a
  record to `career.prototypes[family]` and marks it owned. The research fee is
  the purchase price, matching §10.
- Labels now come from one career-wide counter (`R<research + 1>`), so an id
  names one record in every family. Per-family labels could collide, for example
  an engine `R6` and a catapult `R6`.
- `prototypesOf` and `prototypeById` are the accessors. Restart clears the
  records with the hull. The bot never researches, so the bot path is unchanged.

### 4. Shop rows and buttons (`gravity_gui.js`)

- **Engine prototypes** appear under the refit block. `fit` is free at HQ,
  because owned records refit like bought parts. The fitted record shows
  `fitted` instead of an offer.
- **Catapult prototypes** appear under the pad gear rows. `build` follows the
  tech tables' upgrade rule, so it needs an empty pad or a higher rung, and costs
  the record's interpolated build cost. The built record shows `built`. A same-rung
  invention is offered disabled.
- `shopRecord(data)` resolves a button to a table tier or a prototype id
  (`data-item`). Both the act handler and the copy handler use it, so every
  prototype also gets a `copy` balance line.
- The science defaults move to `catapult (100, 0.76)`, which is genuinely outside
  at dist 0.0061 and fee 3.04, so the panel still demonstrates both regimes.

## Validation (`experiments/logs/0.4.11-bench.txt`)

- `node --check` clean on every touched JS file.
- **Solver against independent oracles**, run as one-off probes (the seeded 2-D
  brute force is kept in `career_bench`):
  - 24 000 queries against 2-D brute force: max error `4.6e-13`, zero
    classification mismatches.
  - 9 000 queries in 3-D against separating-plane and convex-combination bounds:
    zero violations.
  - Exact rational arithmetic on the real tech points agrees with the new solver
    on every probed point. The 0.4.10 solver was off on six of the eight probes
    (it agreed only on engine `(60, 0.5)` and catapult `(90, 0.71)`).
- `career_bench.js`: `CAREER BENCH OK`. New checks: tech-point recombinations
  inside with base fee, default fees against exact distances, the sliver
  regression, a seeded 400-case brute-force cross-check, prototype unlock and
  labels, engine refit (free, ship mass, Δv, ladder swap back, HQ-only),
  catapult build (empty pad, upgrade rule, cost, generic physics), communism free.
- `dom_smoke.js`: `SMOKE OK`. New 0.4.11 block drives the page through `careerBox`
  clicks: research R1 and R2, fit the engine, build the catapult on HQ, prototype
  copy spec, same-rung build disabled. The 0.4.10 expectations were updated to the
  corrected fee (2.30) and labels (`R1`).
- All other suites green. The four career bot runs and the two scaled runs match
  the 0.4.10 log bit for bit. Those lines are in `experiments/logs/0.4.11-bench.txt`.

## Not verified

- **No browser in the sandbox** (`CHROME_PATH` unset, no Playwright), so
  `layout_check.js` did not run and the new shop rows were not inspected visually
  on the 390 px drawer. The rows reuse the wrapping `careerRow` / `careerBtns`
  pattern, but this needs a real check before release.
- **Balance is untuned.** Prototype fees use the same hull metric as before, in raw
  units. A catapult efficiency change of 0.01 costs the same distance as 0.01 kN
  of force, so the metric favours force. Normalising axes would change every fee,
  so it is a balance decision, not a fix.
