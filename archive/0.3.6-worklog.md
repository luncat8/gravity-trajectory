# 0.3.6 worklog — review of the player switch, route best and action row

## review

Three defects in the 0.3.5 delivery, none of them in the DOM smoke coverage:

- The YOU switch disabled itself on the first use. `refreshGameUi` still set
  `playerBot.disabled = flightLock`, and a bot-controlled run starts a flight
  immediately (a tour/money bot fires the moment control is handed over, a route
  bot starts planning). Every later switch needed the player type radio that had
  just been removed, so the checkbox was effectively one-way.
- `use best` was unreachable instead of merely reflowing. The whole cargo panel
  was the scroll container, `#cargoHud` was capped at `calc(100vh - 76px)`, and
  in game mode the content is ~780 px tall: the action row and the hint sat
  below the fold and the footer (`position: fixed`, centred) covered part of it.
  Nothing was visible at 1280×800 without scrolling the panel.
- The launch label changes length while aiming (`launch` → `launch · 1.00` →
  `launch · leaves system`), and the flexible row it shared with `clear` moved
  `clear` under the cursor. A dedicated full-width row for `use best` did not
  fix that, and the label is the button's feedback.

## implementation

- Dropped the `playerBot` disable entirely: the score row is the control that
  starts and ends a bot run, and stopping a bot run must never be gated by
  `flightLock`. Restarting the run is the documented cost and stays the title.
- Split the cargo panel into a scrolling body and a fixed foot. `#cargoBody`
  scrolls (thin styled scrollbar, overscroll contained), while `#cargoFoot`
  holds `launch`, `clear` and `use best`; the foot is never scrolled away and
  the panel keeps its `pointer-events: none` padding, with `#cargoBody` and
  `#cargoFoot` catching input.
- Made `cargoActions` a fixed grid: the launch button owns a full row, then
  `clear` + the best slot. Nothing in the row can resize or wrap with the label,
  so aiming cannot move the buttons. Without a best slot `clear` spans the row.
- Reserved the trade footer's real height as `--footReserve` (measured on
  resize, since it wraps to two rows below ~1060 px) instead of the fixed 76 px,
  so the foot never ends up under the footer at 900×640.
- Stopped the score rows from wrapping: the live meta line under YOU/R1/R2 was
  `overflow-wrap: anywhere`, so a longer shot summary grew the scoreboard and
  pushed the trade HUD below it while aiming. It is now one ellipsised line with
  the full text as its title, and the scoreboard height is constant per run.
- Added `experiments/layout_check.js`, a real-browser check (headless Chromium,
  `CHROME_PATH`) that fails when the foot crosses the trade footer, the best
  slot leaves the viewport or collapses, the page throws, `clear` moves while a
  plan is being aimed, or the aim readout wraps.
- The layout check also asserts the scoreboard height never changes while scores
  update, which is the flex-stack jitter the wrap caused.
- Extended the DOM smoke suite with the regression itself: the YOU switch must
  stay enabled after switching to a bot, while the bot flies, and after taking
  control back.

## validation

- `node experiments/dom_smoke.js` — `SMOKE OK` with the three new switch checks.
- `CHROME_PATH=… node experiments/layout_check.js` — `LAYOUT CHECK OK` at
  1440×900, 1280×800, 1024×700, 900×640 and 520×760 (`use best` 158 px / 118 px
  wide, foot 10 px above the trade footer everywhere).
- Browser session: the row switches user → bot → user → bot on repeated clicks,
  including mid-flight; `use best · 1465 px` is visible and enabled at 1280×800,
  1024×700 and 390×844; the launch/clear row keeps its rects through a full aim
  sweep (40/90/160 px/s) and back to armed.
- `node experiments/game_bench.js`, `node experiments/route_bench.js` — both OK
  (unchanged physics; only UI state was touched).
