# 0.4.27 worklog — launch sounds and local generation

## Review of 0.4.26

The existing browser layout coverage is useful for the new cargo-header
control; extended it to check the sound button is visible, unobscured and
clear of the title at all eight viewport sizes. One initial DOM smoke run
failed the saved-aim assertion; a diagnostic rerun and the final unmodified
smoke run passed. Its cause was not established.

## Changes

- Added gesture-unlocked aim, armed, launch and flight cues. Synth stand-ins
  play until selected local WAVs are available. Loops crossfade on transitions;
  flight fades on landing or at ten seconds. Mute, cancellation, backgrounding,
  replay/reset, and delayed career turret firing follow the game state without
  changing simulation or replay data.
- Chose Stable Audio 3 Medium distilled for mixed effects and instrumental
  music, based on Stability's benchmarks and the official ComfyUI workflow.
  Documented the lighter Small-SFX alternative, its different sampling and
  reported compatibility issues, model size and license conditions.
- Added an API graph and derived visual workflow, three prompt/settings
  variants per cue, and a standard-library CLI based on the photo queue client.
  It saves accepted jobs as they are queued, resumes collection, builds an
  audition page and installs ffmpeg-converted, trimmed, crossfaded selections.
- Added a project sound-generation skill, setup/selection documentation and
  findings. Generated audio, selected WAVs and queue manifests stay local.
- Real Chromium exposed silent `file://` media routed through Web Audio. Chosen
  WAVs now play directly with native volume ramps; Web Audio is limited to the
  synth fallback. Backgrounding pauses media immediately even if timers stall.
