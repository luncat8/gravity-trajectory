# 0.7.39 Plan — Experimental Stay-Pay (`harvestTick`) Forecast & Book Parity

> **Roadmap position (Pre-FFT `0.7.*` · Forecast parity, 0 balance drift):** Closes `predLogDwell` trace and launch-book parity on the existing experimental stay-pay (`#expHarvest`, `&ht=1`) before `0.7.40` (two-leg quests) and `0.7.42` (`pay ×` balance knob) build on `estimateProfitLog`. Any stay-rate balance tuning is deferred to `0.8.3-plan-bot-balancing.md`.

Deferred half of the stay-pay work (`0.4.30`). The experimental `stay-pay · per
tick` checkbox (`#expHarvest`, career only) makes every step a ship stays inside
a reporting system pay what regrew during that step on top of the entry lump.
Today every trace consumer — aim readout, HUD profit, launch list (`gui_book.js`),
helper scans (`gui_helper.js`), and rival scoring (`gravity_bot.js`) — still
prices only the entry rule and prints `· ≥ticks`. This plan makes
`estimateProfit` / `estimateProfitLog` exact under `HARVEST_TICK`.

## Exact live rules `estimateProfitLog` must match (`gravity_game.js`)

Inspecting `openFlight`, `stepHarvest`, `harvestPlanet`, `harvestStay`, and
`planetProfitAt` pins five exact behaviors that the forecast must mirror to keep
`|estimateProfit − stepHarvest| < 1e-12`:

1. **Spawn-inside systems (`step = 0`):** `openFlight` calls
   `sim.markSystemsAt(sim.cargo.x, sim.cargo.y, ledger.inside)` at launch. Under
   `HARVEST_ENTRY`, those systems are already `inside`, so step 1 is not an entry
   and pays `0`. Under `HARVEST_TICK`, if the ship is **still** `inside[p]`
   after step 1's `stepInsideAt`, `harvestStay` runs on `runStep = baseStep + 1`
   and collects the **full stored `planetProfit(market, p, baseStep + 1)`**
   (pad wait included), stamps `lastVisitStep[p] = baseStep + 1`, and then pays
   1-step drips on steps `2 .. dwell`. If step 1 already exited `p` (`dwell = 0`),
   `harvestStay` sees `inside[p] === 0` and pays `0`.
2. **Entry + stay steps (`step = s0 >= 1`):** When `stepInsideAt` enters `p` at
   flight step `s0`, `harvestPlanet` collects `planetProfit(market, p, baseStep + s0)`
   and stamps `lastVisitStep[p] = baseStep + s0`. When `harvestStay` runs later
   in the same `stepHarvest` call, `planetProfit` is `0` (`pay <= 0`), so step
   `s0` never double-pays; stay drips accrue on subsequent steps
   `s0 + 1 .. s0 + dwell` while `inside[p]` remains `1`.
3. **Surface impact (`END_IMPACT`):** If `hit >= 0` was not yet `inside[hit]`,
   `stepHarvest` triggers one final `harvestPlanet` at `endStep` with `dwell = 0`.
4. **Specials (`capitalPlanet`, `arfPlanet`) & quiet worlds:**
   - `capitalPlanet` has `CAPITAL_VISIT_PAY = -3` and `arfPlanet` has `0`. In
     `harvestStay`, `if (pay <= 0) continue;` skips both, so neither special ever
     drips during stay ticks (`capitalPlanet` charges `-3` on entry only, and `0`
     for a spawn-inside launch from Capital!).
   - A `market.quiet[p]` planet or an unreported step (`s >= reportUntil` when
     the observation device wears out mid-flight, `0.7.2`) neither pays nor
     advances `estScratch[p]` on entry or stay drips — **including** when
     `reportUntil` cuts through the middle of a dwell window (`s0 < reportUntil`
     pays entry + drips up to `reportUntil - 1`, and stops at `reportUntil`).
   - `landing.value` (used by `careerBribeOffer` in `gravity_bot.js`) still
     receives the entry `value` on `landing.body` (`harvestStay` does not touch
     `market.visitPay`), or the uncollected value at arrival when unreported.
5. **Rebellious worlds (`market.rebel[p] === 1`):** `planetProfitAt` multiplies by
   `OrbitEcon.flybyMultiplier(age)`, where `age` depends on `at = baseStep + s`.
   *Correction during implementation:* the closed form
   `paidDwell * planetProfitAtStep(0, 1, market.k)` is wrong — it is not even
   linear for `d = 2` — and a closed geometric series over the exponential
   curve loses ~1e-11 to cancellation at `d ≈ 5400`, missing the 1e-12 bound.
   Every world therefore sums the dwell window step by step, mirroring
   `harvestStay`'s addition order so the two sums match bit for bit; the CPU
   cost stays bounded by the flight length.

## Design

### 1. Preallocated dwell tracking in `GravitySim` (`gravity_sim.js`)

- Allocate once per `GravitySim`:
  - `this.predLogDwell = new Int32Array(PRED_LOG_MAX)`
  - `this.predLogOpen = new Int32Array(MAX_BODIES)` (index of the currently open
    log row for planet `p`, or `-1` when outside / truncated).
- In `routeBeginAt`:
  - Reset `this.predLogCount = 0` and `this.predLogOpen.fill(-1)`.
  - For each active planet `p` where `this.predInside[p] === 1` at spawn, open a
    row `{ planet: p, step: 0, dwell: 0 }` and set `predLogOpen[p] = row`.
- In `routeStep` (after `this.advance` and `this.stepInsideAt` at `s = this.routeSteps`):
  - For every open planet (`predLogOpen[p] >= 0`): if `inside[p]` is still `1`,
    increment `predLogDwell[predLogOpen[p]] += 1`; otherwise set
    `predLogOpen[p] = -1`.
  - For every newly entered planet `p` in `enteredBuf`: open a row
    `{ planet: p, step: s, dwell: 0 }` (merging or capping cleanly at
    `PRED_LOG_MAX`, or raising `PRED_LOG_MAX = BOOK_LOG_MAX = 96` so long loop
    flights never drop tail visits) and set `predLogOpen[p] = row`.
  - On `END_IMPACT` when `!inside[hit]`: append `{ planet: hit, step: s, dwell: 0 }`.
- Zero heap allocation in `routeBeginAt` or `routeStep`.

### 2. Pricing in `estimateProfitLog` & `estimateProfit` (`gravity_game.js`)

- Extend `estimateProfitLog(market, baseStep, planets, steps, count, ledger, reportUntil, landing, dwells)`:
  - Keep `dwells` as the optional trailing parameter (defaulting to zero dwell
    when omitted or when `harvestMode === HARVEST_ENTRY`), so existing external
    callers stay backward-compatible.
  - Under `HARVEST_ENTRY`: skip rows with `steps[i] === 0` (`spawn-inside`);
    process `steps[i] >= 1` identically to today.
  - Under `HARVEST_TICK`:
    - Row with `steps[i] === 0`: if `dwell >= 1` and `p` is neither Capital nor
      A.R.F., treat step `1` (`1 < reportUntil`) as the first stay-pay lump at
      `at = baseStep + 1` and steps `2 .. dwell` (`s < reportUntil`) as 1-step
      drips, stamping `estScratch[p]` to the last paid step.
    - Row with `steps[i] >= 1`: price entry at `at = baseStep + steps[i]` as
      today, then if `dwell >= 1` and `p` is neither Capital nor A.R.F., price
      reporting stay steps `steps[i] + 1 .. steps[i] + dwell` (`s < reportUntil`)
      and advance `estScratch[p]` to the last paid step.
- `estimateProfit(market, baseStep, sim, ledger, reportUntil, landing)` passes
  `sim.predLogDwell`.

### 3. Launch book, impulse-burn prefix & action replay (`gravity_game.js`, `gravity_bot.js`, `gui_book.js`)

- **Launch book (`gravity_game.js`):** Each book entry allocates
  `logDwell: new Int32Array(BOOK_LOG_MAX)` alongside `logPlanet` and `logStep`;
  `recordLaunch` copies `trace.logDwell` (or fills `0` if absent). `saved_map.js`
  and `career_replay.js` pack/unpack `Int32Array` fields generically, so saved
  runs and replays inherit `logDwell` automatically.
- **Bot (`gravity_bot.js`):**
  - `careerLogStore` copies `probe.predLogDwell` into `this.careerLogDwell` and
    passes it to `GravityGame.recordLaunch`.
  - `careerScoreStored` passes `entry.logDwell` to `estimateProfitLog`.
  - `careerBurnVisitPay` joins `prefix.dwell` and `probe.predLogDwell` into
    `prefix.joinedDwell` so in-flight impulse burn previews and bot burns price
    stay-pay identically.
  - Add an encounter-only `market.encounterStamp` (or keep `market.stamp`
    encounter-only as today) and verify sliced vs synchronous bot parity under
    `HARVEST_TICK`.
- **Book UI & `CareerActions` (`gui_book.js`, `gui_predict.js`):**
  - `storedMoney(entry)` passes `entry.logDwell` to `estimateProfitLog`.
  - `saveTrace` appends `Array.from(entry.logDwell.subarray(0, entry.logCount))`
    as element `12` of the `bookTrace` tuple; `applyCareerBookTrace` accepts both
    legacy 12-element tuples (zero `logDwell`) and 13-element tuples.
  - Include `(harvestTick ? 1 : 0)` in `refreshLaunchList`'s cache key (`gui_book.js`).
  - Remove `predTickNote()` (`· ≥ticks`) from `gui_predict.js` and the matching
    `· ≥ticks` suffix in `gui_book.js:launchRowsHtml`.
