# FFT mode: larger torus and random placement

## Review

The periodic map was still the classic 1600×1000 field, and best-of-96
maximin placement spread planets so evenly that they looked like a soft grid:
uniform gaps, no clusters, no overlapping orbits. Request: more random
placement (partial orbit overlap is fine) and a zoomed-out map with more
distance on screen and between planets.

## Changes

- Periodic torus is now 3200×2000 (`OrbitWorld.PERIODIC_WORLD_W/H`): 4× the
  area, same aspect ratio. `GravityFFT.gridFor()` already picks 512×256 for it
  (cells ≤10 px), so the solver did not change.
- `placePeriodicPlanets()`: uniform random on the torus. The only rule is a
  48 px centre floor (roomiest of 40 tries, bounded, so it never loops on a
  dense map) to keep bodies from touching. Orbits use the classic 46–180 px
  range, so neighbouring orbits can overlap. Clusters and voids are intended.
- World size comes from one source: `OrbitWorld.create` → `world.width/height`
  → `Sim.worldW/H` → `GravitySim.setWorldSize` / `GravityBot.setWorldSize`
  → view `fieldBox()`. Every min-image or wrap site that hard-coded
  `WORLD_W/H` now reads the sim size (`orbit_sim`, `orbit_view`, `gui_view`,
  `gravity_gui`, `gui_world`, `gui_helper`, `gui_maps`, `gui_hud_text`,
  `game_career`, `game_contracts`). The view fits the whole torus, which gives
  the zoom-out.
- Classic generation is unchanged: 1600×1000, same RNG stream, same
  fingerprints. Old periodic seeds and replays now produce different maps.
- Docs: `index.html` periodic label, `README.md`, `gui_tables.js` help.

## Tests

- `periodic_roster_test`: the spacing and anti-alignment sweep is replaced by a
  48 px floor, axis coverage, and at least one close pair at capacity (proof
  that placement is no longer maximin). Also checks orbits are 46–180 and the
  world is 3200×2000.
- `periodic_gui_test`: grid is now 512×256, seam coords moved to x≈3198.
- `dom_smoke` 0.8.0 block: seed 5's edge planet sits at x=11.6, so the launch
  spawn is already across the seam (3193). Wrap detection now starts at the
  launch body, the same fix as in `periodic_gui_test`.
- `career_gravity_bench` `FFT=1`: builds its sims at the trade sim's size.

Validation: `classic_physics_test`, `periodic_roster_test`,
`periodic_gui_test`, `periodic_sim_test`, `fft_test`, `special_planets_test`,
`orbit_clock_test`, `politics_test`, `gravity_view_test` and
`make_saved_maps.js --check` all pass. `run_fast.js` passes except the
known-red `balance_knobs_test`. `bot_gravity_test` fails with its known red.
Full `dom_smoke` stops at `0.4.17`, which also fails on pristine base
`75872b3`. Its 0.8.0 block was run on its own and passes.
`run_fast.js --slow` (400 s) has one new red, `career_evacuation_test`: its
embedded replay gets `not a valid replay` instead of `replay opened`. It fails
the same way on pristine base `75872b3`, so it is not caused by this work and
is not added to `KNOWN_RED` here. `two_leg_test` passed in both runs, but its
README note says it is GC-flaky, so the note stays.

## Next step

Try it in the browser at `?mode=lab&fft=1`. If 3200×2000 makes planets too
small when fully zoomed out, add a zoom/pan view for periodic mode instead of
shrinking the world. The unshipped `0.8.1` max-distance plan could reuse
`OrbitWorld.create(..., {width, height})` and `setWorldSize()` directly.
