# 0.3.2 worklog — money mode

Started with a review of the previous task (photos generator
`extra_pnginfo` fix, commit 7815498): the patch itself is sound, but the
hardcoded `WORKFLOWS` map it sits under was the real fragility — commenting out
the krea entry (the model the user does not have) crashed the queue loop with
`KeyError: 'krea'` because `--workflow` defaulted to it. Fixed before this
plan: `comfy_queue.py` now discovers every API-format json in `generator/`,
`--workflow` takes a stem / unique part / `all`, and the default falls back to
the only template present, else the krea one (commit b7e8024).

## step 1 — rules (`gravity_game.js`)

- `MONEY` table with the plan's knob names (`cost`, `k`, `floor`, `landing`,
  `tour`, `purse0`) plus `PURSE_PRESETS` (6/12/20). No preset UI: the plan's §5
  lists none, and presets staying out of the link is exactly what keeps links
  comparable (§3).
- `createLedger(purse0)` → `{ purse, entryStep, tourPaid, last }`; `earn(ledger,
  flight)` pays first entries from their entry steps (Δt since the previous
  first entry, the run's first since its launch — flight clock, so the frozen
  gaps between shots cost nothing), adds the landing fee, the tour bonus once,
  and records `last` = the shot's net. The launch cost is deducted in `fire()`
  at the moment of gating, so a refused launch is impossible to overdraft.
- Reading of "aborts pay nothing": the abort event pays no landing fee, but
  first entries already flown still pay — they are real entries, `visitedCount`
  counts them, and forfeiting them would desync the purse from the tour.

## step 2 — sim (`gravity_sim.js`)

- Per-flight first-entry log: `visitLogPlanet/visitLogStep/visitLogCount`
  (Int32Arrays, filled by `addVisits`, reset in `launch()`), plus the
  `visitLogged` mask which is **run**-cumulative so a system is logged exactly
  once per run. First version reset the mask per flight too — the money bench
  caught it immediately (flight 2 re-logged all 9 old systems, purse inflated
  to 20.80 and per-flight rows went cumulative 9/14/16…). Landings needed no
  new state: `endReason === END_IMPACT` + `landedBody` already carry them.

## step 3 — GUI (`gravity_gui.js`, `photo_deck.js`, `index.html`, `style.css`)

- `game.money` ledger, fresh in `startGame`; `fire()` deducts the cost;
  `endGameFlight()` calls `earn()` (baseStep = `game.steps` before the flight
  folds in, same pattern as `doneSteps`) and shows the toast.
- `gameLocked()` gains `purse < cost`: a broke run closes aiming, the launch
  button reads `purse 0.40 · need 1.00` (own state bit in `setLaunchState`, so
  the text updates when a flight ends broke while already blocked), status
  reads `purse empty · run over`. Replays are unaffected — they fire through
  `advanceReplay`, not `launch()`.
- Purse stat `13.15 · last +1.15` with `loss`/`gain` colouring; score line
  carries the purse after time; verdict is `verified ✓ · purse 13.15`
  (recomputed, nothing money-related in the link).
- Toast reuses the postcard slot (`PhotoDeck.toast`, 2.5 s, no art): a card
  that is open or landing in the same frame keeps its moment, the toast follows
  the open one, a newer card drops it, and the × button dismisses the queue
  too. Skipped entirely when the landing card owns the frame.
