## step 1 — `careerAdvanceShip` split (0.7.2 hand-off)

- `game_ship.js`: `careerAdvanceShip(career, steps, flightStep)` is the wear
  half of `careerAdvance`; `game_flight.js`: `careerAdvance` ends with a call

  calls only this for each fleet ship.

## decisions recorded while implementing

- The ledger carries flight-scoped state (`fee`, `shotGain`, `shotVisits`,
  `lastPlanet`, `inside`, `reports`), so two ships flying against one ledger
  would corrupt each other's visit masks. The context swap therefore covers a
  per-record `flight` block plus the company's block in `contextBase`; `purse`
  stays shared.
- `checkEnded` returns at once for a swapped context (`career.fleetShip`): a
  fleet loss starts no company recovery, and no fleet-context call can clear
  or tick the flagship's recovery.
- `careerBeginFlight` skips the sport `attemptedMask` stamp on a fleet ship:
  the shared event is company-indexed and the flagship may have entered.
- `careerEndFlight` skips `refreshBoard` and the return-landing visit book on
  a fleet ship; landing settlement itself is safe (`contract` is -1 in the
  swapped tasks, `settleSport` needs an accepted COMPETE_SLOT).
- The fleet sim gates on `setLaunchNetwork(career.launchPads, f.ship)`
  (`attachCareer` would freeze the flagship's ship object into the sim).
- A fleet record carries `career` and `index` (YOU's trace index), so the
  existing controller (`careerNextShot`, `careerLaunch`, sit, recharge) runs
  against it unchanged; the only edits are the race-entry skip and the
  `careerBetweenFlights` gate that detours to the reduced fleet shop.
- Decommission: a lost ship with no evacuation target is spliced with a
  notice; a company end is never triggered by a fleet ship.

## step 2 — save / restore round trip (was missing)

A loaded page starts with an empty `career.fleet`, so the old `applyState`
unpack loop (`for i < fleet.length`) never ran and the fleet silently vanished
on reload. Fix:

- `game_career.js`: `restoreFleetShip(career, trade, sim, saved)` rebuilds one
  fleet record from its saved fit and the flagship sim's geometry/field, then
  returns it; exported on `GravityGame`.
- `saved_map.js` `applyState`: after the sim loop (so the flagship sim's
  `planetMask`/field are restored) rebuild `career.fleet` record-by-record via
  `restoreFleetShip`, unpack the saved flight state over each, relocate/restore
  the sim flight keys, and re-attach to the launch network.
- `gui_maps.js` `applyRunRecord`: re-alias the rebuilt records into the
  controller (`bot.attachFleet`) so the restored fleet keeps steering itself
  (per-ship trace index / burn state backfilled).
- `experiments/dom_stub.js`: the fleet template clone mirrors real DOM nesting
  (`row > name|value|meta`) so `name.parentElement === row` holds in tests.

## decisions recorded while restoring

- The fleet sim is rebuilt from the flagship sim (`info.sims[career.index]`),
  never from the saved record: the world, planet mask and gravity field are
  derived from the armed seed/universe, not stored. Only the past (fit,
  position, flight keys) is saved.
- `career.fleetSeq` is reset to 0 then bumped by each rebuild so ids come back
  identical to the saved `id`; `fleetSpent`/`fleetUnlocked` ride on the normal
  career unpack (`CAREER_SKIP` does not list them).

## 2026-11-27 — updated buy-ships draft

### review

The earlier implementation already had shared company property, unlimited
fleet records, independent simulations and ×2 wear. Its completion note did
not cover the updated draft: buying was opt-in/HQ-only, the row showed only
the latest visit, and fleet paths/controls were absent. Save review also found
lost queued launches and sequence reuse after retiring the highest ship ID.

### changes

- Buying defaults on in both the model and settings; any inhabited in-play
  planet can sell a ship. New vessels start there. Empty worlds, space,
  flight, arrest and evacuation refuse. Capital starts need no HQ.
- Each vessel accumulates the shared purse's change only during its own
  synchronous context. Net starts at minus the actual purchase price, so
  service/fuel/launch/evacuation costs reduce it; flagship transactions and
  other ships cannot leak into that total.
- Mint rows show lifetime net, support click/keyboard inspection (shots and
  fuel), a bounded per-ship decision-log copy, and an automatic-pilot toggle.
  Off releases queued energy and parks after the current flight/tow; it is
  not manual control and does not freeze flight physics or the company.
- Fleet predictions use the existing memo and path renderer, computed only
  for the hovered/pressed/focused ship or row. They work without HQ radar
  and stay hidden when only the global prediction checkbox is checked.
- Queue cancellation clears the correct vessel context, never the parked
  flagship's landing. Fleet trace events are ID-tagged and no longer look
  like flagship flight events to action recordings. Purchases, buy-setting
  changes and pilot toggles are recorded as actions.
- Saves preserve net, pilot flags, logs, the sequence and queued launches;
  pad references are rebound without reserving energy twice. Loading also
  restores the buy checkbox and reattaches YOU's fleet, including an empty
  fleet. Rival inspection cannot hijack its controller.
- The DOM stub mirrors the fleet control-group nesting. Added focused test
  filtering to the fleet test (`node experiments/career_fleet_test.js page`).
- Moved the standalone specification into `archive/`, corrected its stale
  gates/UI/persistence sections, and updated README/draft links and status.
