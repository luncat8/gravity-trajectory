# 0.4.3 Worklog — flat mode row and the career drawer

## Review of 0.4.2

0.4.2 shipped the career *rules* headless (`GravityGame.buildGear`,
`bulkUpgrade`, `installPart`, task board, `evacuate`, `careerAdvance`) and
suggested the GUI slice. Reading it before starting turned up three things:

- **the mode/rule split was dead weight.** `lab | game` + a hidden `rule` group
  (forced by `gameBox[hidden]`) meant two clicks and a JS-hidden box just to
  pick a rule, and `selectedHelpRule()` had to sniff `ruleMoneyEl.checked` to
  answer "which rule is selected". The career had no radio at all (link only).
  Replaced by one flat row (`career | lab | visit all tour | route length |
  money for visit`) driven by the same `setPlayMode`; lab is "no rule", every
  other value is a `RULES` key, so `?mode=` and `?rule=` accept the same names.
- **`setMode` did two jobs**: it set the gravity *source* (planets/ports) and
  looked like the play mode. Renamed to `setSource` — the name collision was
  the only reason the two groups looked related.
- **career status lived where the HUD cannot wrap.** The launch button read
  `stranded · build a catapult or evacuate`; with the run box visible at 1280
  the grid cell is 267 px, so the label now says `stranded · build or evacuate`
  and the *explanation* lives in the drawer (which has room for it).
- pad plates drawn under a planet are hidden by the HUD panels (`P21` sits
  exactly under the cargo panel at 1280×800). `drawCareerPad` walks four slots
  (below/above/right/left) and takes the first that misses the cached panel
  rects (`measureHudRects`, refreshed on resize and on HUD changes — never per
  frame).

## Implementation

### 1. `index.html` — one flat mode row

```
MODE   ( ) career  (•) lab  ( ) visit all tour  ( ) route length  ( ) money for visit
RUN    [caption: rule] rival radios · seed · purse · restart / new seed / copy replay
CAREER planet select · pad block · task board · shop · wait / evacuate · note
```

`gameBox` → `runBox` (visible for every rule now, rivals hidden for a `solo`
rule), `careerBox` is new, `modeLab/modeGame/ruleTour/ruleRoute/ruleMoney`
became `modeCareer/modeLab/modeTour/modeRoute/modeMoney`. The rule caption
(`#ruleTag`) stays the one-line rule state (`career · 3 / 26 pads`).

### 2. `gravity_gui.js` — mode row

- `modeEls` is a flat `[value, el]` table; `syncModeRadios()` writes it from
  `game.on ? game.rule : PLAY_LAB` (called from `refreshGameUi`, so a link or a
  `setPlayMode` from the console can never desync the radios).
- `setPlayMode(next)`: `lab` → `stopGame()`; a rule → `startGame(seed, …)` and
  a restart message; the active rule is a no-op. A flight disables every mode
  but `lab` (the escape hatch stays reachable).
- the mode tag lost the now meaningless `game ·` prefix (`run · clock runs in
  flight`, `run · planner · no launch`, `lab · free clock`); an invalid link
  that never started a run reads `invalid link · back to lab` instead of
  implying a run exists.
- Help drawer previews any mode on hover/press/focus; the default selection is
  `lab`, `selectedHelpRule()` is now `game.on ? game.rule : 'lab'`.
- `?mode=career`, `?mode=money`, `?mode=lab` all load the right run; the `mode`
  parameter is read as a rule name when it is one.

### 3. `gravity_gui.js` — career drawer

Everything is generated from records, one delegated `click` on `#careerBox`
plus `data-act/data-kind/data-tier/data-slot` (so a re-render never leaks
listeners, and the benches can click the *rendered* markup):

- **pad block** (`padBlockHtml`): planet, ship mass, hold/engine/tank, catapult
  · panel · battery, a charge bar, `max N px/s · full shot X kWh`; stranded or
  lost says so and offers `build EMC-1 here`.
- **shop** (`gearRowHtml` / `partRowHtml`): the next tier per gear kind on the
  selected planet plus `all N · <total>` for a bulk upgrade of every built pad
  (`GravityGame.bulkUpgradeCost`); ship parts are `buy`/`fit` at HQ only and
  show `free` when already owned. Buttons carry the **table index**
  (`tierIndex`), not the record's `tier` — the hold/tank tables start at tier 0.
- **task board** (`taskRowHtml`): `from → to · good N t · pay · time left` with
  `accept` (disabled with the reason in the title: hold too small / one contract
  at a time) or `drop`; the sport slot shows the planet and the minimum landing
  length.
- **`wait · 30 min`**: `careerAdvance(career, rate, steps)` with
  `steps = 30 / (DT · rate)` — always 30 world minutes whatever the trade rate
  — plus `game.clockSteps`, `tradeSim.advanceTo(t + 30)`, `refreshBoard`, and a
  notice with the real charge gained. Its title previews the gain
  (`waitGain`).
- **`evacuate · 5.00`**: only enabled while stranded, calls
  `GravityGame.evacuate`, cancels the aim and re-follows the ship.
- the planet selector follows the ship (`careerFollow`) until the player picks
  a planet; a landing re-enables following.
- `careerFollow`/notice reset in `startGame`, so a restart never inherits a
  stale pick or message.

### 4. Reading the pad at a glance

- the launch button shows the pad note only when it blocks (`pad 1.50 kWh ·
  shot 4.84 · max 111 px/s`), never on a shot the pad can fire.
- a plate under the landed planet (shaded to the HUD-free side) shows
  `EMC-1 · 1.50 kWh · 111 px/s` + charge bar, red when the shot band
  (< 90 px/s energy) is not affordable. Strings are cached by
  `(planet, tier, 0.01 kWh)`, so `draw()` allocates nothing.
- scoreboard meta is `N pads · N shots · time`, the role tag names the mode.

### 5. Aiming through the HUD

A career HQ is often *under* the cargo panel (`P21` at 1280×800). `hudPadPress`
lets a press that lands on the panel's padding start an aim when it is over the
ship's pad and not over a control — the pad is usually the largest thing on
screen there, and the previous behaviour (press does nothing) was a dead end.

## Notes

- the pad the player stands on is the one the flight leaves from, so the block
  shows `at P1` (no catapult) while the shop can still build anywhere.
- `wait` is a *free* action: it spends the world clock, which also ages the
  task board and grows the visit profit of unvisited planets — the career is
  the only rule where standing still has a price and a reward.
- the trade footer `speed` now scales the wait's step count, never its world
  minutes, so the same wait is worth the same charge at ×0.5 and ×12.
