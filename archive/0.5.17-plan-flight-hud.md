# 0.5.17 plan — impulse flight loop and the flight HUD panel

Standalone spec: a fork can rebuild this file alone.

## Goal

Two asks that meet in one panel.

1. **The impulse loop is pause-first.** A career ship with an engine and fuel is
   paused (the footer time button or Space / P), then dragged from the *paused* ship to aim a burn, and
   released to arm it. `Enter` burns (which unpauses and continues the flight);
   unpausing by any other route cancels the arm. A press on the *flying* ship
   does nothing, so a moving ship can never steal a press meant for a planet.
2. **The bottom-right panel becomes the flight HUD.** It holds everything about
   the ship and the flight in one place — facts, action, the work it is flying
   for, and the auto-helper scans — instead of being a launch row with a scan
   block bolted on top.

## 1. the impulse loop

- `onPointerDown` on the ship aims a burn only while the shared career clock is paused; it enters the
  grip directly (`takeOverBurnAim`) instead of the old press-then-drag takeover,
  so `burnPressing` disappears. Nothing about a live flight press changes: the
  press is not taken and the planet/hover logic below it sees the event.
- The footer time button and `Space` / `P` toggle the shared career clock. Unpausing runs
  `clearBurnAim`, so an armed burn is dropped — the arm never survives a resume.
- `Enter` executes the armed burn and unpauses (`executeBurn` → `clearBurnAim`);
  with no arm and a landed shot armed it launches, as before.
- The `#launch` button is the *context action*: it shows `launch …` while landed
  and the burn label (`burn · Δv N px/s (−kg · price)`) only while a burn is
  armed. The existing footer time button controls the same pause; resuming clears the arm.
- Everything else about the career action row is unchanged: the queued EMC
  (`gun · N s`), the pad note, `buy EMC-1`, `commercial EMC-1`, `evacuate`,
  `clear`, `use best`.

## 2. the flight HUD panel

`#cargoFoot` becomes `#flightHud` (`aria-label="flight hud"`), same place and
width, four groups in reading order:

| group | content |
|---|---|
| head | `flight hud` + a state tag: `landed P#` / `coasting` / `flight paused` / `burn armed` / `scanning i/n` |
| ship | `speed` (live `|v|` in flight, the armed aim speed on a pad), `flight time` (`sim.flightTime`), `engine` (`IMP-1 · Δv 22.4 px/s` from the fit, or `none`); career only: a `fuel` gauge, `fuelKg / cap kg`, and `refuel · <cost>` |
| action | the context `#launch`, the planet actions, `clear`, `use best`, with the shortcut in the caption (`enter` / `space`) |
| work | the open work as planets: the taken contract's next stop (load / deliver / medics out / patients home) and the competition planet |
| helpers | the auto-helper scans, unchanged (`quick scan`, `scan here`, `tweak best`, `best profit`, `profit + EMC`, `quest scan`, progress bar, stop) |

- **Grouping rule:** ship facts describe the vessel, the action row is the one
  button that moves it, `work` says where it is going and why, and `helpers`
  are the scans that place that shot for you. A reader goes top-down: what state
  am I in → what can I press → what is left to do → let the page aim.
- **Refuel** (`#flightRefuel`, in the fuel row, directly above the action row):
  one `FUEL_BUY_STEP` top-up that spends the owner's unreserved pad charge first
  and buys the rest, so the label is `refuel · free` when the charge covers it
  and `refuel · 0.80` when money is needed. Disabled with no engine/tank, a full
  tank, or no convertible charge and no purse.
- **Quest arrows:** pointing at a work row sets `questHoverBody`; the canvas
  then draws the guide arrow (`drawGuideArrow`, the blocked-launch arrow's
  shared chevron stream) from the ship (in flight) or its planet (landed) to
  that planet, plus a ring on the target. Leaving the list clears it. The rows
  rebuild only when their key changes (contract slot, state, targets, deadline
  minute), never per frame.
- Element refs and the panel's own state live in the new `gui_flight.js`;
  `setLaunchState`'s flight branch delegates to it so the label logic stays in
  `gui_hud_text.js`.
