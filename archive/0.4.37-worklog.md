# 0.4.37 worklog — heading-relative trajectory sonification

## Review

The prior flight voice did have separate left/right output channels, but its pan
was driven by world-space `dx`. That only said whether the planet was left or
right on the canvas; it ignored the ship's velocity and could reverse meaning as
the ship turned. The screen-side mapping was not useful as a ship-relative
bearing.

## Implementation

- Flight pan now uses the current cargo velocity as the ship's instantaneous
  heading and the vector from cargo to the nearest planet. A signed normalized
  cross product maps ship-left/right to the corresponding stereo channel; the
  launch angle is only a fallback for zero velocity. The nearest target is
  selected by distance to its surface, matching the loudness mapping.
- The predicted visit fly-through and destination EMC beacon use the planet's
  bearing from the relevant prediction point relative to the local trajectory
  tangent. Aim angle/speed changes invalidate cached event panning. GUI telemetry
  no longer sends screen-center pan values.
- Both flight mappings keep their prior identities and distance behavior:
  pentatonic note + nearer-is-louder, or planet instrument + farther-is-higher
  and quieter. UI hints, plan, README and sound documentation now describe the
  heading-relative mapping.
- Tests cover a ship turn swapping a planet from left to right, a planet ahead
  centering, fly-through and EMC panning relative to predicted headings, and
  distance behavior in both flight variants.

Ordinary stereo pan conveys lateral bearing only: a planet directly ahead and
one directly behind are both centered. A future fore/aft cue would need a
separate sound dimension rather than more screen-space pan.
