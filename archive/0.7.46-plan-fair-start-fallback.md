# 0.7.46 Plan — Fair-Start Fallback When the Seat Search Runs Out

> **Roadmap position (Pre-FFT `0.7.*` · after the `+5` map law):** the seat
> planner (`planCareerSeats` in `gravity_game.js`) is a bounded, deterministic
> search. On a few rosters it returns its best unfair (or shared) seating even
> though a fair one exists. This plan decides what the *game* does then, so the
> planner never has to be unbounded.

## Where the planner stops

`0.7.43` gives every roster a plan (`experiments/career_start_fairness.js`,
`MATRIX=1 ALT=1 ASSERT=1`, `experiments/logs/0.6.8-roster-matrix-after.txt`).
Two kinds of seed are still left over:

- **Out of budget (fair set exists):** `20/6` seeds 5 and 10. The independent
  oracle finds one fair HQ set among its first 1000 candidates. It sits at about
  #177 in the unpinned-proxy order, with a proxy ratio of `0.10`, so reaching it
  takes about 22 s of exact traces. The planner's wide walk stops after 400
  traces (`roomyTraces / count`), at `0.39` / `0.48`.
- **Cramped universes (`COUNT ≤ 13`):** a few seeds where an exit-safe or fair
  set exists but the short walk (`traces 2400`) misses it: `13/4` seed 1, `13/5`
  one fair seed, `13/6` one exit-safe seed. The plan time also exceeds the 4 s
  target on `13/4`, because of the legacy floor walk that the saved maps depend
  on.

Raising the trace budget only moves time between these two problems. Of the
ranking proxies tried (pinned heavy candidates, adaptive re-ranking, pair
ranking, cold windowed ranking, one-swap local search), none brings the needle
sets forward. The planner can report `openingGroupAccepted(plan.stats)`, so the
game can tell when it is in this case.

## Options, cheapest first

1. **Say so, and let the player choose (UI, no new physics).** When the plan
   is not accepted, the helper says so over the radio (`0.8.4` helper dialog)
   and offers three choices:
   - *continue the search*: a sliced, background continuation of the same walk
     with a larger budget. It must stay deterministic: the same seed and
     roster always give the same HQs.
   - *load a fair saved map* (`saved_maps.js` / `?map=`).
   - *start as drawn*: the unbalanced start, with the measured ratio shown.

   Only the first option costs anything, and it reuses `planHomeSet` with a
   different law.
2. **Repair the map, not the seating.** `planCareerExpansion` already enables
   one inactive generated planet for a late rival and checks it as a g 1.00 HQ
   in the final field. The same one-seat search can add a *good planet* for the
   weakest seat: a light, exit-safe site whose pay lands inside the band. This
   works only where the roster leaves inactive planets (`COUNT < PLANETS`). It
   changes the universe size, so saved maps must record it.
3. **A symmetric start.** All companies start from one place: an Imperial
   berth or a free-space spawn with fuel. Fairness then holds by construction,
   with no HQ search at all. This is a new career mode, and its first HQ becomes
   a choice the player makes.
4. **Economy knob (`MONEY.initSec` 40 → 120–200).** Measured in
   `0.7.43-fair-start-report.md`: it moves the 20/6 needles from #177/#172 to
   #28/#8. But it breaks 0.7.7's "a quick hop pays what it always paid", so it is
   an economy decision first.
5. **A cheaper exact check.** Coarse-to-fine fans, exit probes only for the
   chosen assignment, pair-pinned ranking above 14 candidates. A 5–10× faster
   check brings the top 250 inside 4 s. The catch: a 4×2 fan correlates poorly
   with the 8×4 fan on these seeds, and `predictFast` takes about 93 % of the plan time.

## Contract to keep

- The default career (`COUNT=13 SEATS=3`) and every saved map keep their HQs.
- Any fallback is deterministic per seed and roster, and it is visible: the
  player is told when a start is not fair. It is never silently unfair.
- `career_start_fairness.js ASSERT=1` stays the gate. The leftover seeds above
  are its current `FAIL` lines, and they are the measure of this plan.

The question to answer first: is an unfair start acceptable if the player is
told about it (option 1), or must the game always repair it (options 2–3)?
