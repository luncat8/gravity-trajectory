# 0.5.1 worklog — flat global scripts, first six areas out

Stages 1a–1c of `0.5-plan-gui-split.md`: the pre-flight renames, the unwrap, and
the low-coupling leaves. `gravity_gui.js` 8,455 → 6,621 lines; six files born.

## Order of operations

1. **1a — the 7 id-shadowing renames** (`gravity`→`cargoSim`, `gameSpeed`→`gameRate`,
   `soundVolume`→`soundVolumePct`, `soundAim`→`aimSoundState`, `launch`→`launchShot`,
   `careerWait`→`waitCareer`, `helperStop`→`stopHelper`), 301 references over 267
   lines, no `$('id')` string touched.
2. **1b — drop the IIFE.** `'use strict';` + `const root = …` at top level, whole
   body dedented one tab, wrapper lines gone.
3. **1c — cut the leaves**, one commit each: `gui_tables.js`, `gui_help.js`,
   `gui_share.js`, `gui_science.js`, `gui_shop.js` (two blocks), `gui_book.js`
   (two blocks).

1b is a hard precondition the plan did not state: while the state was IIFE-local,
an extracted file could not see it, so nothing could be cut at all. Unwrapping
first is what makes every later cut a plain block move.

## Why the renames are not a word-boundary sed

`\bgravity\b` also matches the `gravity:` key of `experimentScales` (a
`root.GravityScene` contract key read by the benches) and the `$('gravity')` id
string; `\blaunch\b` also matches `sim.launch()`, `sound.launch()` and
`cargoSim.launch()`, which belong to other modules. So the rename ran through a
scanner that tracks string and comment state per line and classifies each
occurrence as ident / property / object-key, renaming idents only — and it kept
exactly the 4 property/key sites it had to. Shorthand properties were checked
separately: none of the 7 appears as `{ name }`, so no contract key moved.

## Load-order facts this stage established (now in the plan)

- **the first gui script owns `root` and `$`**, and no other file may declare
  them — a second top-level `const` of one name is a `SyntaxError` at load. That
  is `gui_tables.js`, which is why it loads first and why the `$` that travels
  with its block must not also be emitted into its header (an early draft of the
  generator did exactly that and was caught by `node --check`).
- cross-file reads at *definition* time are the only ordering hazard; call-time
  reads are free. `const OrbitTech = root.OrbitTech` in the tables block is a
  definition-time read, hence the rule above.
- a block cut leaves a seam; two consecutive blank lines mark it, so the
  generator normalises the seam to one blank and puts a `/* ── … */` divider on
  it in the two-block files, which keeps `grep "── "` a valid section index
  inside those files too.

## Method note

The extractor validates **before** writing: non-blank content must be preserved
exactly, no declaration name may end up declared in both files, and none may be
duplicated inside the new file. Three of those asserts fired during this stage
and each one caught a real defect rather than a formatting nit — after the first
hit, the writes were moved below all checks.

`node --check`, the global-scope gate and `dom_smoke.js` run per extraction; the
gate is what makes the unwrap safe to keep extending.

## Validation

- `dom_smoke.js` output **byte-identical to the pre-rename baseline** at every
  one of the six extractions (`SMOKE OK`, paint counts unchanged). Nothing in
  stage 1 changes behaviour, by construction and by proof.
- unwrap proof: with all leading tabs stripped and the wrapper/root lines
  removed, old and new are identical across 8,018 code lines — 0 differences.
- global-scope gate after each step: 0 duplicate top-level declarations across all 24
  loaded scripts, 0 collisions with Window built-ins, with the other scripts'
  exports, or with an element id of different meaning.
- `gravity_seed_test`, `career_departure_test`, `career_guidance_test`,
  `gravity_bench`, `route_bench`, `colony_bench`, `game_bench` all pass.
- `game_bench` against the `0.5.0` baseline: every deterministic quantity equal
  (replay 1940 / 1991 / 223 frames, route 1385 steps in 1 sliced frame,
  1944 px, purses 6.97 / 5.20 +2.20 / 11.01 +8.01 / 0.00, ulp drift to the
  digit). Wall-clock ms came out ~30% faster, which is environment variance, not
  a gain from this stage — the split moves no hot code yet.
