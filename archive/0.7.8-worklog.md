# 0.7.8 — saved maps, and one test tier per run — 2026-11-15

## review of the previous stage

The two candidate branches (`410b135` test-fast, `491aed0` analyze-testing) split
the same job between them, and neither alone was the better answer:

- **test-fast** shipped a runner (`experiments/run_fast.js`), a README and a python
  duplicate (`run_tests.py`), and *replaced* the `## tests` section of `AGENTS.md`.
  Its "fast" list mixed 25 files, including `gravity_seed_test` (a ~6 min soak),
  `career_pause_test` (78 s), `career_departure_test` (94 s) and `field_gl_test`
  (needs a real Chromium) — a ~20 min "fast" loop is not a per-edit loop. Its
  README also gave every file a cost the measurements do not support.
- **analyze-testing** wrote a good area→test table and the best prose on honest
  reporting (a deferred or timed-out run is never a pass, compare failures by
  name, isolate a fixture before rerunning a bench), but no way to run a tier and
  it also replaced the section instead of extending it.
- Both branches carried the same unrelated `gravity_game.js` edit: they *removed*
  the refusal in `planCareerSeats` (`pools[0].length < seatsWanted → null`) and
  the `pools[pool] &&` guard on a pool that is null when every in-play planet is
  sunlit. That re-opens a TypeError and turns a refusal into a loop, so it is not
  carried over. Neither branch's deletion of `findings-pitfalls-skills.md` content
  (95 and 67 lines) is carried over either.

What main has now is one section rather than two: main's `## tests` text and its
touch→run table, plus the runner line, the honest-reporting rules, and a pointer to
`experiments/README.md`, which holds the tiers, the costs, the coverage table and
the list of files that are red on a clean main. `experiments/run_fast.js` is the
single entry point, has no python twin, and keeps that red list in `KNOWN_RED` so a
file that is already broken cannot mask a new failure — it runs, it prints its
reason, and it does not sink the tier. A stale entry turns green and says so.

Measured after the merge, on the 2-core sandbox: the fast tier is 12 logic files in
79 s, all green.

## what 0.7.8 built

A career page boot is ~37 s and ~33 s of it is the fair-opening search. That search
is a pure function of `(world seed, trade seed, mask, seats, gravity/force scales,
specials)`, so a proven answer is data:

- `saved_maps.js` — the registry, a plain `<script>` file next to `index.html`
  (`root.SAVED_MAPS`, `module.exports` under node), 6 start maps in 2.7 KB.
- `saved_map.js` — `GravityMaps`: record capture, seat-plan injection into
  `GravityGame.rememberSeatPlan`, exact-state pack/unpack, `fileText`, `download`.
- `gui_maps.js` — four buttons (save map, save run, load map, load run), the
  `?map=<index|name>` boot path and the status line. Saving appends to the registry
  and downloads `saved_maps.js`; loading is a predefined file name, no picker.
- `experiments/make_saved_maps.js` — samples seeds per configuration and keeps the
  first plan the page itself would accept.

## the exact-state step took four tries

`?map=` was straightforward; "restore the exact state" was not, and the worklog
deserves the failure because it names the trap:

1. worlds only — restored, then drifted 8 clock steps on the *first* frame. The sim
   `status` was the giveaway: a career at rest sits on `STATUS_ENDED` with the trail
   of the flight it just finished, while `placeShip` → `relocate` resets it to
   parked-on-pad.
2. `status`/trail/origin/end reason restored — still drifted. The bot's
   YOU-as-bot turn state (`bot.careerPlayer`) was missing: without the plan it had
   already made it re-planned on the first frame and queued its turret shot ~400
   steps late.
3. planner restored — still drifted by one frame's worth. `playAcc` (the leftover
   step accumulator) and `playerBotSyncNeeded` are page state that decides the next
   frame, not world state.
4. all four captured — 240 frames at 8× speed, byte-identical, purse 5.37 at step
   4063 through a real flight.

The record also stores the trail only up to `trailCount` instead of the preallocated
4096 points: that alone was 99 KB of a 161 KB state, now 63 KB.

  `findings-pitfalls-skills.md` records the cause and drops it from the red list.

  `exitProbe`, so `careerNextPad` returns −1). Not fixed here; it is in `KNOWN_RED`.
