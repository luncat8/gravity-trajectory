# 0.5.5 — planet gravity cards, potential view, random startup seed

## Review of 0.5.4

The gui split held: this change touched the owning area files (`gui_draw_econ`,
`gui_draw_world`, `gui_view`, `gui_world`, `gui_tables`, `gui_hud_text`) plus the
composer's element refs/wiring/boot, without moving mutable state. The field
renderer's dirty-state cache and context-restore contract were reused rather than
duplicated for the new backdrop.

## Changes

- **Planet cards** (`gui_draw_econ.js`, `gui_tables.js`): the visit-profit pill is
  now a two-line card: profit on top, `g ±N.NN` beneath. Gravity strings are
  precomputed like profit cents so draw stays allocation-free. A claimed planet's
  border uses the EMC owner's colour (mint YOU, violet/rose rivals); neutral cards
  keep the existing profit/route palette. Port-source cards read the parent port
  strength.
- **Gravity potential view** (`gravity_field.js`, `gui_view.js`, `gui_hud_text.js`,
  `gui_draw_world.js`, `index.html`, `style.css`): third radio `potential`, `f`
  cycles space → field → potential, `?view=potential` loads it. The backdrop sums
  the simulation's softened Plummer potential `φ = -Σ μg/r`; negative wells are
  blue, positive repulsive hills green, zero is the dark space base. Heavy bodies
  (`g ≥ +2`) get a red tint/ring and a legend. WebGL shader and 1/4-res 2D LUT
  fallback share the same palette; context loss/restore and slow-frame resolution
  drop behave like the field view.
- **Random startup seed** (`gui_world.js`, `gravity_gui.js`): boot picks
  `startupSeed()` before attaching the world: replay hash seed first, then a valid
  `?seed=`, otherwise `randomSeed()`. `new seed` reuses the same helper. Explicit
  seeds and replays still reload identically; the chosen seed is written to the URL.
- **Help/README**: shared controls mention the seed rule and the three-view cycle;
  README run/controls/mechanics/files updated.
