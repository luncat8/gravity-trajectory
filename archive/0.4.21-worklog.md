## what changed

### 1. EMC turret queue (`gravity_game.js`, `gravity_gui.js`)

- `galaxy.barrel` (rest angle) is back to the seeded turret model:
  `galaxy.period[p] ∈ [2, 5] s` + `galaxy.phase[p]`, `turretPeriod` /
  `turretAngle(galaxy, p, wallSeconds)`, salt `SALT_TURRET`. The rest-angle
  record in `careerBeginFlight` and the aim-follow barrel in `drawCareerEmc`
  are gone — every barrel visibly turns on wall clock (even while the world
  clock is paused), which is what the queue aligns against.
- `launch()` in career (not replay) now queues: `queueTurretShot` measures the
  forward delta from the current barrel angle (fires at once below `0.02 rad`),
  stores body/angle/speed and a `fireAt`; the launch button shows `gun · N s`
  with a cancel title, `careerNotice` shows `EMC turning · N s to Pn`, planet
  actions hide and wait blocks. `stepGame` freezes the world for the beat
  (`playAcc = 0; tickTurret(now)`) so the shot leaves exactly as aimed, then
  `tickTurret` restores the aim, resumes the clock (`setCareerPaused(false)`)
  and fires — landing-paused and clock-running starts behave the same as a
  normal launch afterwards.
- Cancels: second click / Enter, Esc (`cancelAim`), a new drag
  (`takeOverAim`), a trim move, `startCareerRun`, `stopGame` — all funnel into
  `cancelTurret`, which clears the notice, refreshes locks and re-enables
  wait. Rivals and the bot-controlled YOU still fire straight through bots'
  own path (benches unaffected); replays skip the queue.
- `refreshGameUi` career flight lock: `activeFlying || turret.pending ||
  replay.on` (0.4.19's shape — a rival flying no longer locks your abort).

### 2. wait is no longer pinned to 2 s (`gravity_gui.js`)

- `careerWaitTick` credits each frame with at most `WAIT_FRAME_MS = 20`
  (a 50 fps budget) toward the nominal `CAREER_WAIT_MS = 2000`, instead of
  reading the raw wall deadline. Healthy 60 fps still finishes in ~2 s
  (16.7 ms < 20 ms full credit); below ~50 fps the run stretches past 2 s and
  the per-frame step chunk stays bounded at ≤ 1.5 % of the wait — slow
  machines slow down rather than entering the freeze spiral (fewer frames in
  a fixed deadline ⇒ bigger chunks ⇒ heavier frames ⇒ fewer frames). Progress
  is monotonic, so there is nothing to oscillate; settlement stays exact
  because the eased target math is unchanged.
- Guards: wait is refused while a shot is queued (`careerWait`,
  `refreshCareerWaitUi`, `careerAct`).

### 3. finished trajectories leave the view (`gravity_sim.js`)

- `finish()` now zeroes `trailCount` (and restores the stride), so the cyan
  flown path vanishes the moment a flight lands, aborts or is lost — for the
  player, user rivals and bot rivals alike (all end through `finish`). The
  prediction already cleared in the frame loop once the ship is down; with
  the trail gone the map is clean for the next aim. `flightLength` and the
  money toast are computed from movement/state, not the trail, and no bench
  reads `trailCount`.

### 4. docs

- README: launch row (queue + `gun · N s` + cancels), career row (turning
  barrel, launch waits for alignment), wait row (20 ms/frame credit),
  intro/mode-row clock wording, `gravity_game`/`gravity_gui` file notes.
- Help drawer: career detail + controls describe the 2…5 s alignment queue.
