# 0.7.48 Plan — Start Gifts: A Start-Gift Budget, Drawn Per Company (`#giftAll` / `#giftBot` / `#giftHuman`)

> **Roadmap position (Pre-FFT `0.7.*`, after fair-start modes `0.7.47`):**
> answers `drafts/new/game-options.md` (the second TODO of
> `drafts/map-fair-start-modes.md`). The start is a fixed grant
> (`OrbitTech.starterGrant`: purse 6.00, starter ship, EMC-1 / SP-1 / BAT-1);
> this plan adds an operator-tunable gift budget drawn per company at start.
> `0.7.49` (radar) is the only pool entry this plan depends on, and it is
> gated so the two land independently.

Standalone spec: a fork can rebuild this from this file alone. Source note:
`drafts/new/game-options.md`.

## decisions (settled with the player)

1. **Budget, not a gift list.** Three sliders set the money: a base gift for
   all, an additional gift for bots, and an additional gift for human players.
   Each is `0` (default) … `20 cr`, whole cr. The sum is previewed live.
2. **Every company draws.** Bots and humans each draw from their own budget
   (`bot = all + botAdd`, `human = all + humanAdd`), so a gift to the human
   also strengthens the rivals and stays balanced. A hot-seat rival typed
   *user* is a human; YOU flown by the bot (`you=bot`) is a bot.
3. **Random 1+ gifts + rest cash.** Within the budget each company draws
   `1…GIFT.maxDraws` pool entries and keeps the remainder as cash. Cash is
   never a pool entry — it is what the draws leave. A budget below the
   cheapest entry is pure cash.
4. **Science gift = a random science product** (one free invention), not a
   fitted item.
5. **Pool** = an engine kit (IMP + FT), a science product, radar. The radar
   entry grants the `0.7.49` facility and is absent until that plan lands.
6. **Determinism.** The draw comes from the company's career seed (the game
   seed for YOU, `rivalSeed(seed, i)` for rival `i`): a run replays the same
   gift, a new seed re-rolls.
7. **Career only**, settings + address + links + saved records, no new sim or
   slot, nothing in the frame loop.
8. **👀 example.** A checkbox adds a sample draw to the preview, drawn on a
   seed no company uses, so it never tells what a competitor actually got.

## problem

`resetCareer` applies one fixed `starterGrant` to every company. A fixed gift
table would be unbalanced across seeds and rosters, and a per-gift toggle
spreads the balance across many switches. A single **budget** keeps the balance
in one number the operator slides, while the pool stays a fixed, tunable table.
The gift is a company asset drawn once at start — not a per-flight effect — so
it lives in the career, not the ship.

## 1. the pool and the budget (`gravity_game.js`)

```
GIFT = { budgetMax: 20, maxDraws: 3 }
GIFT_POOL = [
  { id: 'imp1',  kind: 'part',    weight: 3, items: ['IMP-1', 'FT-1'] },   // 4.77
  { id: 'imp2',  kind: 'part',    weight: 2, items: ['IMP-2', 'FT-2'] },   // 9.00
  { id: 'imp3',  kind: 'part',    weight: 1, items: ['IMP-3', 'FT-3'] },   // 13.67
  { id: 'sci3',  kind: 'science', weight: 2, value: 3 },
  { id: 'sci6',  kind: 'science', weight: 2, value: 6 },
  { id: 'sci10', kind: 'science', weight: 1, value: 10 }
  // radar — 0.7.49 adds { id: 'radar', kind: 'radar', … } here
]
```

- A **kit's value is the sum of its parts' `buildCost`**, computed once at load
  from `OrbitTech`, so a gift never disagrees with the shop and a reprice of a
  part reprices its gift. Kits pair an engine with its tank: an engine without
  fuel capacity, or a tank without an engine, is no gift.
- A **science entry's value is its research budget**: the invention it buys
  costs at most that much at the company's start hull.
- The pool is data: a balance pass edits weights and science values here,
  not code (`balance_lab.html` may reprice later).

`setStartGifts(all, bot, human)` (clamped whole cr), `startGiftsOf()` and
`giftBudget(isBot) = all + (isBot ? bot : human)` hold the run's budgets as
module state, like the other career knobs (`setPadScale`, …).

## 2. the draw

`drawGifts(budget, seed) → { drawn: [entry…], cash }` — pure, deterministic:

- up to `GIFT.maxDraws` picks; pick `k` uses
  `OrbitWorld.hash01(seed, k, SALT_GIFT)` over the summed weights of the
  entries that still **fit**: `value ≤ remaining`, not the entry just drawn,
  and not a kit already drawn (a second copy of a part is worthless);
- no entry fits → stop; `cash = budget − Σ value` (two decimals).

The draw is a **budget spend**, not a count: 20 cr may draw one expensive kit
or several cheap entries.

## 3. applying the gifts — `grantStartGifts(career, budget)`

```
career.giftCredit = budget                     // the granted total
career.ledger.purse += budget
for each drawn entry:
  part    → ownPart(each item); buildSpent += value
  science → one free invention (below); sciSpent += value
  purse  -= value
career.giftCash = what stayed in the purse; career.giftDrawn = [text…]
```

- **Parts are owned, never fitted.** The start ship stays exactly the one the
  fair-start seats were planned and exit-checked for (a fitted engine and tank
  would add 1.5–3.9 t and could strand a deep HQ). Owned parts refit for free
  at any planet (`installPart`), so the company fits the kit when it wants.
- **Science** (`grantGiftScience`): the family is picked from the seed
  (`hash01(seed, maxDraws + k, SALT_GIFT)`, then the next family if one cannot
  be paid). Each family has a frontier segment from a known rung toward its
  next step:

  | family | from | to |
  |---|---|---|
  | catapult | EMC-2 (90, 0.71) | EMC-3 (135, 0.80) |
  | engine | IMP-3 (40, 2.5) | (56, 2.5) |
  | tank | FT-3 (160, 1.4) | (220, 1.4) |
  | battery | BAT-5 (16, 0.0003) | (22, 0.0003) |

  The point is the farthest hundredth of the segment whose
  `OrbitScience.previewHull` fee fits the value. It is researched exactly as
  `researchPoint` would, free: `acceptHull` + `research += 1` +
  `unlockPrototype` (label `R#`, owned as a prototype). Engine and tank
  prototypes therefore refit free like any owned part; catapult and battery
  prototypes are pad gear and still pay their build cost. EMC-3 itself costs
  ~28 cr of research at the start hull, so no gift unlocks a stock rung; the
  gift is a step toward it (6 cr ≈ a 100 kN EMC-2+ rail).
- The **endgame cheat** draws nothing (it starts maxed).

Money stays readable: `careerStats` gains `out.gift = career.giftCredit`, and
`purse = starter + gift + profit − property − science` holds exactly.
`giftText(career)` → `start gift 14 cr · IMP-1 + FT-1 · R1 catapult · cash 0.23`.

## 4. where it is applied

`startCareer(career, sim, seed, trade, cheat, galaxy, homePlanet, startMode,
isBot)` calls `grantStartGifts(career, giftBudget(isBot))` right after
`resetCareer`, before the start mode places the ship (a space start then adds
its own IMP-1/FT-1 fit on top; the gift never downgrades it).

- YOU: `isBot = game.player === PLAYER_BOT`.
- rivals: `GravityBot.startCareers` passes `rivalTypes[i] !== PLAYER_USER`;
  `addCareerRival` (a `+` mid-run) passes `true` and draws the run's bot budget.
- A restart is a new company: `resetCareer` clears the gift and the start
  re-draws.

## 5. the UI

### settings (experimental panel, `#giftBlock`)

```
start gifts                         [ ] 👀 example
for all    [====|-----] 0 cr        (#giftAll)
+ bots     [====|-----] 0 cr        (#giftBot)
+ humans   [====|-----] 0 cr        (#giftHuman)
bots 6 cr · humans 12 cr · from next start · e.g. bot IMP-1 + FT-1 + 1.23 cr · human …
```

- The sliders are **pending settings**: `startGame` copies them into
  `game.giftAll/giftBot/giftHuman` and `setStartGifts` (`applyStartGifts`), so
  a slider moved mid-run waits for the next start (the preview says
  `from next start`), and a mid-run rival draws the running budgets.
- `#giftPreview`: `gifts off` at zero, else both budgets; with 👀 checked a
  sample draw per budget on a seed derived from the game seed that no company
  uses.
- Disabled outside career. Default 0 = today's start, bit-for-bit.
- The player's shop block shows `giftText` above the ship refit rows.

### address, links and records

- Address: `ga=`, `gb=`, `gh=` (whole cr, omitted at 0, career only),
  read on boot and written back by `syncSeedUrl` from the pending sliders.
- Replay/career link (`encodeLink` / `decodeLink`): the same `&ga=&gb=&gh=`
  from the run's `game.gift*`; out of range, non-integer or outside career →
  the link is refused.
- Saved records (`saved_map.js` `startFields`): `gift: [all, bot, human]`
  only when non-zero, so default records are unchanged. Loading a record sets
  the sliders from it (absent = 0), like its scales; the career actions
  payload carries the same `gift` and its replay re-draws the same gifts.
- `GravityScene.startGifts()` → `{ all, bot, human, run }` (pending + running).

## 6. tests — `experiments/gift_test.js` (fast tier)

1. Pool: kit value = Σ build cost; every entry ≤ the slider ceiling.
2. Draw: deterministic; spent + cash = budget; 1+ gifts once the cheapest fits,
   pure cash below; no immediate repeat, a kit once; a new seed re-rolls.
3. Default zero budgets: purse 6.00, nothing drawn, money identity.
4. Grant over a seed × budget sweep: purse = starter + cash, identity exact.
5. Part gift: owned, ship/mass/HQ identical to the ungifted start, refit free.
6. Science gift: one research and one owned prototype per science entry,
   `sciSpent` = value, nothing fitted, ≥ 3 families over a sweep.
7. Per company: bot/human budgets, endgame draws nothing, clamping;
   `GravityBot.startCareers` gives every rival the bot budget.
8. Link round-trip and refusals.
9. Page: address → budgets → draws (YOU and rivals), labels, preview + 👀,
   shop line, address write-back, slider pending until next start, record
   `gift`, career actions replay from a gift-less page reproduces history and
   the same gifts.
10. `balance_knobs_test` keeps its pre-0.7.42 state hash: the three new career
    keys must be zero and are stripped before hashing.
11. Radar gift (with 0.7.49): a radar draw sets `career.radar`.

## scope boundary

No gift editor; the pool is a fixed, tunable table. No per-gift toggles — the
three sliders are the only controls. Radar as a gift requires `0.7.49`. No
gifts outside career. No allocation in the frame path. The gift is a
start-time company asset, not a per-flight effect. Bots do not yet plan around
owned kits (they refit when their own research logic asks); weighting gifts
for the bot is `0.8.3`'s calibration.
