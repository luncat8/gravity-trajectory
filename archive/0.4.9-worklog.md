# 0.4.9 — Fly-Time Impulse Engine, Burn Replay Codec & 0.4.8 Review Fixes

## Review of 0.4.8 (`89e306f`)

`0.4.8` wired reversible HQ ship refits (`hold`, `tank`, `engine`), HQ pad-cap
previews on every part row, and WebGL `lost` state handling. Auditing the code
turned up five real defects/gaps that were fixed before adding the impulse
engine:

1. **Engine down-refit skipped owned lighter tiers (`gravity_gui.js:partRowHtml`)**:
   `const back = engine ? null : lighterTier(career, row.table, cur)` hardcoded
   `null` for engines, so owning `IMP-1` and `IMP-2` (or starting in `endgame`
   with `IMP-3`) offered only `back no engine` instead of stepping down
   `IMP-3 → IMP-2 → IMP-1 → no engine`. Using `lighterTier(career, row.table, cur)`
   steps down through owned engines and falls back to `null` (`no engine`) at
   `IMP-1` or when no lighter engine is owned.
2. **WebGL context restoration left the GUI stuck on `'space · field lost'` and
   locked at 1/4 resolution (`gravity_field.js`, `gravity_gui.js`)**:
   `webglcontextrestored` rebuilt the shader silently without resetting
   `glDiv = 1; slowStreak = 0;` or notifying `gravity_gui.js`, while `fieldLost()`
   clobbered `viewMode` to `VIEW_SPACE`. `GravityField.create(canvas, onStateChange)`
   now resets `glDiv`/`slowStreak` on restore and invokes `onStateChange`;
   `gravity_gui.js` keeps `viewDesired` separate from active `viewMode` via
   `syncViewState()`, so `webglcontextrestored` automatically restores the
   WebGL field view (or clears the stale `'field lost'` tag in space view).
3. **Auto-helpers ignored Career's pad speed ceiling and ship origin
   (`gravity_gui.js:helperMakeBroad/Focus/Tweak`, `helperScore`)**:
   Candidate speeds were sampled up to `SPEED_MAX` (`320 px/s`) instead of
   `speedCeiling(planet)` (causing the winner to clamp to a different shot on
   selection), and `helperMakeBroad` sampled random planets even when landed.
   All three generators now snap speeds within `[SPEED_MIN, speedCeiling(planet)]`,
   `helperMakeBroad` locks onto `landedBody` in flown rules, and `helperScore`
   values Career contracts, sport offers, and pad-less landing solvency.
4. **Non-zero user slot `copyLink` omitted experimental multipliers
   (`gravity_gui.js:copyLink`)**:
   `bot.rivalLink(game.seed, scene.trade.speed, slot - 1)` now passes
   `gravityScale, forceScale` just like `copyBotLink`.
5. **Velocity unit consistency (`gravity_gui.js`)**:
   `orbit_tech.js` maps `1 m/s = 1 px/s` across the sim, pad caps, and drag
   rings; `Δv` readouts in the pad block, refit tooltips, notices, and impulse
   grip now all print `px/s`.

## Design & Implementation of 0.4.9: Fly-Time Impulse Engine

### 1. Partial-Tank Rocket Equation & Thrust Burn Cap (`orbit_tech.js`)
- Extended `impulseDeltaV(fuelKg, engine, shipMassT, tankFuelKg)` with optional
  `tankFuelKg` (defaulting to `fuelKg` so all 3-arg callers stay identical) so
  partial burns act on wet mass `shipMassT + tankFuelKg / 1000` down to
  `shipMassT + (tankFuelKg - fuelKg) / 1000`.
- Added inverse `impulseFuel(dv, engine, shipMassT, tankFuelKg)` so splitting a
  tank across sequential burns telescopes (`dv_1 + dv_2 + … === shipDeltaV`).
- Activated `engine.thrust` via `BURN_SEC = 12`:
  `burnMaxDeltaV(engine, shipMassT, tankFuelKg) = thrust * BURN_SEC / wetMassT`
  and `burnLimit(fuelKg, engine, shipMassT) = min(byFuel, byThrust)` (plus
  `refitBurnLimit` for HQ refit previews). Heavy tanks on small engines
  (`IMP-1 + FT-3`) are thrust-capped per burn (`11.6 px/s` single burn out of
  `32.7 px/s` total tank `Δv`), giving `IMP-2` (`24 kN`) and `IMP-3` (`40 kN`) a
  real mechanical role beyond `Isp` alone.

### 2. Step-Boundary Burn & Continuation Tracing (`gravity_sim.js`, `gravity_game.js`)
- `speedAt(length, ceiling, floor)` and `gripLength(speed, ceiling, floor)`
  accept an optional `floor` (`0` for burns, `SPEED_MIN` default for launches)
  so the full `GRIP_MAX` (`240 px`) drag ring maps linearly onto `0 … burnLimit()`.
- `GravitySim` adds `burnLimit()`, `canBurn(dv)`, `burn(angle, dv)` at the
  fixed-step boundary, and unified `traceFromCargo` backing `predictFlight`,
  `predictBurn(angle, dv, budgetMs)`, and zero-alloc external
  `predictBurnFast(sourceSim, angle, dv)` (copying `sourceSim.stepX/stepY` so
  moving-port stride alignment matches `stepOne()` bit-for-bit, and capping
  horizon at remaining `stepLimit - liveSteps`).
- `GravityGame` tracks `ship.fuelKg`, `career.burns`, and `career.lastFuel`;
  refuels `ship.fuelKg` to `tank.fuelCap` on built pads (start, HQ refit, launch,
  built-pad landing, fresh catapult build, evacuation) while retaining partial
  fuel when stranded; and settles mid-flight burns via `careerBurn(career, sim, angle, dv)`.
- Extended shot replay codec (`encodeShot` / `decodeShot` / `decodeLink`) with
  optional `-b<step36>.<angle36>.<dv36>` burn suffixes on the same integer
  `ANGLE_STEPS` / `SPEED_STEPS` grid, rejecting out-of-order steps, steps
  `>= abort` / `capSteps`, zero `dv`, and burns on `route` planner links.

### 3. Headless Career Burn Planner (`gravity_bot.js`)
- Factored shared landing/harvest/contract/solvency valuation into
  `careerScoreFlight` (zero duplication with `careerScoreProbe`, accounting for
  already-flown distance on sport tasks).
- Added synchronous zero-alloc `careerBurnPlan(career, sim, market, runStep)`:
  evaluates coasting first (`predictBurnFast(sim, 0, 0)`), enforces **"burn only
  when it still lands the contract"** whenever a delivery contract is active,
  rescues missed contracts and off-map `END_EXIT` trajectories, and deducts fuel
  opportunity cost so minor gains never waste the tank. All 7 standard and
  scaled `career_bot_bench` runs remain bit-identical to `0.4.7`/`0.4.8`.

### 4. In-Flight Pause, Ship Drag, Trim & Replay (`gravity_gui.js`)
- During a Career flight with an engine and fuel (`canImpulse()`), pressing
  `Space` / `P`, clicking `#launch` (`impulse · max … px/s`), or clicking/dragging
  directly from the flying ship pauses the flight cleanly at the integer
  `liveSteps` boundary (`playAcc = 0`).
- Dragging from the ship draws an ice-cyan `GRIP_MAX` ring and vector, previews
  the post-burn continuation trajectory (`predictBurn`) with live system-visit
  rings, green planet-profit pills, `aimReadout` (`Δv … px/s · …° · −… kg`),
  and `±` trim (`burn Δv`).
- `Enter` or `#launch` (`burn · Δv …`) executes `careerBurn`, appends the step
  burn to `game.shots[last].burns`, updates `#careerPad` (`fuel …/… kg · Δv … px/s`)
  and flight-end toast (`fuel −… kg`), and resumes flight immediately; `Escape`
  disarms an uncommitted burn first and unpauses on a second press.
- `applyReplayBurns()` fires recorded step burns inside `advanceGameOneStep()`
  before `stepOne()`, keeping watched (`×0.25…×16`) and skipped replays bit-exact.
