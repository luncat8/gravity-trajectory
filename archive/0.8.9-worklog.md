# 0.8.9 worklog — cheat panel under the flight HUD

The panel (draft §4.5 cheats, previously seed-url only): a `[+10cr]` button and
two checkboxes — communism (all free) and test mode (install all stock
upgrades) — docked directly under the flight HUD at the right edge.

## decisions

- **Communism = all free, not unlimited money.** The free-price approach was
  already in the core: every wrapper (`price`, `careerCost`, gear tiers,
  research, fuel, fees) reads `career.cheat` at call time, the shop prints
  `free`, and the bots reason about 0-cost builds. An unlimited purse would
  need a parallel display path for every price and would break the ledger
  identity and the insolvency checks. Toggling the box just flips the flag —
  "for gameplay it looks the same" for free.
- **Test mode = the endgame cheat applied to a live career.** Reuses
  `fitEndgame` (top rail/panel/battery on every buildable planet, every stock
  part owned, ship fitted top) instead of a second fit routine. A career
  record holds one cheat value, so communism wins the slot and the test fit
  re-applies itself on top whenever its box is checked — the endgame flag
  alone would also stop the paved career from completing, which is what a
  test run wants.
- **The panel is the session's cheat intent.** Restarts pass `game.cheat`
  (kept equal to the boxes), `cheatPanelAdopt` folds a run's own cheat (seed
  url, saved map, replay link) into the boxes without ever clearing one, and
  `cheatPanelApply` re-asserts the intent after every career start — a
  single-slot reset cannot carry both boxes, the overlay heals that.
- **Cheats are recorded actions.** A mid-run cheat would silently desync the
  compact replay, so the panel records `cheat` and `credit` entries;
  `applyCareerAction` replays them through the same panel path (boxes
  included). Full saves already snapshot `career.cheat`, purse and pads.
- **`+10cr` mutates the shared ledger only** (`game.money`, which is YOU's
  `career.ledger`): no `earned`/stats accounting, cheat money is not income.

  published on `GravityGame`.

  checkboxes, `cheatPanelCheat`/`Apply`/`Adopt`/`SyncUi`, recording toggles.
- `index.html`: the `#cheatPanel` strip after `#flightHud`, the script tag
  after `gui_career_replay.js` (alphabetical, before its runtime callers run).

  stops above it via `--cheatReserve`, which `reserveGameFooter` measures
  (`gui_view.js`), so the strip sits under the HUD and never over the footer;
  hidden below 820 px where the footer spans the full width.
- `gui_hud_game.js`: `cheatPanelSyncUi(career)` in `refreshGameUi` — career
  boxes lock outside a career and during replays, the credit button locks only
  for replays (it works in lab/money/tour).
- `gui_game.js`: adopt + apply at the end of `finishCareerStart`, before the
  recording's first snapshot, so the recorded start state carries the panel.
- `gui_career_replay.js`: `applyCareerCheat`/`applyCareerCredit` + dispatcher
  cases.
- `drafts/science-and-ship.md` §4.5 `→` line gained the panel.
