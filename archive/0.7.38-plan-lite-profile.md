# 0.7.38 Plan — Lite Profile (Fast Boot, Still Backdrop, Quiet Page)

> **Roadmap position (Pre-FFT `0.7.*` · First):** zero physics or balance drift;
> speeds up page boot, automated page runs and laptop battery play for every plan
> that follows.

Source notes: `drafts/new/lite-version.md`.

---

## Goal

A first-class **lite profile** — `?lite=1`, or the persistent `lite` checkbox in
the canvas view bar — for slow devices, laptops on battery and test sessions:

1. A career whose seed nobody pinned starts on a saved opening from
   `saved_maps.js` (no seat search, ~0.2 s instead of ~3 s), and every page boot
   runs the trade world's seven-hour pre-history once.
2. The trade backdrop canvas `#c` (`orbit_view.js`) holds one still frame over
   static planets instead of painting the trade traffic, moons and pulses at
   60 Hz.
3. Web Audio and the postcard deck stay off without overwriting the stored sound
   preferences.

Lite is a **viewer profile**: it never changes `PlanetGravity`, `GravitySim`,
`GravityGame`, `OrbitEcon`, the career clock's `tradeSim` stepping, `GravityBot`
budgets, or `CareerActions` / `CareerReplay` state. A lite run and a full run of
the same seed are the same run, frame for frame.

---

## Design

### 1. State and controls (`gui_lite.js`, `index.html`)

One area file owns the profile: `liteMode`, the address override `liteParam`, the
`#liteMode` checkbox, the saved-opening lookups and `applyLite()`. It loads after
`gui_maps.js` (it reads `savedMapList`) and before the composer, which reads
`liteMode` when it creates the sound controller.

- `?lite=1` / `?lite=0` set the profile for the tab and stay in the address
  (`syncSeedUrl` writes `liteParam` back as found); without the param the stored
  `localStorage['gravity.lite']` decides.
- Only the checkbox writes `gravity.lite`. Using it drops the address override,
  so the address stops forcing a profile the player just changed. A stored
  profile is never written into the address: a copied link does not make the
  receiver lite. Game/replay hashes are untouched — lite is not a rule
  parameter.
- `applyLite()` (boot and checkbox): checkbox state, still backdrop, sound gate,
  postcard gate, `new seed` tooltip.
- `GravityScene.liteMode()` exposes the state to tests.

### 2. Saved-opening career starts (`gui_lite.js`, `gui_world.js`, `gui_game.js`)

A record fits a run when `kind === 'start'`, `universe` and `seats.length` match,
it has no designed `gravity` field, and its `gs` / `fs` equal the page scales.
Career seats are `1 + GravityBot.LEVELS[level].careerCount` unless the
scoreboard pins `game.playerCount`: `off` = 1, `easy` = 2, `normal` and `hard`
= 3.

- **Arming:** `startCareerRun` calls `liteArmOpening(seed)` just before
  `GravityMaps.applySeats`. In lite, with no record or designed field already
  armed, it arms the fitting record of that seed; `applySeats` still checks the
  world, mask, field tag and scales before it replaces the search. A pinned seed
  with a saved opening is therefore seated from it too — the same run, minus the
  search.
- **Unpinned seeds:** `startupSeed()` returns, in lite and without `#game=`,
  `?map=` or `?seed=`, a random saved seed for the roster the address asks for
  (`universe=`, `players=`, `bot=`, else 13 worlds and the page's level); a
  roster without records falls back to `randomSeed()`. The boot's seed is the
  lab's seed too, so switching the lab to career later is still a saved start.
- **`new seed`:** in a lite career it cycles the saved seeds of the roster
  (next one above the current seed, wrapping); `Shift+click`, another rule or a
  roster without records rolls `randomSeed()` through the live planner.
- **Registry:** `experiments/make_saved_maps.js` carries 2-seat 13-world records
  (seeds 3, 6, 7, 8) so `easy` boots fast. A 1-seat search costs ~0.3 s, so
  `off` needs no record (and `saved_map_test` keeps requiring ≥ 2 seats).

### 3. One pre-history per boot (`orbit_view.js`, `gravity_gui.js`)

`orbit_view.js` used to fast-forward its placeholder world (seed 7) on load, the
boot reset to the boot seed fast-forwarded again, and a run started from the
address reset and fast-forwarded a third time.

- `orbit_view.js` builds the placeholder world without stepping it.
- `OrbitScene.reset(seed, deferHistory)`: with `deferHistory` the world is
  rebuilt but the `START_MINUTES` (420) fast-forward waits for
  `OrbitScene.settle()`, which runs a pending one and returns whether it did.
- Boot: `scene.reset(startupSeed(), true)`, then the link / address / last-mode
  load; a run started there resets fully, and a boot that started none calls
  `if (scene.settle()) attachWorld()` so the lab sees the advanced world.
- The deferred history runs under the boot universe mask, like every other
  reset (hidden seed ports retire before the fast-forward).
- `OrbitScene.fastForwards()` counts fast-forwards for tests.

### 4. Still backdrop (`orbit_view.js`, `gui_view.js`)

`syncStillBackdrop()` sets `OrbitScene.setStill(liteMode && mode === MODE_PLANETS)`
from `applyLite()` and `applyMode()`. Moving ports are gravity bodies in
`MODE_PORTS`, so that mode always paints live.

While still, `orbit_view.js`'s frame:

- never calls `sim.step`: in the idle lab the background trade world is
  decoration over static planets; under the game clock the page's own
  `advanceCareerWorld()` keeps stepping `tradeSim` exactly as before — the
  backdrop never owned that clock;
- skips moons, port/ship positions and hover;
- paints `paintStill()` (sky or field frame, orbit ellipses without trails,
  planets) only when stale: `stillDirty` (set by `resize`/`setFrame`,
  `resetWorld`/`settle`, `setPlanetMask`, a `setBackdrop` change, `setStill`, the
  orbits checkbox) or a planet whose `planetState` / `planetPort` differs from
  the painted copy (a colony founded or lost recolours it; 96 typed-array
  compares per frame, no allocation);
- keeps the 10 Hz trade HUD text.

`beginPaint()` (clear, sky, world transform, field frame) is shared by the live
`draw()` and `paintStill()`; `OrbitScene.paints()` counts paints for tests.

### 5. Sound and postcards (`gui_lite.js`, `gui_frame.js`, `photo_deck.js`)

- Sound: the controller is created with `enabled: soundEnabled && !liteMode` and
  `applyLite()` keeps `sound.setEnabled(soundEnabled && !liteMode)`. Every
  backend's `unlock()` returns before `ensureContext()` while disabled, so
  gestures never create an `AudioContext` and no gesture handler needs a lite
  branch. `soundEnabled` (the stored choice) is never written by lite, so
  unchecking restores it. The `sound` button reads `sound off` and is disabled
  with a tooltip while lite holds it.
- Postcards: `PhotoDeck.setEnabled(on)`; while off, `show`, `showCareer` and
  `toast` return before touching the card or `photoImg.src` (no art request),
  and turning it off dismisses an open card. Toasts only repeat money the ledger
  already settled, so nothing is lost.

## Verification

`experiments/lite_mode_test.js` (slow tier: it boots pages):

1. `?lite=1&mode=career` boots on a saved seed, seated from its record, with one
   fast-forward and no `AudioContext` after key and pointer gestures (a full page
   asks for one: positive control); `bot=easy` boots on a 2-seat record;
   `new seed` moves to the next saved seed and seats from it.
2. `?map=0&you=bot`, `?map=0&you=bot&lite=1` and the lite seed link of record 0
   capture the same `GravityMaps.captureState` at boot and after 600 frames
   (~4 800 career steps), while the lite page paints its backdrop once.
3. A lite lab paints once and not again over 60 frames, does not advance the
   idle trade world, repaints once on a view switch and on resize, and paints
   live at once with moving ports or with lite off.
4. `?lite=1` writes no stored key; the checkbox stores `gravity.lite`, drops
   `lite=` from the address and restores the stored sound choice; a stored
   profile boots lite; `?lite=0` overrides it and stays in the address.
5. Postcards and toasts stay closed in lite and open without it.

Also: `saved_map_test`, `make_saved_maps.js --check` (new records),
`dom_smoke` (index.html and the boot changed).
