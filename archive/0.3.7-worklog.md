# 0.3.7 Worklog — Per-Player Bot Controls, Active User Switch & Route `use best` Visibility

## Review of 0.3.5 / 0.3.6

Reviewing commits `4f328e0`, `19cc176`, and `b972dbb` (`archive/0.3.5-worklog.md`, `archive/0.3.6-worklog.md`) together with real headless-Chromium rendering uncovered two groups of defects:

1. **Scoreboard player controls (`index.html`, `style.css`, `gravity_bot.js`, `gravity_gui.js`)**:
   - Only row 0 (`YOU`) had a `bot` checkbox (`#playerBot`); `R1` and `R2` were static display rows that could never be switched between `user` and `bot`.
   - `#scorePlayer` was a `<label>` wrapping `#playerBot`, so clicking anywhere on the row toggled the `bot` checkbox instead of selecting a `user` player to control.
   - `GravityBot` assumed `rivals[0..1]` were always bots, so there was no way to hand `R1` or `R2` to a human user or switch active control between multiple human players.

2. **`route` mode `use best` recovery & HUD visibility (`gravity_gui.js`, `style.css`, `index.html`)**:
   - **Zero-step drag starvation**: `startAimTrace()` called `routeBegin()` without running an initial `routeStep()`, while `onPointerMove` set `dirty = true` on every pointer move (even sub-grid `Shift` fine moves where snapped `(angleU, speedU)` did not change) and `onPointerUp` set `dirty = true` unconditionally. During a continuous drag at 60 Hz, `routeBegin()` kept resetting `predCount = 1` before `else if (routeActive) routeStep()` could ever execute, so `routeBest` stayed empty (`disabled`, `opacity: 0.35`) until the pointer stopped completely.
   - **Viewport & footer clipping**: `#cargoHud` used `max-height: calc(100vh - var(--footReserve, 76px))` without subtracting `#cargoHud`'s own `top` offset (`14px` / `8px`), without `100dvh` / `visualViewport` / `ResizeObserver` updates when `#tradeControls` wrapped, and without `flex: none` on `.panelHead`. On shorter viewports or embedded frames, `#cargoFoot` (`#clear` + `#routeBest`) dropped into `#tradeControls` or below the viewport.
   - **Help drawer & dead-control clutter**: `setRule()` called `showRuleHelp(next, false)` on every `change`, leaving `#helpDrawer` (`z-index: 6`) open; on viewports `<= 640px`, `.drawer` (`bottom: 64px`) covered `#cargoFoot` directly. Meanwhile Lab-only controls (`#bodyGroup` in game mode; `#horizonGroup`, `#playbackGroup`, `#flightRow` in `route` mode) consumed ~177 px inside `#cargoHud`, and `#routeBest` wore `.miniBtn` (`opacity: 0.35` when idle) with near-zero contrast on `#060d19`.

## Implementation

- **Unified scoreboard rows & multi-user switching (`index.html`, `style.css`, `gravity_bot.js`, `gravity_gui.js`)**:
  - Replaced `<label id="scorePlayer">` and static rival rows with uniform `div.scoreEntry` rows (`#scorePlayer`, `#scoreRival1`, `#scoreRival2`), each containing a dedicated `<label class="scoreBot"><input type="checkbox"><span>bot</span></label>` (`#playerBot`, `#rivalBot1`, `#rivalBot2`).
  - Added `rivalTypes[0..1]` and `isRivalBot(i)` in `GravityBot` so user-controlled rivals skip bot search/auto-launch while still participating in shared-market lockstep physics, route leader comparison, and score summaries.
  - Added multi-slot state in `gravity_gui.js` (`slotTypes[0..2]`, `activeSlot`, preallocated `slotPlans[0..2]`, `slotBest[0..2]`, `slotAim[0..2]` with zero per-frame allocations).
  - Clicking (or pressing `Enter`/`Space` on) any `user` row calls `selectUserSlot(slot)` to switch active manual control (`▸` active indicator and highlighted border), preserving each human player's armed aim, route plan, and saved `routeBest`. Clicking the `bot` checkbox stops propagation and toggles `user` ↔ `bot` for that player row.
  - Added `clockDriverFlying()` in `gravity_gui.js` so human flights drive the shared game clock in `tour`/`money` while bots step in exact `DT` lockstep (and auto-run immediately when zero active human users remain).

- **Immediate mid-drag `routeBest` capture & high-visibility footer (`gravity_gui.js`, `style.css`, `index.html`)**:
  - `startAimTrace()` now runs `sim.routeStep(ROUTE_STEP_MS)` immediately after `sim.routeBegin(...)` during interactive aiming (`0.4–1.0 ms` typical trace time), `onPointerMove` only sets `dirty = true` when snapped `(aimAngle, aimSpeed)` actually changes, and `onPointerUp` preserves completed/in-flight traces instead of resetting them.
  - `reserveTradeFooter()` computes exact `--hudMaxH` from `visualViewport` / `innerHeight`, `#cargoHud` top offset, and `#tradeControls` top (observed via `ResizeObserver` + `visualViewport` resize).
  - Hid inactive controls (`#bodyGroup` in game mode; `#horizonGroup`, `#playbackGroup`, `#flightRow` in `route` mode), switched `setRule()` to `updateRuleHelp(next)` so changing rules does not pop `#helpDrawer` over the HUD, top-mounted `.drawer` on `<= 460px` screens, and styled `#cargoFoot.routeMode` + `#routeBest` (`.bestReady`, `.on` gold highlight whenever `best.length > current + 0.5` or after `clear plan`).
