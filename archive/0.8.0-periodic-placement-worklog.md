# Periodic map placement correction

## Review

The shipped 16×12 lattice has only ±1 px jitter. Bit-reversed row-major
indices also put the first 64 planets in just six columns. The old tests
explicitly required this layout, so they could not detect the visual defect.
The FFT field solver is not the cause.

## Changes

- Replace lattice placement with deterministic best-candidate sampling:
  select the roomiest of 96 random positions per planet, using minimum-image
  distances on both axes. Work is bounded; no dense-map rejection loop.
- Every roster prefix is distributed over the torus, not selected columns.
  Classic generation, FFT physics, roster capacities and orbit sizes stay intact.
- Replace lattice-specific assertions with a 102-seed distribution sweep for
  4/16/26/64/104/192 planets: density-relative spacing, broad axis coverage and
  no dominant nearest-neighbour row/column alignment. Keep repeatability checks.
- Fix the GUI seam-flight fixture to leave room for the initial surface spawn;
  otherwise a planet extremely near the edge wraps during launch, before the
  flight-crossing detector starts.

The old uniform 81 px gap is deliberately not retained: irregular progressive
packing at capacity has smaller gaps. The 100-seed measurement found minimum
spacing ≥0.627×sqrt(area/count) for 4/64/104/192 prefixes (~57 px at capacity),
while the regression sweep requires ≥0.6 for all six tested prefix sizes.
This is still safely larger than two planet radii (maximum 22 px combined).
Periodic seeds now generate different geometry and orbit draws, so old periodic
seed-based replays are not compatible. Classic seeds/replays are unchanged.
