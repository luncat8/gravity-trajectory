# 0.7.9 — the page stub was the slow part, and page tests boot saved maps — 2026-11-16

## review of the previous stage

0.7.8 was reviewed by reading its code, plan and worklog; its tests were not
rerun as a verdict on it. The base commit `a2319c4` was run once, in a scratch
export, only as the timing and output reference for the changes below.

**The ~33 s was not the seat search.** 0.7.8 measured a career boot at ~37 s in
`node`, put ~33 s of it on the fair-opening search and proposed `?map=` as the
way around it. The search is ~3 s. The rest was `experiments/dom_stub.js`:
`vm.createContext(sandbox)` *contextifies* the sandbox, so node wraps the realm's
global object around it and every global name the page reads (`Math`,
`Float64Array`, each top-level function of the classic scripts) is answered
through that wrapper, which the optimiser cannot cache. One tight loop of
builtins: 1.1 s in the main realm, 26 s in a contextified one, 1.3 s with
`vm.createContext(vm.constants.DONT_CONTEXTIFY)`. `findings-pitfalls-skills.md`
had this under dead ends ("V8 treats functions compiled inside a context as
second-class", "no flag speeds the vm up"); that no compiler flag moved it was
the clue that the compiler was not the cause.

So the next step 0.7.8 proposed would have gone around the cause again:
`dom_smoke` (41 page loads), `gravity_seed_test`, `game_bench` and every seed
boot that must stay a seed boot would still have paid ten times.

**A `?map=` boot was not the run its seed link starts.** Comparing the captured
run state, the page scalars, the random stream and every element of the two
pages found three differences, each of which would have changed what a converted
test tests:

- the page drew a random startup seed before the map loaded (`startupSeed` knew
  `?seed=` and the replay hash only), which moved every later `Math.random` draw
  — helper scans, roster spawns;
- the record stored `targetPay` rounded, while a company that joins mid-run is
  seated by its ratio to the unrounded number the search leaves in the galaxy;
- `rate=` was ignored, so a map could only run the record's orbit clock, and a
  seed link without `rate=` runs the career default (0.5), not the record's 1.

Smaller, fixed on the way:

- `saved_map_test.js` wrote the tracked `saved_maps.js` back on every run: a
  test that rewrites its fixture tidies a hand-edited registry instead of
  failing on it. Its proof of "no search" was two wall-clock caps, and the
  comparison with the planner was an opt-in (`PLANNED=1`).
- the same test raised both pages to orbit rate 8 after boot
  (`OrbitScene.setSpeed(8)`) as "playback ×8 [that] keeps the frames (and the
  test) short". It is the orbit rate — the sky and its moving gravity sources —
  set behind a career whose rate the link locks: the run it saved started at
  rate 1 and flew at 8, which no player can do, and the bot comes to rest after
  the same 530 frames without it. The test now flies the record's own run.
- `captureState` built the 48 mask bits by hand next to `maskBits`; the comment
  on `pick` described another function.
- `saved_map_test` and `dom_smoke` printed the registry's character count as
  bytes (2669 for a file of 2683).
- `run_fast.js` had no timeout, so a hang and a long run looked the same, and a
  failure printed an exit code and nothing else.
- docs: `player_growth_test` was listed red as "had not finished after 10
  minutes" (it passes at the base commit, in 8); `bot_bench` carried "1 known
  failure" with no name on record (it prints
  `BOT BENCH OK` at the base commit); `README.md` did not mention saved maps;
  `gui_maps.js` was missing from the gui table in `AGENTS.md`; the implemented
  plan was still in the root and told its own history (`PLANNED=1`, "the first
  restore attempt").

Seen and left (not this stage's subject):

- `?map=` pins the roster size and the universe to the record
  (`game.playerCount`, `game.planetUniverse`; a seed link leaves both to the
  level and the rule) and ignores `bot`, `cheat`, `src` and `rule` in the
  address. A default-shaped record could follow the level like its seed link
  does; that changes what `load map` means after a level switch, so it is the
  human's call.
- `bot_gravity_test` is in `KNOWN_RED` but in no tier, so the runner never runs it.
- `experiments/logs/0.7.8-maps.txt` lists seeds the committed registry never
  had; `0.7.9-maps.txt` is the generator's output for the current one.
- `AGENTS.md` still says "do not run `dom_smoke.js` per step". Only its numbers
  were updated (~20 min → ~2 min); the rule itself is the human's.

## the plan, improved

0.7.8's next step: convert the career page tests that are not about the seat
search to `?map=<n>`, with `player_growth_test` first, by "a saved map or a
smaller loop".

1. Fix the cause first. One change in the stub makes every page load ten times
   cheaper, converted or not.
2. Make a map boot provably its seed link's run *before* any test moves onto it,
   and keep that as a permanent assertion — otherwise the conversion silently
   swaps the fixture under 12 files.
3. Address a map by its seed, not by a hand-picked index: `mapSearch(42)` in the
   stub finds the career-default record of seed 42 or throws with the remedy.
   Records are generated, never hand-written, and appended so `?map=<index>`
   stays stable.
4. A record can outlive the search that proved it, and then every test on it
   passes on a run no seed link starts. `make_saved_maps.js --check` re-plans
   every record and closes the slow tier.
5. `player_growth_test` needed neither a saved map nor a smaller loop. Its
   8 minutes were the stub; it keeps its whole loop (no assertion weakened) and
   runs in ~45 s.

## steps

1. **stub** — `experiments/dom_stub.js`: the page globals are assigned onto
   `vm.createContext(vm.constants.DONT_CONTEXTIFY)` (node ≥ 22.8 or 20.18; an
   older node falls back to a contextified object, the old speed).
2. **`?map=` is its seed link** — `gui_world.js` `startupSeed` returns the
   record's seed; `saved_map.js` stores `targetPay` unrounded and reuses
   `maskBits`; `gui_maps.js` splits `savedMapParam` (which record) from
   `loadSavedMapParam` (start it) and reads `rate=` (0.5–12) next to `you=`;
   `gui_share.js` hands over the parsed params.
3. **registry** — `experiments/make_saved_maps.js`: a config may name its seeds
   (`seeds: [42, 7, 3, 520383]`, the worlds the page tests are written against),
   `--check`, and a short run no longer writes a file with shifted indices.
   `saved_maps.js` regenerated: 10 records, 4.3 KB; the first six keep their seed
   and seats and gain the unrounded pay. Seeds 10 and 61 have no fair opening and
   are refused: the registry is also the pool `load map` draws from.
4. **`saved_map_test.js`** — reads the registry, never writes it (asserts the
   committed file is exactly the text a save writes). The two time caps
   (`ms < 10000` for the injected plan, `bootMs < 15000` for `?map=0`) are gone:
   a searched boot now takes 3 s, so neither could tell a seated run from a
   searched one. In their place: a record with its seat order reversed must seat
   the run reversed, and the `?map=0` run must equal its seed-link run in captured
   state at boot, after a flown flight, and in the next `Math.random()`.
   `PLANNED=1` is gone too: that equality is always on, and `--check` covers all
   ten records. `&rate=0.5` on a map boot must set the orbit rate and change
   nothing else in the captured state: the form ten of the converted boots use.
5. **conversion** — 17 boots in 12 files now read `mapSearch(seed)`, plus
   `&rate=0.5` where the seed link carried no `rate=`. Kept on seed links: the
   seat search or the address as subject (`career_start_seat_test`,
   `gravity_seed_test`), seeds with no fair opening (`player_growth_test` seed
   10, `gravity_view_test` seed 61), and `bot=off` pages, which no default record
   matches. `multiplayer_career_test` got one assertion tightened: the notice
   line must *change* after the scan, because a map boot leaves `loaded …` there
   and "not empty" would have passed without a scan.
6. **runner** — `experiments/run_fast.js`: entries may carry script arguments;
   a file is stopped at ten times its listed cost (never under a minute) and
   reported as `TIME`; a red file, known or not, prints why (its `FAIL` lines,
   else its error message and where); costs re-measured; `bot_bench` left
   `KNOWN_RED`.
7. **docs** — `experiments/README.md` (tiers, `mapSearch`, red list),
   `AGENTS.md` (numbers, the seat-search row, the `gui_maps.js` row),
   `README.md` (saved maps, `?map=`), `findings-pitfalls-skills.md` (the vm
   pitfall replaces the wrong dead end; `setSpeed` is the orbit rate, not
   playback), `archive/0.7.8-plan-saved-maps.md` (moved from the root, brought
   to the final spec), `experiments/logs/0.7.9-*`.

## next step

Make the opening search cheap when it finds nothing fair. A career on seed 10
or 61 takes 13–15 s to boot, against 3 s on a seed with a fair opening, and the
stub no longer explains any of it: a browser runs the same search (not measured
in one). 2 of the 10 seeds planned here for the default career are such seeds.
The first question is where the extra ten seconds go — `career_start_probe.js`
asks the planner directly — and the fairness law stays as it is. The same search
is what `player_growth_test` now spends its time on.

Before or beside it, the small one: decide the two red assertions in
`gravity_view_test` (is the seed-61 raster or the expectation wrong; `+0.46` or
`+0.47`). It is the last red file in the slow tier, and a tier that is green is
one where every red line is news.
