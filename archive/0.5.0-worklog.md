# 0.5.0 worklog — index the cargo GUI in place

Stage 0 of `0.5-plan-gui-split.md`: make the monolith navigable before moving
anything. No code moved, no behaviour change, the file still runs as one IIFE.

## Review of the previous state

`gravity_gui.js` at 8,419 lines / 315,670 chars ≈ 88k tokens, wrapped in a
single IIFE with 386 functions, 348 `const` and 106 `let` all at indent level 1,
and no section comments of any kind — `grep '^\t//'` matched nothing, so the only
navigation aid was reading the file. `README.md` describes it as one entry.
`balance_lab.html` (added alongside the plan) loads only `orbit_science.js` and
`orbit_tech.js`, so it is unaffected by the split.

## What landed

- 32 banner comments, one per area, each naming the area, the file it is slated
  to move into, and what it holds:
  `/* ── area · gui_file.js ── contents */`
  so `grep -n "── " gravity_gui.js` returns the table of contents with fresh line
  numbers, in place of a stale list of ranges that rots on the next edit.
- two lines at the top of the file header pointing at that grep, so an agent who
  opens the file cold learns the navigation rule instead of scrolling.
- `AGENTS.md` → `### gravity gui`: the grep rule, the area → file routing table,
  and the two invariants (state and element refs stay with the area that owns
  them; `root.GravityScene` keys are a test contract).

## How the boundaries were derived

Areas come from the ordered list of level-1 declarations, not from eyeballing.
Each area is anchored on its **first declaration's symbol name** and the 32
anchors were asserted to partition all 840 declarations, in order, exactly once —
which is what makes the future move mechanical instead of a judgement call.

Two corrections found while doing that, both now written into the plan:

- the ranges first drafted for the plan are declaration anchors, not cut points:
  only 3 of 21 fell between declarations, the rest landed inside a function body
  (1998 is inside `showBlocked`, 6000 inside a `return`). Cutting on the numbers
  would have produced ~18 half-functions. The plan now carries the outward-walk
  rule and a `node --check` gate per file, verified against a deliberately naive
  slice.
- an area is not always contiguous: 32 blocks for 21 files — twelve files own one
  block, seven own two, and `gui_aim.js` and `gui_predict.js` own three, because
  aim input and prediction readouts are physically interleaved with the route,
  helper and HUD-clock code. The plan's first draft forbade a third range; the
  measurement showed the third blocks are substantial (4.4k–11.2k chars), so
  cutting them off would mean misfiling a whole block to obey a line count. The
  plan now allows three where the code genuinely interleaves and keeps four or
  more forbidden.

## Findings worth keeping

- the id-shadowing audit is the one pre-flight the flat-global mechanism needs:
  20 of the 840 top-level names equal an `id` in `index.html`; 13 are
  `const foldBtn = $('foldBtn')` and stay harmless, **7 mean something else and
  must be renamed** — `gravity`@248, `gameSpeed`@636, `soundVolume`@405,
  `soundAim`@427, `launch`@1778, `careerWait`@5908, `helperStop`@2450. All 7
  colliding ids are `<input>`/`<select>`/`<button>`, i.e. exactly what a bare
  `launch.click()` would want. `index.html` has no inline `on*=` handlers, so
  nothing depends on the implicit globals today.
- verified in a vm before committing to the mechanism: top-level `let`/`const` of
  one classic script are visible to the next in the same context and share object
  identity; a duplicate `const` across files is a `SyntaxError` at load (a wrong
  boundary fails loudly); top-level `let`/`const` do not become `window`
  properties. 0 name collisions with the 7 globals the other scripts export.
- `experiments/dom_stub.js` scrapes the script list from `index.html`, so adding
  files costs nothing in the harness — the reason the split can be staged one file
  at a time.
- a `grep -E` with `\t` or `\s` matches nothing (POSIX ERE has no such escapes);
  it silently passed a "0 collisions" claim until re-run with a literal tab and
  in python. Any check written this way must use `$'\t'` or a real parser.
