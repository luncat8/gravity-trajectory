## 1. H: the entry point becomes a call with a contract

The human's note asked for something the merge had left as a compromise: *"i
imagine it as — Helper call player if found problem, if call ignored or problem
solved ico disappears"*, `>>entry point at the moment of the problem`. The merge
had answered with the flight panel's state tag and the rule that H never speaks
first, which is silence, not a call.

**§4.11 added to `concept-helper-dialog-merged.md`** — the entry point as three
states (quiet / called / dismissed) and four mechanical rules:

- **what counts as a problem** — a closed `launchReason` gate behind an armed
  shot from this planet, plus the one case that blocks every shot (condition
  `0`, `WORN_OUT_BLOCK`). Both inputs already exist (`launchReason` from §4.4,
  `armed`/`aimBody` in `gui_aim.js`); nothing is authored for the trigger.
- **never nags** — one call per `gate id + planet + numbers` per visit; a
  dismissal is remembered for the visit and cleared with the transcript; no call
  during a settle, a replay or an open card, and not twice in a second.
- **the icon disappears by itself** — the call renders the current gate, so it
  is not a record: `launchReason` returning `null` quiets it in the same tick.
- **cost** — one string compare on the HUD tick; the badge and the dismissal map
  live in `commsState`; "H changes no state" still holds.

## 2. gallery.py: paint the list, do not rebuild it

Reviewed against the human's two complaints. The blink was one cause with four
symptoms: `rebuild_cards()` destroyed and recreated every card from the worker's
one-second `rescan`, from every delete and undo, and from every checkbox click —
so the list redrew while nothing about the card set had changed.

- **the set split from a member.** `rebuild_cards()` now owns only the visible
  set (filter, prompt file, view mode, column count). `sync_cards()` walks the
  cards that exist and calls `card.set_images(files, pending)`, which diffs the
  tuple: one new render adds one thumbnail and rewrites two labels. A rescan
  event, a download, a delete and an undo all take that path, so the scroll
  offset, the hover and the keyboard focus survive.
- **a checkbox toggle no longer touches the widget.** `configure()` on a Tk
  checkbutton regenerates its indicator, which is the click and the focus
  thrown away for a colour change. The state now lives in the variable, the
  indicator colour is constant, "off" is a separate chip, and a toggle is
  `variable.set` + `state=` on the queue button — plus the one-file write it
  always needed.
- **files are indexed by prompt, in one directory pass.** `images_for(key)` used
  to glob and `stat` the whole output dir per card, per repaint. One scan now
  groups every render by its prompt (bare target first, variations oldest to
  newest, ties by name so the order never flips between two worker ticks) and a
  sidebar line counts the renders no prompt claims. The naming lives in
  `launch.py` (`split_name`, `seed_of`) next to the writer.

### the viewer, as the note asked

| key | does |
|---|---|
| ← / → | previous / next variation of this prompt (wraps) |
| ↑ / ↓ | newest image of the previous / next prompt **in the list**, and the list selection follows |
| `+` `-`, wheel | zoom 25–400 %, drag the picture to pan |
| `Del`, `Esc` | delete to `.trash` / close |

The viewer is reused when another thumbnail is clicked, so it keeps its place
instead of opening a second window; every viewer binding returns `"break"` so
the `bind_all` list keys (↑ ↓) do not move the list behind the windows.

### scroll, wheel and drag

`bind_all` on `<Button-4/5>` and `<MouseWheel>`, gated by one containment walk
from the widget under the pointer: the prompt list and the sidebar scroll under
the pointer, while the batch log's `Text` and the viewer keep their own wheel.
Right/middle drag pans the list from anywhere over the cards (a left click on a
thumbnail still opens the viewer); left drag on the empty canvas pans too.
PgUp/PgDn and `G` (grid view of every image) are the keyboard side of the same.

Small fixes taken while in there, each one line of reasoning:

- a disabled card's caption was `FAINT` on `CARD_OFF` (~2.9:1, unreadable);
  `DIM` on the same background is 5:1. The "off" chip carries the state.
- `Run batch` asks nothing now: it opens its own window with the `launch.py`
  log and a stop button, and a non-zero exit points at that log.
- the batch log buffers a drain tick into one insert and only auto-scrolls when
  the reader was already at the tail.
- the log scan skips files younger than two seconds (it already did in the
  worker; the UI path now shares it).
- the scrollregion follows the canvas width too, and a reflow happens only when
  the thumbnail column count changes, never per pixel of resize.

## validation

no X display), so the GUI itself was **not** exercised:

- `python3 -B -m unittest discover -s photos/generator` — 12 tests, OK, including
  a new `test_gallery_filenames_map_to_their_prompt` (bare target, seeded name,
  every bundled workflow, `_2` suffix, non-workflow suffix, `seed_of`).
- `python3 -m pyflakes photos/generator/gallery.py launch.py` — clean.
- the real saving and download naming (`launch.py`) re-checked against all 168
  names this project can produce: 168/168 map back to their prompt.
- a fake-Tk harness (no `tkinter` in the image) drove the app logic end to end
  on the real `gravity.json` project and a scratch output dir: boot 19 cards
  from 3 renders; **toggle → 0 rebuilds, 0 syncs**; a new render → 1 sync, 4
  thumbnails; a rescan event → 1 sync, 1 orphan; wheel over the list scrolls
  and over the batch log returns `None`; grid mode paints cells; filter narrows
  and restores 19 cards; the viewer walks variations and prompts, and delete +
  undo repaint without a rebuild.

This harness only proves the logic. The layout, the widget options and the
pixel result need one real launch on a desktop with Tk — a deferred check, not
a pass.
