# 0.4.8 — ship refit rows & reversible refits, field context-loss fix

## Review of 0.4.7

- **The `webglcontextlost` fallback could never work**: a canvas keeps the first
	context type it was given, so `canvas.getContext('2d')` on a canvas that once
	had `webgl` returns `null` for the life of the element. The handler assigned
	that `null` and the field simply froze; `gravity_bench`'s mock canvas returned
	a 2D stub for *any* kind, so the dead path passed headless. Replaced with a
	real `lost` backend: draw nothing until `webglcontextrestored` rebuilds the
	program/buffer, and the page returns to the starfield (`space · field lost`)
	with `f` retrying after the restore.
- **`installPart` could throw** on a `null` hold/tank (`item.capacity`). Only the
	engine has a "nothing" tier, so it is now the only slot that accepts `null`.
- **The starter fit was not owned**: `resetCareer` cleared `career.owned`, so the
	shop offered to *buy* `HOLD-0`/`FT-0` for the parts already fitted. The starter
	hold and tank are owned from reset. The endgame cheat fitted parts it did not
	own either, which left its heavy ship with no cheaper tier to go back to — it
	now owns every ship part, so the endgame ship can be flown light as well.
- The 0.4.7 panel row and the `wait · 30 min` settlement agree with the execute
	path (same `batteryLeak + solarCharge` per-pad formula, same step count); the
	rate-scaled `ready in N s` is deliberate: one wait is 30 world minutes at any
	rate, so the seconds shrink as the clock speeds up. No change.

## Changes

- **`orbit_tech.js`**: `partMass(item)` (holds/tanks `emptyMass`, engines `mass`,
	`null` = 0), `refitMass(ship, kind, item, cargoTons)` (substitute one slot,
	keep cargo and the other parts; `shipMass` is now its null-kind case), and
	`refitDeltaV` / `shipDeltaV` — the Δv the tank's full fuel buys with an engine
	at the refitted mass.
- **`gravity_game.js`**: starter fit owned on reset (`ownPart`), endgame owns
	every ship part, `installPart` rejects a `null` hold/tank.
- **`gravity_gui.js`**:
	- Ship-part rows lead with the stat (hold `8 t`, tank `40 kg`, engine `12 kN`)
		and the **HQ pad cap** the offered fit costs (`8 → 24 t · 88 → 78 px/s`),
		computed from `refitMass` + `padCapMass` — the same `OrbitTech.speedLimit`
		the launch gate uses, so a heavy hold reads as a launch limit before it is
		bought.
	- A free `back <id>` button returns to the heaviest **owned** tier below the
		fitted one, and `back no engine` (`data-tier="-1"`, `NO_TIER`) strips the
		engine. The row's arrow describes the upgrade when one is on offer and the
		step down when maxed; tooltips state the stat, the ship mass, the HQ cap
		and the fit's `Δv`.
	- The pad plaque's ship line and every refit notice state the whole fit's
		`Δv` (only once an engine and a fuel tank are both fitted).
- **`gravity_field.js`**: context loss is a real state (`backend() → 'lost'`,
	`render` no-ops), `webglcontextrestored` re-inits WebGL; `findings` updated
	with the one-context-type rule.
- **Tests**: `career_bench.js` refit check (starter ownership, `refitMass`
	identities, buy-once / free-back, cargo floor, engine strip, `Δv` from tank ×
	engine, endgame ownership); `dom_smoke.js` clicks the rendered rows
	(`shopButtons`/`shopTier` helpers), checks the hold cap text, the free back
	refit and its mass drop, the engine strip button, the pad `Δv` line and the
	cargo-blocked disabled state; `gravity_bench.js` models the real canvas
	(`getContext('2d') → null` after WebGL) and checks lost → restored, plus a
	no-WebGL canvas that keeps the 1/4-resolution 2D raster.
- `README.md` shop/view rows and `findings-pitfalls-skills.md` (§numbers that
	decide a purchase, §WebGL backdrop) document the new rows and rules.
