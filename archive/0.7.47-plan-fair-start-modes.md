# 0.7.47 Plan — Fair-Start Modes: Composition Rule, 75 % Exit Margin, Background Search, Space & Capital Starts

> **Roadmap position (Pre-FFT `0.7.*`, after the `+5` law):** answers
> `drafts/map-fair-start-modes.md`. `0.7.46-plan-fair-start-fallback.md` asked
> whether an unfair start is acceptable when the player is told — this plan
> says yes, and builds the whole answer: a composition rule that knows when a
> roster cannot be fair at all, a visible warning, a seat search that never
> freezes the page, and two symmetric starts (space, capital) that trade HQ
> seating for a shared spawn. `0.7.46` is superseded; its options 1 (say so,
> let the player choose) and 3 (symmetric start) land here, options 2, 4 and 5
> stay open.

The draft is the design source; where its wording left a choice open, the
decision and its reason are recorded below. Implementation order = the
workstream order.

## decisions (settled with the player)

1. **Scope:** the whole draft, planned here, implemented in workstream order.
2. **Minimal case = 2 × players + 4 distinct planets** — players HQs, players
   light landings, 2 specials (Capital, A.R.F.), 2 heavies, all separate.
   Rosters below the line (8/3…8/6, 13/5, 13/6 on the test matrix) leave the
   strict roster contract; they are still generated and printed, never
   asserted fair.
3. **Exit margin = 75 % of EMC power.** An exit counts only when the ship
   leaves with a quarter of the rail's power in hand, over more bearings —
   fairness must not depend on one lucky full-power trajectory.
4. **Search:** run synchronously up to 2 s; if the plan is not accepted by
   then, continue in the background with H's live report. The search proceeds
   in deterministic tiers; the page never blocks again.
5. **Space-start bots get full parity:** they plan the from-rest burn with the
   same trajectory tools a human uses.
6. **Evacuation, universal rule:** a career with no HQ (`hq < 0`) is towed to
   the Capital.

## shared vocabulary

- **light planet** — EMC-1 + BAT-1 can leave it at ≤ 75 % of that kit's cap
  (WS1 probe), 16 bearings, `CAP_SECONDS` horizon.
- **heavy ≥ EMC2** — EMC-1 cannot leave it, EMC-2 + BAT-1 can (at ≤ 75 %).
- **heavy > EMC2** — EMC-2 cannot, EMC-3 + BAT-1 can.
- **heavies** (share/density) — planets the starter rail cannot leave at all.
- All three class probes run on the drawn field (mask applied, specials at
  g 1.00), memoised per field stamp.

## WS1 — the exit-probe law: 75 % margin, two tiers, 16 bearings

The probe is one law with three mirrors: the game opening (`gravity_game.js`),
the bot (`gravity_bot.js`, `careerExitSpeed`) and the experiment probes. The
game's comment already says "mirror the bot's probe"; all three move together.

**Probe shape** (replaces 4 fractions × 8 bearings):

- bearings `8 → 16` (`OPENING_EXIT_ANGLES`, `CAREER_EXIT_ANGLES`,
  `career_start_probe.js`'s `EXIT_ANGLES`);
- speed tiers `[0.75, 1]` of the kit's cap (`OPENING_EXIT_FRACTIONS`,
  `CAREER_EXIT_SPEED_FRACTIONS`): test 0.75 first, test the cap only when
  0.75 fails — a high-G planet therefore ends up probed at max only, which is
  the draft's "for high G use only max";
- returns the escaping tier: `0 | 0.75 | 1` (fraction of the passed cap).

**Two semantics, split on purpose:**

- **strict (margin)** — used wherever a rail would be *created* or a first
  landing *accepted*: `exitOk` of a seat, `openingSiteLight` / the
  buildable-target gate, `res.starterCanExit` (the bot's "may I build a
  starter here"). Only tier ≤ 0.75 counts. This replaces
  `OPENING_BUILD_GRAVITY_MAX = 1.5` as the authority: the constant is
  deleted, the probe decides (the draft's "limited by actual EMC-1/bat-1 with
  some margin").
- **capability** — used wherever an *existing* rail must be left or a heavy
  classified: kit pricing in `careerDeparture` (`currentSpeed > 0`), the
  composition heavies, the §2 blocked-share probe. Either tier counts; a
  full-power exit is still a physical exit.

**Knock-ons to re-measure (never silently re-pin):**

- the §2 blocked share (2–4 per 10) is measured with the bot probe — if the
  band moves, report the numbers before touching the band;
- `career_departure_test`'s g 3.15 fixture barely exits at full cap today —
  under the margin it is no longer a starter exit, the fixture moves to a
  planet that passes 75 %;
- `make_saved_maps.js --check` will likely go red (seats move with
  `exitOk`) → regenerate `saved_maps.js` and re-pin the tests whose literals
  quote seats, gravity labels or bot hashes (`balance_knobs_test`'s bot-run
  hash, `saved_map_test`, `two_leg_test` if its legs shift);
- benches re-run for numbers: `bot_bench`, `career_bench`,
  `career_gravity_bench`, `career_bot_bench`, `game_bench`.

**Contract:** `career_start_fairness` default run still prints the drawn
blocked share; `career_start_seat_test` still passes; the oracle inside the
fairness script follows the defaults (its hard-coded `8, 4` fan arguments go
to the shared defaults so the law lives in one place).

## WS2 — the composition rule

New pure function in `gravity_game.js`:

```
startComposition(world, mask, count, players, sourceSim, startMode) → {
  ok, minimal, light, heavyEmc2, heavyEmc3, heavies, additional,
  missing: [ids…]     // 'planets' | 'light' | 'specials' | 'emc2' | 'emc3'
}
```

- **planet start:** `minimal = 2 × players + 4` (decision 2); needs
  `count ≥ minimal`, `light ≥ players`, both specials present, both heavies
  present. With `specialPlanets` off the specials term drops
  (`minimal = 2 × players + 2`).
- **space / capital start (weakened, no access test):** `light ≥ players`,
  both specials, both heavies — no HQ term, no 2 × players + 4.
- **the draft's "2–4 heavies per 10 additional planets"** — `additional =
  count − minimal` when positive. The band is a *density diagnostic*, not an
  acceptance gate: which planets belong to the "minimal" set is not defined
  per planet, and an upper bound would reject richer fields that are perfectly
  seat-able (the light count is gated separately). It is printed in the
  helper report and in the fairness script's per-cell line, the same role as
  §2's share law.

**Test contract (`career_start_fairness.js ASSERT=1`):**

- cells with `count < 2 × seats + 4` are skipped by the roster contract
  (still run, still printed, marked `compos`);
- per seed, strict fairness is asserted only when that seed's drawn field
  passes `startComposition` for the roster; a composition-failed seed prints
  `compos` instead of `FAIL`;
- 13/5, 13/6 and 8/3…8/6 leave the contract this way; 13/4 (12 ≤ 13) and
  20/6 (16 ≤ 20) stay — their leftover seeds are WS4's measure.

## WS3 — the unfair-roster warning (visual + H)

Shown when `startComposition(...).ok === false` for the live roster:

- **highlight:** a `rosterUnfair` class on `#playerCountRow` and
  `#planetRow` (amber/red border and text, `style.css`) while the condition
  holds; the counters themselves stay editable — the fix is one click away.
- **H call:** a new call reason `fair-roster` in `gui_comms.js` (same
  mechanism as `return-tow`), copy in `comms_copy.js` as a topic: "N planets
  cannot seat M companies fairly · decrease players or increase planets",
  with actions `fair-less-players` / `fair-more-planets` wired to
  `setPlayerCount(-1)` and the planet input (+1, restarts the search).
  One call per roster (keyed like the other findings, dismissible).
- the call is raised in the planning state (WS4), so the counters the draft
  wants highlighted are on screen; saved-map boots skip it (their roster is
  fixed by the record).

## WS4 — the background seat search

### driver

The walk becomes resumable without changing its order or its results:

```
GravityGame.createSeatSearch(world, trade, mask, count, seats, sourceSim)
  → { step(budgetMs) → { done, accepted, tier, best, progress },
      advanceTier() → bool, tier, bestHomes(), bestStats() }
```

- phases: build sets (fast) → rank (chunked per pair for the pair proxy, per
  planet for the cold table) → exact batches (the existing batch loop, atomic
  per set) → repair (fast) → compare walks → done;
- `planCareerSeats` stays as the synchronous T0 wrapper
  (`create + step(Infinity)`), so `prepareCareerStarts`, `make_saved_maps`
  and every node test keep today's exact behaviour — chunk boundaries never
  skip or reorder work, only pause it;
- **tiers are deterministic work budgets**, so the same seed and roster always
  produce the same HQs:
  - **T0** = today's laws bit-for-bit (floor walk where it runs, wide walk
    2400 / 8000 traces, miss 48);
  - **T1** = wide walk with a larger trace budget, sized by measurement to
    reach the oracle's fair sets on 20/6 seeds 5 and 10 and 13/4 seed 1
    (target: ≤ ~30 s of background work);
  - **T2** = full pool, generous budget — the last "wait more".
  Exact numbers are tuned against those three seeds and recorded in the
  worklog.

### page flow

- `startCareerRun` runs the driver synchronously for up to **2 s**
  (`performance.now()` budget inside `step`). Accepted → finish the start
  exactly as today (no visible change on the happy path).
- Not accepted by 2 s → **planning state**: `game.on` is already true, the
  frame loop keeps running, the driver gets ~6–10 ms per frame, and H raises
  `fair-search` — a live report: tier, best weakest-share so far, and which
  criterion is still unmet (`distinct` / `exit-safe` / `≥ 55 %`). The
  roster highlight from WS3 is on.
- **tier ends unaccepted** → the `fair-search` card grows the decision:
  - *play as-is* — start with **the tier that was complete when the card
    offered it** (deterministic: mid-tier progress is display-only);
  - *load fair saves* — inline dropdown of saved maps that pass
    `planFieldOpening` (the existing fair filter in `gui_maps.js`), picking
    one loads it through `startMapRecord`;
  - *wait more* — `advanceTier()`; the live report keeps updating in the
    background until the player decides (the draft's "upd results until
    player decision");
  - when a tier **accepts** while the card is open, the card offers *start
    fair* with that tier's plan — acceptance is work-deterministic, so no
    race between the button and the search.
- determinism rule: **only completed tiers can become a plan.** Wall-clock
  decides when dialogs appear, never which sets were seen.

### guards during planning

`careerPlanning` (state owned by `gui_game.js`) gates: launch/aim input,
`setPlayerCount` ±, the planet input, `setBot`, mode switches, restart/new
seed (all cancel and restart the search with the new parameters — the draft's
"increase planets / decrease companies" loop), `syncSeedUrl`. `?map=` and
lite boots never enter planning (seats come from the record).

### tests

- `dom_stub.loadPage` drains planning: after boot, `runFrames` until the
  planning flag clears (bounded), so every existing page test keeps waiting
  on a planned start the way it does today;
- new page test `fair_start_gui_test.js`: planning → accepted → started;
  roster change restarts the search; the highlight and the H card render;
  play-as-is / wait more / load-saves paths;
- node callers (`career_start_fairness`, `make_saved_maps`, benches) never
  see the driver — they keep `prepareCareerStarts`.

## WS5 — space start and capital start

### selecting a start

- `game.startMode = 'planet' | 'space' | 'capital'`, default `planet`;
- a radio row under the play-mode radios in `index.html` (visible pre-game,
  tagged career-only, hidden for other rules), URL param `start=`, written
  back by `syncSeedUrl`, carried in run records and replays;
- H also offers the two alternatives from the `fair-roster` card (they are
  the draft's answer for a roster below the minimal line);
- saved-map loads force `planet` (a record owns its seats).

### grants and placement (`gravity_game.js`)

| | space | capital |
|---|---|---|
| HQ | none (`hq = -1`, no `fitPad`) | none (`hq = -1`, no own pad) |
| start position | in flight, at rest, clustered near the world centre, deterministic small offset per company (seed + index) | landed on the Capital |
| ship | starter fit + `ENGINES[0]` (IMP-1) + `SPACE_START_FUEL_KG` | starter fit, no engine |
| purse | `grant.purse + 15` (= 21.00) | `grant.purse + 10` (= 16.00) |
| rail | none until a planet is landed on | the free imperial rail (`padAt` already returns `CAPITAL_PAD`) |

- `resetCareer` takes `homePlanet = -1` as "no HQ" (it already prefers an
  explicit value over `pickHq`), skips `fitPad` and `at = hq`;
- the space flight opens like any career flight: `openFlight(…, 0)`,
  `stepLimit = RULES.career.capSteps`, `career.flying = true`, `at = -1`;
  ending it unlanded is the normal lost-in-space state → tow (below);
- `pinCareerStrengths` already skips `planet < 0`, so only the specials get
  pinned — no seat search runs for these starts (weakened composition gate
  only, WS2);
- `placeShip` learns the Capital exception already used by `careerEndFlight`:
  standing on the Capital never counts as stranded.

### the universal no-HQ evacuation rule (decision 6)

`evacTarget(career) = career.hq >= 0 ? career.hq : career.capitalPlanet`,
used by `canEvacuate` (false when already at the target), `evacuate` and
`advanceEvacuation`. A tow from space with no HQ therefore rides to the
Capital; a company standing on the Capital cannot order a pointless tow.

### bots

- **space, full parity (decision 5):** at the first career step a company
  flying with `hq < 0` runs a space opening: fan the granted kit from the
  spawn state (same `predictFast` machinery), score reachable landings the
  bot already scores mid-flight, pick the best deterministically, then hand
  the flight to the existing mid-flight burn policy. After landing the normal
  career logic runs — `canBuildStarter` (now strict, WS1) keeps it off
  marginal rails.
- **audit every `career.hq` consumer** in `gravity_bot.js` and
  `gravity_game.js` for `hq = -1`: research gate falls back to the Capital,
  traces print `start · space` / `start · Capital`, `hqMask` already skips
  `-1`, `returnLandingVisit` never matches.
- live roster changes in these modes: `setPlayerCount(+)` adds the company at
  the same spawn/Capital with the bonus purse — no `planCareerExpansion`, no
  planet enable (there is no HQ to site); a planet-count change still
  restarts the run.

### tests

- `career_space_start_test.js` (headless): spawn state, grants, purses,
  capital rail launch, tow-to-capital, weakened composition pass/fail, bot
  lands from rest and builds its first pad, capital-start bot plays;
- `fair_start_gui_test.js` gains the selector, `start=` URL round-trip and
  record capture;
- `launch_reason_test` / `comms_topics_test` / `comms_facts_test` for the new
  topic and actions.
