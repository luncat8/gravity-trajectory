# 0.4.18 worklog — career predicted-route pickup note and post-pickup EMC-1 cap

## what changed in 0.4.18

### 1. Predicted-route delivery pickup note (`gravity_gui.js`)

- Added `careerPickupNote(career, planet)`: when aiming in career mode at the pickup planet of an accepted delivery contract (`planet === task.from && task.state === TASK_ACCEPTED`, cargo not yet loaded), appends a `loads <N> t → <to>` note to the aim/predicted-route readout.
- The note also previews the post-pickup pad speed cap of a starter `EMC-1` on the pickup world, computed with the post-pickup ship mass (`ship.mass + task.tons`):
  - padless pickup planet → fresh `EMC-1` + `BAT-1` at full charge (what building a starter would give);
  - `EMC-1` already built → the pad's live cap with the loaded ship;
  - any other catapult → the `EMC-1` starter reference.
- This lets the player see before launching whether a starter `EMC-1` on the pickup world will lift the newly loaded ship.
- Wired into `refreshAimLabel()` so the note updates live while aiming (`#aimReadout`).

### 2. Tests (`experiments/career_bench.js`)

- `post-pickup EMC-1 cap: cargo mass lowers the starter-rail cap`: verifies post-pickup mass = dry + cargo tons and that the `EMC-1`/`BAT-1` cap drops under cargo (dry 91.65 px/s vs loaded 68.31 px/s).

### 3. Docs (`README.md`)

- Documented the `loads <N> t → <to>` pickup note and `EMC-1` post-pickup cap preview in the release-drag / predicted-trajectory row.
