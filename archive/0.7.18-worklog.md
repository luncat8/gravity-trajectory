## 1. "only down" was one truth test in `_up`

`_up(event)` opened with `if getattr(event, "num", None)` and only then read
`delta`. tkinter's `Event._substitute` writes `e.num = getint_event('%b')`, and
`%b` is the string `'??'` for everything that is not a button press - including
`<MouseWheel>`. `'??'` is truthy, `'??' == 4` is false, so every Windows/macOS
wheel event took the `else` branch of `wheel()` and scrolled **down**. X11 was
unaffected because it sends real Button-4/5 events, which is why the bug read as
"only down" rather than "dead".

`wheel_notches(event)` replaces it: -1/+1 by button number, otherwise the sign of
`delta`, with a notch count (`|delta| // 120`, clamped to 3) so a hi-res wheel or
a multi-notch delta moves proportionally. The viewer's zoom binding went through
the same helper.

Other scroll problems found in the same pass:

| symptom | cause | now |
|---|---|---|
| a right/middle drag only panned from the frame background, never from a card | the bindings sat on the canvas and the cards frame, and Tk does not bubble events to the parent | the drag bindings are `bind_all`, gated by the same containment walk the wheel uses |
| a left drag on a short list moved the view by a fraction of a list that does not scroll | `_drag_*` never asked whether there was anything to scroll | `ScrollArea.can_scroll()` gates the pan, and the cursor is still reset on release |
| a wheel notch moved 1/10 of the *window height* per unit, so the step doubled on a maximised window | a canvas scroll unit is a fraction of the viewport | `step()` moves `SCROLL_STEP = 20` px per unit, `WHEEL_UNITS = 3` per notch: one notch is 60 px at any size, and the drag still pans unsnapped |
| the wheel over the scrollbar or the hint strip did nothing | the containment walk stopped at the canvas | `ScrollArea.owns()` walks to the area frame, so every child counts, and the hint strip below the pane is routed to it explicitly |
| `PgUp`/`PgDn` was `yview_scroll(4, "units")` | arbitrary | one canvas "page" |

## 2. the card did not fill the pane

The card width was `canvas width - 8` set on the canvas window, then a card
packed with `padx=10` either side into it, next to a 15 px scrollbar: the right
edge carried `8 + 10` px of dead space on top of the scrollbar, asymmetrically.
The magic `- 8` is gone (`ScrollArea` forces the body to exactly the viewport
width), the card takes `LIST_PAD = 10` on both sides, and every inset that shapes
the thumbnails is a named constant again (`THUMB_GAP`, `LIST_PAD`, `CARD_PADX`
replaced `CARD_PAD = 30`).

The row of thumbnails was the second half of "wasted space right": `columns()`
fits whole 180 px columns, and the 40-60 px a card could not use ended up in one
gap at the right edge. Those columns are now `columnconfigure(weight=1)`, so the
leftover is split between them and the row spans the card. The grid view does the
same for its whole viewport, and takes the weight back from columns a wider
layout left behind (an empty weighted column still eats space).

A resize now also re-wraps the captions when the column count does *not* change:
a Tk label clips instead of re-wrapping, so before this a slightly narrower
window cut long captions. `_reflow()` rebuilds only on a column-count change and
otherwise calls `card.set_wrap()`, which compares before it configures.

## 3. the status bar owns ComfyUI

The sidebar carried a `ComfyUI` box (URL, queue depth, downloads) while the
status bar carried the server state - the same server twice. The box is gone;
the status bar's right side is now, in pack order:

| chip | text | notes |
|---|---|---|
| queue | `queue 1 running · 2 pending` | `queue -` until the first ping |
| downloads | `downloading 1` | empty when nothing is in flight |
| server | `● online  ·  127.0.0.1:8188` | `unchecked`/`offline` in `FAINT`/`BAD`; click opens Settings |

`update_server_label(ok=None)` is the single writer (boot, settings save, every
ping), and `update_pending_label()` runs on the ping, on a queued job and on a
finished download, so the count does not lag a guest 5 s behind.
