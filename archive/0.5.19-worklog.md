# 0.5.19 worklog — make the paused ship an obvious impulse handle

## Request

With an IMP engine and fuel aboard, pause a flight, drag from the flying ship to
set an impulse, release to arm it, then press Enter to burn and resume. Resuming
without Enter cancels the arm. The ship must not start this interaction while the
flight is moving.

## Changes

- Increased the paused ship's pointer target to 26 screen pixels so the small
  in-flight marker is easier to grab.
- Fixed the input gate: before the normal canvas/HUD target filter, paused-flight
  ship hits are now tested directly (while still excluding buttons and other
  controls). A drawing/overlay layer can no longer swallow the ship pointerdown.
- Expanded the paused ship's pulsing ring to mark the actual hit target. The ring
  only appears when the flight is paused; a moving ship remains non-interactive
  as an impulse handle.
- Extended the DOM smoke helper to start the drag 22 screen pixels off center,
  proving the larger visible target still resolves to the intended Δv.
- Existing handling already provides the rest of the requested sequence: Enter
  executes the armed burn and clears the paused state; resume clears the arm.

## Validation

- `node experiments/dom_smoke.js` passed the flight pause / ship drag / arm /
  Escape / resume-cancels / Enter-burn checks (the 0.4.9 verification line,
  including a 22 px off-center pointerdown targeted at the drawing layer rather
  than the field canvas). The full script later stops at the unrelated
  `padless destination must use its affordable commercial departure` assertion.
- `git diff --check` passed.
