## What changed

1. **`bot_career_shop.js` — crash fix (real bug found in review).** The
   colony-kit shop's rail-upgrade fallback called `GravityGame.techUnlocked`,
   which exists nowhere in the repo (only that one call site): whenever the
   starter pad could not reach any exitable empty world, the branch threw a
   TypeError instead of degrading. Replaced with `GravityGame.gearKnown`, the
   same gate `careerDeparture`/`buildGear` use for "is this rail buildable".
2. **`experiments/dom_smoke.js` — the three plan-caused `CHECKFAIL`s.**
   - Rule tags now expect the 16-world career default:
     `career · 1 / 16 pads` and `career · 12 / 16 pads · endgame`
     (tag text comes from `gui_shop.js`: `padCount + ' / ' + planetCount`;
     `padCount === 12` = 16 − 3 empty − Capital was already asserted).
   - The build-env first landing now filters with
     `pads[body].catapult === null && planetBuildable(bCareer, body)`:
     an empty world has no pad block to build the first EMC on, and a rival's
     claim hides the first-catapult button; the shortest *unfiltered* shot
     picked R1's HQ. Probe at seed 7: filtered landing exists (unclaimed
     settled world), stranded + build flow unchanged after it.
3. **Coverage added to fast-tier tests** (plan §6 items that had no assertion):
   - `found_colony_test.js` — a stranded kitless landing pins
     `careerOverText() === 'stranded · found the colony'`; `colonyInPlay`
     flips false → true across the founding; 60 board redraws before the
     founding never name an empty world (§6.1); 300 redraws after it name
     the founded world (task regeneration, §1).
   - `gift_test.js` — `GIFT_POOL` contains no `COLONY-KIT` (not as an entry,
     not inside a part gift): the kit is an endgame purchase (§5/§6.6).
   - `career_space_start_test.js` — fixture moved to the real default:
     `START_COUNT = 16`, `deriveEmptyWorlds` + `setEmptyMask` before the
     settle (as the page does), `startComposition` called with the market's
     empty/heavy masks like the live callers. New asserts: three empties in
     play, none is the Capital or A.R.F., the capital start and the
     seat-search HQ are not on an empty world, composition counts
     `empty === 3` / `settled === 13`, and the bot's space landing is not on
     an empty world (§5, §6.6). 43 checks per seed.
   - `career_actions_test.js` — replayed colony block: `&cheat=communism`
     funds HOLD-24 + kit on a fresh purse, a deterministic seek finds an
     empty world inside the loaded pad cap (seed 1: reachable at full cap,
     ~26 s flight), the shot flies and lands stranded, `foundColony` is the
     next act, and `verify` re-applies purchase + launch + founding with
     `skipped === 0` and matching history (§6.6 "replayed actions").
4. **Bookkeeping** — plan moved to `archive/`, draft status flipped to

- **Stranded stays true after founding** — `foundColony` does not clear the
  flag; every reader (`careerOverText`, `padLift`, bot recovery) re-checks
  lift capability, and the post-founding text correctly reads `''` once the
  commercial EMC-1 lifts the dry ship (77 px/s at seed 1). The tests pin the
  observable text, not the flag.
- **`dom_smoke` remains KNOWN_RED, now at its documented named failure.**
  With the three plan fixes the file runs to `0.4.17: no landing with a
  commercial exit from HQ`. That failure is not ours: it was named on base
  `68905ee` (2026-11-24, two days before the colonization commit), and a
  standalone probe of the accept logic fails identically at base and on this
  tree — on seed 42 every settled planet reachable from the HQ at the test
  speed prices its exit as `build`, none as `commercial`. Logged, not fixed
  in passing; a candidate for a dedicated `dom_smoke` pass.
- **`career_guidance_test`, `bot_gravity_test` stay exempt** with their
  named failures (confirmed unchanged by this stage's slow run).
- **`career_bot_bench`'s exemption was removed** — its
  `padless solvency gate counts this flight's launch fee` note (reproduced at
  `68905ee`, 2026-11-24) is stale: the bench is green at base `6134d4f`
  (677 s) as well as on this tree (680 s), so it is not this stage's doing.
  The `gearKnown` fix above stands on its own as a probe-confirmed latent
  crash (`typeof GravityGame.techUnlocked === 'undefined'`), not on the bench.
