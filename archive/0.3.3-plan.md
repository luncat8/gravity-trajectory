# 0.3.3 — bot competitor: shared-market deterministic rivals

Standalone spec. Rivals fly the same seeded world under the same `DT = 1 / 120 s`
integrator and compete with the player in real game-clock lockstep for the same
growing per-planet fly-visit profits (`0.3.2`). Because every rival decision is a
pure function of `(seed, rule, botLevel, runStep, market)`, rival flights never
need to be encoded in the shot list — only `&bot=easy|normal|hard` (omitted when
`off`) is added to the link.

## 1. race model: live shared-market lockstep

Rivals compete in a **live shared-market race** rather than an isolated ghost:

- Game time advances only during fixed physics steps (`game.clockSteps += 1`).
  While the player is aiming between flights, the world clock and rival ships are
  paused (and `bot.tickIdle` pre-computes any ready rival's next shot in bounded
  slices).
- On each integer `runStep` of flight, player and rivals step together (`stepOne`)
  and harvest from the **same** `game.market` (`lastVisitStep[0..25]`, player
  resolved before `R1`, `R1` before `R2` on same-step ties).
- Rivals always launch from static planet bases (`SRC_PLANETS`), starting at
  deterministic distinct homeworlds (`base0 = (seed * 7 + 5) % 26`, spaced by
  `+13 mod 26`). After landing, a rival stages for `stageSteps` before its next
  launch.
- **End-of-run settlement (`bot.settle`)**:
  - In `tour` / `route`, if the player hits `26 / 26` first, the race ends
    immediately on that finish line.
  - If the player stalls out broke (`purse < 1.00`) before meeting the rule's
    goal, OR finishes the 10th shot in `rule=money`, remaining active rivals
    settle their remaining launches synchronously (bounded by `maxShots` /
    `MAX_BOT_SHOTS = 16` on static `SRC_PLANETS`, without advancing `tradeSim.t`)
    so the final WIN / LOSS / TIE comparison reflects completed runs across every
    replay cadence.

## 2. difficulty ladder and candidate search

| level | rivals | grid (`angles × speeds`) | horizon (`tour` / `route`) | stage gap | lookahead |
| --- | --- | --- | --- | --- | --- |
| `off` | 0 | — | — | — | none |
| `easy` | 1 (`R1`) | `24 × 4` = 96 | `18 s` / `28 s` | `3.5 s` (420 steps) | 0-ply |
| `normal` (UI default) | 1 (`R1`) | `36 × 5` = 180 | `42 s` / `75 s` | `1.5 s` (180 steps) | 0-ply |
| `hard` | 2 (`R1`, `R2`) | `48 × 6` = 288 | `65 s` / `110 s` | `0.5 s` (60 steps) | top-4 × `24 × 3` 1-ply (discount `0.55`) |

- Every candidate angle/speed is snapped onto `GravityGame.angleUnits` /
  `speedUnits` before calling `probe.predictFast(origin, angle, speed, horizon)`
  (which skips path-buffer writes). Ties break deterministically on
  `(angleUnits, speedUnits)`.
- Candidate scoring (`scoreProbe`) combines `GravityGame.estimateProfit(market,
  runStep, probe)` with `predNewVisits`, landing bonus (`+12`), solvency guard
  (`-400` if `purse - 1 + profit < 1` unless completing the 26th system), same-pad
  penalty (`-35`), and non-landing cap penalty (`-250` unless completing), tuned
  per rule (`money` weights `30 · profit`, `route` weights `18 · newVisits +
  0.015 · predLength + 10 · profit`, `tour` weights `11 · newVisits + 18 · profit`).
- On `hard`, the top 4 landed candidates simulate harvesting into preallocated
  `lookMarket` + `probe.visited` and evaluate a 1-ply follow-up (`24 × 3 = 72`
  shots) from the predicted landing planet at `runStep + predSteps`.

## 3. sliced execution & measured performance

Measured in Node (`experiments/bot_bench.js`, `experiments/logs/0.3.3-bench.txt`):

- **Full synchronous decision (`chooseSync`)**: `easy` **6.08 ms**, `normal`
  **15.53 ms**, `hard` **38.69 ms**.
- **Sliced execution (`stepJob`)**: capped by both `BOT_STEP_MS = 3 ms` AND
  `SLICE_CANDIDATES = 64` (**worst slice 3.98 ms**). Slicing by candidate count as
  well as wall time keeps `emaFrameMs` well below `16.7 ms` (preserving `60fps
  30/30` in `autoInterval`) AND ensures multi-frame `thinking N %` works in
  headless `dom_stub` where `performance.now()` is fixed within a frame.
- **Exact slice invariance & zero allocation**: 1-candidate slices match
  `chooseSync` identically across all tested levels/rules (`6 / 6`), and all
  `GravityBot` typed arrays preserve object identity across full `hard` races.
- **Ladder & replay verification** (seeds `7, 31, 42, 913`): `hard > easy` is
  `4/4` in `tour`, `3/4` in `route`, `4/4` in `money`; `normal > easy` is `4/4`,
  `3/4`, `4/4`. Contested `money + hard` races match bit for bit across `60 Hz`,
  `144 Hz ×16`, jittery frames, and `skip`.

## 4. presentation and replay links

- **Canvas (`drawRivalsWorld`, `drawRivalTags`)**: rival trails (`R1` violet, `R2`
  rose), diamond base markers around parked homeworlds, live ship chevrons, and
  compact `R1` / `R2` screen-space plates.
- **HUD (`#gameBox`)**: `rivals` radio row (`off`, `easy`, `normal`, `hard`),
  `#rivalTag` (`solo`, `thinking N %`, `1 rival · greedy`, `1 rival · route`,
  `2 rivals · 1-ply`), `#rivalRow` showing live visits/shots/purse and final
  `WIN` (mint) / `LOSS` (coral) / `TIE` outcome, plus **`copy rival`** (`#botCopy`)
  exporting `R1`'s solo trajectory link (`verified ✓`).
- **Link compatibility**: links without `&bot=` decode to `BOT_OFF`, so every
  pre-0.3.3 link replays unchanged.
