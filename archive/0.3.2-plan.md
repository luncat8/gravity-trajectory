# 0.3.2 — money mode: per-planet growing fly-visit profits

Standalone spec. Every number below is either a rule or a measurement; the
measurement section carries exact run numbers so tuning can be inspected directly.
Game runs carry three rules (`rule=tour`, `rule=route`, `rule=money`); links omit
`&rule=` when `tour` and omit `&bot=` when `off`.

## 1. rules

Every game run starts with a **purse** `P0 = 3.00` and a shared **26-planet
market** (`lastVisitStep[0..25]`, initialized to `-initSec / DT = -4800` so every
planet opens at `+0.25`). Each launch costs `C = 1.00`.

1. **launch** — `purse -= 1.00`, refused when `purse < 1.00`. At launch, the
   origin planet's orbit zone is marked already occupied so departing the launch
   pad never self-harvests.
2. **per-planet fly-visit harvest** — entering planet `i`'s orbital zone from
   outside (or impacting a planet whose zone was not yet entered on that pass)
   pays:
   `profit(i, step) = min(CAP, k · max(0, (step - lastVisitStep[i]) · DT))`
   with `k = 0.00625 / s` (`1 / 160`), `initSec = 40 s` (`+0.25` at `t = 0`),
   and `CAP = 0.75` (reached after `120 s` unvisited). Immediately on harvest,
   `lastVisitStep[i] = step`, resetting that planet's value to `+0.00`.
3. **revisits** — revisiting a planet later in the run (or looping back after it
   has aged again) pays whatever value has regrown since `lastVisitStep[i]`.
   There is no artificial landing fee or completion bonus: trajectories must pay
   for their `1.00` launch fee by sweeping well-aged planets.
4. **`money` rule (`rule=money`)** — `10` launches (`MONEY_SHOTS = 10`, `120 s`
   per-shot flight cap, `stopOnTour = false`), ranked primarily by final purse.
   `tour` and `route` share the exact same purse and per-planet market as a
   solvency constraint and tiebreaker.

## 2. why per-planet age pays

Tying each planet's payout to **how long that specific planet has gone unvisited**
turns the map into a living route puzzle:

- Freshly visited neighbourhoods drop to `+0.00..+0.05` (`8 s` -> `+0.05`), so
  bouncing back and forth between two close neighbours bleeds `-0.90` per shot and
  bankrupts a lazy run in 3–4 launches.
- Neglected corners of the map ripen toward `+0.50` (`80 s`) and cap at `+0.75`
  (`120 s`), rewarding multi-planet gravity slingshots into unvisited sectors.
- In contested races (`0.3.3`), player and rivals harvest from the **same**
  `lastVisitStep` array: if a rival sweeps a cluster first, those planets reset to
  `+0.00` on the canvas in real time and the player must steer toward neglected
  planets to win.

## 4. determinism and the replay link

`market.lastVisitStep` and `money.purse` advance strictly on integer fixed-step
physics ticks (`DT = 1 / 120 s`), never wall-clock time. `estimateProfit(market,
baseStep, sim)` uses the per-pass entry log recorded during `routeStep` and
agrees with live `stepHarvest` to `0.0e+0` across 208 tested trajectories.
Replay links re-derive the entire market and purse shot by shot (`verified ✓ ·
purse X.XX`).

## 5. canvas and HUD presentation

- **Canvas planet-profit pills (`drawPlanetProfits`)** — in game mode, every
  planet displays a crisp pill beneath its disc (`+0.00` .. `+0.75`) using
  preallocated cent strings (`PROFIT_STRINGS`, zero per-frame string allocation).
  Freshly visited planets dim (`< +0.14`), warm planets tint mint (`>= +0.35`)
  and gold (`>= +0.60`), and planets along the active predicted route light up in
  bright green.
- **Aim & HUD readouts** — the grip label and `pred visits` readout include exact
  predicted harvest (`+X.XX`); `purse` shows `3.00 · last +0.82`; the launch
  button shows `launch · 1.00` or `purse 0.40 · need 1.00` when broke; a 2.5 s
  postcard-slot toast summarizes each shot's visits, launch cost, and purse.
