# 0.8.0 fft-default worklog — remembered periodic · FFT default + clear button

## task

User decision (chat): the `periodic · FFT` checkbox must *save its default to
localStorage* so a plain open of `index.html` (no url parameters) does not lose
the setting, plus *a button to clear back to the factory default*.

State before: the checkbox already round-tripped through the address on every
toggle path (`syncSeedUrl` writes/deletes `&fft=1`; `loadSearchParams`,
`loadLink`, `loadSavedMapParam` restore it), verified with page probes before
coding (`archive/temp/fft_url_check*.js`, removed at the end). What was missing
was persistence without an address.

## decisions

- **Storage key `gravity.periodic`**, values `'1'`/`'0'`, absent = factory
  (classic). Mirrors the existing remembered-choice patterns (`gravity.lastMode`,
  `gravity.lite`, `gravity.trails`).
- **Only the checkbox writes it** (`onPeriodicChange`, on a real flip). A link,
  hash, `&fft=1` or `?map=` boot sets topology for the session but never
  rewrites the stored default — same rule the lite checkbox follows for `?lite=`.
- **Plain opens only**: `applyPeriodicDefault` runs inside the boot branch
  `if (!loadLink() && !loadSearchParams())`, *before* `loadLastMode()` so a
  remembered career auto-starts on the remembered torus (`setPlayMode` starts
  its rule at once). An address that names a world (any game-hint param, game
  hash, `?map=`) boots its own topology; urls written while periodic always
  carry `&fft=1` explicitly, so "no fft param" means the address was authored
  classic and wins.
- **`clear default` button** (`periodicDefaultBtn`, experimental panel under the
  checkbox): `removeItem` (forget, not store-'0') + unwrap the torus now when
  allowed. Locked exactly like the checkbox (`experimentLock || route` in
  `refreshGameUi`; handler also refuses during `replay.on`/career input replay).
- `onPeriodicChange` gained a `want === periodicMode` early return so a no-op
  change event can never store a default.
- `dom_stub.js` localStorage stub gained `removeItem` (the real API has it).

## known limits (accepted)

- `liteBootSeed` still reads only the `fft` url param, so a lite plain open
  with a stored torus picks its decorative lab seed from the classic saved
  openings before the rebuild. Zero gameplay impact (the lab world re-rolls on
  the same seed as a torus; a later career start re-seats itself); fixing it
  would need the game-hint param list inside `gui_lite.js`.
- Route + remembered torus: `loadLastMode()` restoring `route` is refused while
  periodic (route cannot be periodic), so the page stays lab with the route
  note. The mode conflict is inherent; the mode losing is the documented
  incompatibility, not a storage bug.
