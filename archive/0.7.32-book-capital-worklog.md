# 0.7.32 — Capital recovery counter and bounded book exploration

## Previous-stage review

Reviewed `0.7.30-worklog.md`, `0.7.31-recharge-rail-worklog.md` and the implementation against the six-topic replay report. Kept the recharge/refit policy unchanged. The code already includes the primary 1.0× rung, normal/hard local angle/speed refinement, unfinished multi-visit extension seeds, and a book cash-net gate; these were not missing features to reimplement.

The Capital tow eligibility was already present (`canEvacuate`, not `stranded`), but the recovery counter had a loophole: dropping a contract on failed search 3 reset `idleTries` to zero, below the tow threshold of 4. Board churn is not an exit.

## Changes

- Preserve the failed-search count when dropping a contract. Reset it only when evacuation actually begins. This lets a non-stranded Capital ship exhaust its search budget and use the existing affordable tow quote without changing game rules or recharge patience.
- Every fourth completed-flight departure compares the book against the fresh fan even when a stored route clears both score and cash gates. The booked route remains a candidate and can still win. Other departures retain the cheap shortcut. Flight count keeps the cadence company-local and independent of fallback/planner calls; no additional hot-loop state or allocations.
- Added regression coverage for Capital contract churn, affordable timed evacuation, and periodic book exploration/resumption of the shortcut. Both new regressions fail against `1bd3eb1` independently and pass on the candidate.
